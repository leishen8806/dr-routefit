## 1. 设计原则

1. **真实优先。** 每个数字、位置和时间都要能看出来源与时效。未知显示为未知，不显示 0；演示、影子数据必须明示（第 7 章）。
2. **安全先于效率。** 硬约束违规（超载、越权、版本冲突）用阻断，不用"可忽略的警告"。
3. **建议与决定分开。** 系统推荐和人的确认在界面上明确分区；推荐不等于已提交（PRD 7.3、11.2）。
4. **现场可用。** 司机端按单手、强光、弱网、戴手套设计；驾驶中不要求操作（PRD 7.0）。
5. **少录入、不猜测。** 默认值只能来自已核验数据（模板、地址库），不能由界面"猜一个"。
6. **一致的语言。** 同一概念在所有端使用同一术语和同一状态编码（见[术语表](glossary.md)）。

## 2. 品牌

### 2.1 名称与写法

| 用途 | 写法 |
| --- | --- |
| 产品正式名称 | **DR RouteFit** |
| 英文全称 | DR RouteFit — Smart Dispatch & Delivery |
| 中文说明 | DR 智能调度与顺路配送平台 |
| 上下文已明确时的简称 | RouteFit |
| 地图基座 | **Daen GeoCore**，简称 GeoCore |
| Slogan | The right vehicle. The right route. On time. ／ 配对车辆，规划路线，准时送达。 |

- DR 大写、不加点号。不使用 `Dr. RouteFit`、`Dr.RouteFit`（易读成 Doctor）、`RouterFit`（易读成网络路由器）。
- DR RouteFit 与 Daen GeoCore 各自保留前缀，不写成 "Daen RouteFit" 或 "DR GeoCore"。
- 智序小镇、智序工场是另一产品体系的名称，RouteFit 界面中提及它们时使用其原名，不加 DR 前缀。

### 2.2 Logo

**图形含义：**一笔画成的字母 R。路线从竖笔底部的青绿起点出发，向上绕过 R 的上半圆，把橙色货物包在里面（装得下），再从斜腿驶向目的地（路线合适、按时送达）。

| 文件 | 用途 |
| --- | --- |
| `brand/logo/routefit-icon.svg` | 彩色主图形，24px 及以上 |
| `brand/logo/routefit-favicon.svg` | 16px 专用版，按 16×16 像素网格重画 |
| `brand/logo/routefit-app-icon.svg` | App 图标（深蓝圆角底） |
| `brand/logo/routefit-app-icon-fullbleed.svg` | Apple Touch Icon 源文件（满版方形，圆角由系统裁切） |
| `brand/logo/routefit-app-icon-maskable.svg` | Android 可裁切图标源文件（图形在中心 80% 安全圆内） |
| `brand/logo/routefit-horizontal.svg` | 横版（图形 + 文字 + 副标题） |
| `brand/logo/*-mono-black.svg`／`*-mono-white.svg` | 单色版，用于单色印刷、浅色或深色背景 |
| `brand/logo/export/` | favicon.ico、apple-touch-icon.png、icon-192/512.png、icon-maskable-512.png、logo-horizontal.png |

**选用规则：**

| 场景 | 使用 |
| --- | --- |
| 浏览器标签页 | `favicon.ico`（内含 16/32/48） |
| 调度台左上角 | 横版彩色；侧栏收起时用主图形 |
| 司机端启动图标 | `icon-192/512.png`，Android 自适应图标用 maskable 版 |
| 深色背景（中控大屏、深色模式） | 单色白，或 App 图标版 |
| 传真、单色打印、盖章 | 单色黑 |
| 中控台模块标题 | 主图形 + "DR RouteFit" 文字，不使用副标题 |

**安全留白：**以图形高度的 1/4 为单位 x，图形四周至少留 x，横版四周至少留 x。

**最小尺寸：**

| 版本 | 屏幕最小 | 印刷最小 |
| --- | --- | --- |
| 主图形 | 24px（更小用 16px 专用版） | 6 mm |
| 16px 专用版 | 16px，只用于 16px | 不用于印刷 |
| 横版 | 宽 120px | 宽 30 mm |

**禁止：**

- 拉伸、压扁、旋转、倾斜，或改变线宽和圆角。
- 改色到本标准色板以外，或交换青绿与橙色的位置。
- 加阴影、渐变、描边、发光、3D 效果。
- 拆开重排起点、路线和货物，或只截取局部。
- 放在杂乱照片或低对比背景上。
- 使用 `brand/logo/archive/v2-d/` 中已废弃的 D 版。
- 用文字 "Dr." 或 "RouterFit" 与图形组合。

**当前状态：**图形为草图，正式使用前须由设计师按网格精修，并完成商标检索；横版文字使用 Inter 优先的字体栈，尚未转为路径，定稿须确认实际使用字体及授权并转为路径（见 4.3）。

| Token | 色值 | 用途 | 白底文字对比度 |

所有文字色在白底上不低于 4.5:1（WCAG 2.2 AA）。

| Token | 色值 | 含义 |
| --- | --- | --- |
| `--rf-success` | `#0B7A5F` | 完成、已核验、已对账 |

### 3.4 深色模式（中控大屏、夜间调度可选）

| Token | 深色值 |
| --- | --- |
| 背景 | `#0B2545` |
| 卡片 | `#12325C` |
| 正文 | `#FFFFFF` |
| 次要文字 | `#A9B6C8`（深蓝底 7.5:1） |
| 成功／强调 | `#3DDBB1` |
| 警告 | `#FFC15E` |
| 危险 | `#FF8A80` |
| 信息 | `#8AB4FF` |

### 3.5 使用规则

- **颜色不能是唯一信号。**状态必须同时有文字或图标；色弱用户、单色打印和强光下都要能区分。
- 品牌青绿、橙色只用于 Logo、插图和少量强调，不用于状态语义，避免"橙色＝货物"与"橙色＝警告"混淆；警告统一用 `--rf-warning`。
- 履约方式（自营／合作／快递）不靠颜色区分，靠图标和文字标签（见 8.2）。

## 4. 字体

### 4.1 字体栈

| 文字 | 首选 | 回退 |
| --- | --- | --- |
| 拉丁字母与数字 | Inter | Segoe UI、Roboto、Arial、sans-serif |
| 高棉文 | Noto Sans Khmer | 系统高棉文字体 |
| 简体中文 | Noto Sans SC | Microsoft YaHei、PingFang SC、sans-serif |

- 表格、金额、时间、ETA 使用等宽数字（`font-variant-numeric: tabular-nums`）。
- 高棉文有上下叠加的字符，行高不低于 1.6；按钮和表格行高按高棉文最长文案测试（R0-B 真机测试，PRD 8.1）。
- 字体文件随应用打包或自托管，不依赖运行时外网加载（试点现场网络不稳定）。

### 4.2 字号层级

| 层级 | 调度台 Web | 司机端 Android |
| --- | --- | --- |
| 页面标题 | 24 / 600 | 22 / 600 |
| 区块标题 | 18 / 600 | 18 / 600 |
| 正文 | 14 / 400 | 16 / 400 |
| 辅助文字 | 12 / 400 | 14 / 400 |
| 关键数字（ETA、金额） | 20 / 600 | 24 / 700 |

司机端正文不小于 16px，并支持系统字体放大。

### 4.3 Logo 字体

横版 Logo 当前字体栈为 `Inter, 'Segoe UI', 'Helvetica Neue', Arial, sans-serif`：优先使用 Inter，不可用时依次回退。SVG 仍使用 `<text>`，尚未转为路径，实际字形会随设备可用字体变化。定稿须固定实际使用字体、核对其授权，并将文字转为路径，避免回退字体造成品牌字形不一致。

## 5. 布局与组件基础

| 项目 | 规则 |
| --- | --- |
| 间距单位 | 4px 基准；常用 4／8／12／16／24／32 |
| 圆角 | 4（输入框）／8（按钮、卡片）／12（弹层）／16（大屏模块） |
| 阴影 | 只用一级轻阴影表示浮层；不用阴影表达状态 |
| 调度台最小宽度 | 1280px；目标 1440–1920px |
| 司机端触控目标 | 不小于 48dp；主要操作按钮通高 56dp |
| 图标 | 线性图标，线宽 2px、圆头圆角，与 Logo 线条风格一致；图标库在开发选型时确定，须核对许可证 |

每个数据组件都要设计完整状态集：**正常、加载中、空、错误、不可用、过期、降级、无权限**。缺任一状态的设计稿不进入开发。

## 6. 内容与格式

### 6.1 时间

- 时区固定 `Asia/Phnom_Penh`，界面不显示 UTC 偏移，导出文件写明时区。
- 24 小时制；当天只显示时分，跨天显示日期。
- 同时出现多个时间时必须标明类型：**客户期望**、**平台承诺**、**当前预计**（PRD 3.6），三者不能用同一标签。
- 承诺时间一经确认，界面上始终保留原值；变更后显示"原承诺 → 新承诺（客户已确认）"。

### 6.2 金额

- USD 与 KHR 分别显示，不做换算、不合计、不互相抵消（PRD 9.1）。
- 格式：`USD 12.50`、`KHR 50,000`；币种代码在前，避免 `$` 与其他货币混淆。
- 运费、COD、合作方应付分开展示，标签不同（见[术语表](glossary.md)）。
- 区分"司机申报"（reported）与"已核验"（verified），不能都显示为"已收"。

### 6.3 度量

- 重量 kg、尺寸 cm、体积 m³，单位始终显示。
- 未知值显示"—"并在悬停或点击时说明原因，不显示 0。

### 6.4 文案

- **错误提示三段式：**发生了什么 → 用户现在该做什么 → 错误编码（供支持人员查）。例：`路线已被他人更新，请刷新后重新确认。（PLAN_VERSION_CONFLICT）`
- 不用"成功了！""糟糕"等口语；操作结果写明对象和结果，例："订单 #1042 已指派给车辆 PP-3A-1234，等待司机确认。"
- 不说系统做不到的事：推荐写"建议"，不写"最优"；ETA 未校准写"预计（未校准）"，不写"保证送达"。

### 6.5 多语言

- 候选语言：高棉语、英语、中文；试点范围按 D15 确定（PRD 8.1）。
- 所有文案通过多语言键管理，状态和错误在界面显示本地化文案，内部只用稳定英文编码。
- 地址、地标、客户备注保留原文，不自动翻译。
- 每种语言的文案由指定审定人核对后上线；未审定的语言不开放。

## 7. 数据可信度的视觉表达

这是 RouteFit 与普通配送界面最关键的区别。规则来自 PRD 5.3、17、21.6。

### 7.1 数据模式

| 模式 | 标签 | 样式 | 规则 |
| --- | --- | --- | --- |
| live | 不额外标注 | 正常 | 只有真实授权来源才算 live |
| demo | `DEMO 演示` | `--rf-demo` 徽标；大屏模块加对角水印 | 不进入任何生产汇总 |
| shadow | `SHADOW 影子` | `--rf-demo` 虚线边框 | 只用于建议评估，不显示为已执行 |
| unavailable | `不可用` | 灰色，数值显示"—" | 从未接入或当前无权限；**绝不显示 0** |

### 7.2 数据质量

| 质量 | 显示 |
| --- | --- |
| fresh | 正常，显示"更新于 hh:mm" |
| stale | `--rf-warning` 徽标"已过期"，显示最后更新时间；数值变灰，地图上的车辆位置改为空心标记 |
| partial | 徽标"部分数据"，说明缺失的范围 |

超过批准显示期限的 stale 数据，敏感内容隐藏，只保留"数据已过期"提示（PRD 21.6）。

### 7.3 关键数据的来源标注

| 数据 | 必须同时显示 |
| --- | --- |
| ETA | 类型：P90／点预测／人工估计／未校准（`ETA_UNCALIBRATED`），以及计算时间 |
| 车辆位置 | 观测时间、精度；人工位置标"人工确认" |
| 货物尺寸重量 | 来源：仓库实测／已验证模板／客户估计 |
| 地址 | 确认状态：已确认／待确认；坐标来源 |
| 收款 | reported／verified／mismatch |
| 快递状态 | "承运商报告"与"已核验"分开 |

### 7.4 降级与暂停

- 进入人工降级（PRD 6.5）时，调度台顶部显示常驻黄色横幅：降级原因、开始时间、受影响能力；降级期间产生的记录带 `DEGRADED` 标记。
- 试点暂停（PRD 15.1）时，显示红色横幅：暂停的能力、触发原因、操作人；被暂停的按钮置灰并说明原因，不隐藏。

## 8. 业务对象的视觉规则

### 8.1 状态族

状态编码以[开发标准](development-standards.md)和机器契约为准，界面按状态族统一配色和图标：

| 状态族 | 颜色 | 例子 |
| --- | --- | --- |
| 草拟／核验 | 中性灰 | draft、validating、quoted |
| 待处理 | `--rf-info` | awaiting_dispatch、offered、pending_confirmation |
| 执行中 | `--rf-info` 实心 | executing、in_transit、handed_over |
| 完成 | `--rf-success` | delivered、verified、reconciled |
| 风险 | `--rf-warning` | 将超时、reported、stale、待装载复核 |
| 异常／阻断 | `--rf-danger` | 异常、mismatch、装载 REJECTED |
| 结束 | 中性灰、删除线以外的弱化 | cancelled、returned、closed_exception |

### 8.2 履约方式

| 方式 | 标签 | 图标 |
| --- | --- | --- |
| OWN_FLEET | 自营 | 实心车辆 |
| PARTNER_VEHICLE | 合作车 | 车辆 + 握手标记 |
| PARCEL_CARRIER | 快递委托 | 包裹 + 外链标记 |

快递委托不显示"司机""车辆位置"等无法控制的信息；没有实时车位时，地图上不画移动车辆（PRD 21.6）。

### 8.3 装载放行

| 状态 | 显示 |
| --- | --- |
| VERIFIED_PATTERN_PASS | 绿色"已通过（模式）" |
| MANUAL_LOAD_REVIEW | 黄色"待装载复核"，取货按钮禁用并说明原因 |
| MANUAL_RELEASED | 绿色"人工放行"，显示复核人与时间 |
| REJECTED | 红色"禁止装载"，无任何覆盖入口 |

## 9. 各端规范

### 9.1 调度台（Web）

- **布局：**顶部指标条；左侧订单池（按最晚安全派发时刻排序，S1 置顶）；中间地图；右侧推荐与详情；底部事件流水。
- **推荐面板：**展示推荐方案、理由、被拒绝方案及结构化拒绝原因；"确认派单"按钮与推荐分区，确认前显示将写入的版本与预留。
- **写操作：**所有提交显示对象、版本和影响；版本冲突时提示刷新，不自动覆盖。
- **多运力：**提供履约方式筛选与待合作方确认、待揽收、超期未更新、对账异常视图（PRD 11.1.1）。
- **待指派已承诺队列：**单独成区，显示距最晚安全派发时刻的倒计时（PRD 3.8）。

### 9.2 司机端（Android）

- **一屏一个主操作：**当前任务、下一步动作（到达、取货、出发、送达）用通高大按钮。
- **离线可见：**顶部常驻网络状态和"待上传 N 项"；离线时禁用新任务接受（PRD 6.2）。
- **驾驶安全：**新提案以通知提示，显示剩余确认时间；文案提示"请安全停车后处理"；界面不要求行驶中输入。
- **拍照取证：**按步骤引导（整体、包装、件数、破损），不要求拍摄人脸、证件或无关环境。
- **定位：**首次使用说明采集范围（仅授权班次）、用途和停止方式；定位异常时显示提示，不隐藏。
- **合作司机：**只看到被指派的任务，不显示其他订单、客户或运力信息。
- **强光可读：**主要信息使用深色文字白底或白字深蓝底，不用浅灰小字。

### 9.3 客户通知

- 内容至少包括：订单号、平台承诺时间、当前预计时间（如有）、联系方式。不以"预计"代替"承诺"。
- 跟踪链接使用服务器签发的短期引用，链接中不含电话、地址或姓名（PRD 21.6）。
- 按客户选择的语言发送；模板由运营审定。
- ETA 推迟通知遵循 PRD 7.4 的门槛与冷却规则，界面和模板中不承诺未经确认的新时间。

### 9.4 智序工场中控台中的 RouteFit 模块（R1-V）

- 只消费 RouteFit 授权只读摘要（`RouteFitOpsSnapshot`），每个模块独立显示模式、质量和更新时间（第 7 章）。
- 订单数与快递运单数分开统计，不相加；快递订单不计入车辆空驶率和装载率。
- 访客大屏只显示批准的汇总，不显示地址、电话、证件、签收照片、原始轨迹。
- 模块提供"在 RouteFit 中打开"跳转；三维点击、动画结束都不改变业务状态。
- 地图模块注明数据来源（Daen GeoCore 及其供应商归属声明）。

## 10. 无障碍

- 文字对比度不低于 4.5:1；大字（至少 14pt 粗体，约 18.67 CSS px，或至少 18pt 常规，24 CSS px）不低于 3:1。依据：[WCAG 2.2 SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- 颜色不作唯一信号（3.5）。
- 所有图标按钮有可读标签；表格有表头关联。
- 键盘可完成调度台核心流程（选单、查看推荐、确认、撤回）。
- 支持系统字体放大到 200% 不截断关键信息（司机端）。
