## 1 本次产品决定

- 首页以待办组织，显示金额、对象、原因、等待时长、下一负责人、下一动作。账与钱不一致时停在差异，不自动凑平。
- 经办、复核、审批按不同自然人标识分离，最低三人参与。付款执行人与资金核对人也不同；不要求所有环节都是不同的五个人。账号与人是不同概念，同人多账号不能绕过。
- 银行到账／现金点收事实先如实记录；业务核销、调整和付款须走审核。未经审核的交款批次不进入可支付额度，事实已收与授权可用分开。
- 先预付并完成核销才可派单，获批月结例外。演示现金220样例明确是月结例外；运费已预付时不重复向收货人收取。
- 不做充值／转账钱包；已赚收入申请提现保留。无自动银行划转／退款，执行均为模拟人工登记，不扩展完整 ERP。
- 配送费、保险费、COD 货款分项；保险费不分成，COD 不计平台收入。未分配款、保费及商户待返款不能默认为经营支出的可用现金。

## 2 各端的订单与账务边界

| 端／工作席 | 页面与核心内容 | 可操作 | 不可操作／隐私边界 |
|---|---|---|---|
| 财务经办 | 今日待办、订单往来、资金来源、付款与调整草稿 | 登记收款、跨单分配、核定履约成本、制单、修订 | 不复核或批准自己单据，不凭截图记已付 |
| 复核 | 待复核及来源明细、分配合计、账户快照 | 复核或退回 | 不能代审批授权，关键改动后复核失效 |
| 审批 | 付款／调整授权、独立复核意见、余额与用途 | 批准或退回 | 无复核不放行，不使用同人另一账号 |
| 执行／核对 | 已批准付款、执行登记、未知查询、核销 | 分别登记和独立确认资金结果 | 上传凭证不自动结清；unknown 保留占用 |
| 司机 | 我的订单、收款申报、现金交款、收入与提现、报表 | 申报授权任务现金、申报交款、申请自身收入提现 | 不能把持有COD当收入；不能自己点收交款；不可操作合作方款 |
| 用户／发货人 | 费用与订单、付款与退款、申请进度、账单 | 登记公司转账、查看分配、申请未分配超付退款 | 只见本人订单与付款；不见承运成本和内部付款账号 |
| 商户 | 代收订单、货款往来、返款申请／进度、对账单 | 查看本商户已收／未收／待返、申请返款 | 未收的货款不能返；不见其他商户及平台内部成本 |
| 合作承运商 | 本主体运单、协议费用、结算申请与结果 | 申请本主体应付结算 | 不见客户原收款凭证、其他司机收入 |
| 仓库 | 出入仓订单、货品件数、服务收费依据、申请进度、作业报表 | 提交本仓搬运等服务费用依据，交财务审核 | 不核验银行、不付款、不改COD或保费、不因账务变化改签收 |
| 管理者 | 简明总览、逐笔下钻、账龄／明细、导出 | 只读查看责任、来源、去向及未完成事项 | 同一份账生成，不另存管理者余额；看报表不授予付款权 |

用户与商户虽可能属于同一公司，也按付款义务和货款受益身份区分。仓库只提供费用事实，财务批准决定是否计费；上传签收图不能代替收款确认。司机仍使用原任务地图、订单列表及执行流程，本轮增加账款入口，不改变司机滑动签收。

## 3 同单闭环及纠错

### 收款与核销

司机／用户／经办申报 → 独立核对资金事实 → 经办选择一个来源和多笔账项 → 提交 → 独立复核 → 独立审批 → 核销。一个账项可由多笔款结清。每次分配不超过来源和目标余额；公司、币种、付款主体不同拒绝。

超收保留待分配。已确认款不因尚未完成审核而消失，也不能在归属不清时直接放行订单。退款首个切片覆盖公司收款中未分配超付；已核销退款先更正费用与撤销分配。现金退还、渠道手续费、净额银行批次匹配仍待扩展契约，不能伪装已覆盖。

### 司机交款与差额

申报明确来源收款及金额 → 独立点收记录实际金额 → 形成交款审核批次 → 复核、审批、完成批次。220 申报而实际210：公司确认保管210，差额10待查；不能断言这10仍在司机手中，不自动扣薪或减少COD。补交10形成新的审核记录，原210及差异保留，不再增加客户收款。

### 付款、提现及商户返款

已确认的履约应付／已归属COD → 对方申请或经办制单 → 独立复核 → 独立审批 → 人工执行登记 → 独立资金核对（未知／失败／确认成功） → 核销。商户、司机及合作方只能申请自身账项。

审批绑定金额、币种、对象、账户版本／脱敏快照、明细与证据。修订使原审批失效；账户变更也须审核，旧批准付款被阻断。未知不得重付；确认失败记录保留，新申请仍须重新审核，不能换请求键直接再执行。

### 冲正与补差

费用补差／减免和撤销核销均制单、复核、审批、追加记录。不能直接覆盖已核销记录；COD已返还或已预留时，不能直接撤销来源核销制造负负债。差额不自动计损失，不自动扣其他订单或司机收入。

## 4 报表字典与下钻

| 报表 | 维度／筛选 | 金额与口径 | 下钻 |
|---|---|---|---|
| 财务待办 | 席位、币种、单号／状态／对象、分页 | 收款待核、交款待点收、待复核／审批、待执行／核对／核销 | 直接打开当前版本，显示下一负责人 |
| 订单费用明细 | 授权订单、费用用途、币种 | 原额、批准调整、核定额、核销额、未结；货款／保险独立 | 原单、资金分配、交接与审批 |
| 未结账龄 | 观察日、币种、账项 | 未到期／当天、1–7、8–30、31天以上；应收和应付分列 | 保留原合同到期日及组成明细 |
| 司机现金 | 司机、币种、交款批次 | 已确认收款、已申报、实点收、差额；内部交款不算收入 | 关联原收款及点收证据 |
| 司机收入 | 本人、来源订单、币种、申请 | 履约核定收入、申请／占用、确认出款、核销、未结 | 分成依据与审批结果，COD不出现为收入 |
| 用户账单 | 本人订单、币种、费用 | 费用组成、已确认款、已分配、未分配、未结、退款进度 | 付款来源与本人的申请；不展示内部成本 |
| 商户对账单 | 商户、代收订单、币种 | 应代收、已归属代收、已返、待返；未收到的钱不算已保管 | 本商户订单与返款状态 |
| 合作运费结算 | 本承运主体、运单、币种 | 核定费用、已结、未结和申请状态 | 履约协议引用及付款进度 |
| 仓库作业／费用 | 本仓、订单、件数、费用依据 | 件数与履约状态、服务费原额及批准调整 | 仓库费用申请，不能代替库存账或会计报表 |
| 管理简明视图 | 同一授权模型、币种 | 客户欠款、对外未付、司机持款、差额；公司保管余额另列 | 每个金额追至源账及负责人 |

本地 Demo 支持当前状态的明细、账龄观察日、搜索、币种、8条分页和CSV导出。观察日改变账龄分析，不提供“历史任意时点余额重放”；出账周期、正式关账、税务／会计凭证、文件导入和完整净额匹配属后续实现。不得将流水导出称作会计凭证。

可用性规则：桌面分菜单／页签，手机订单与报表以卡片展开；二级返回保留筛选；状态有文字；原生选择器与日期控件；关键变更确认，未保存输入保护。等待时长按记录创建时间计算，不等于合同逾期天数。司机“待交”和商户“待返”可对应同一笔资金，禁止合计成总负债或总现金。

## 5 数据、服务与权限

本地实现：financeLedger 保存资金申报／确认、核销分配、审核文档版本、交款来源、点收、差异和追加审计；订单沿用主工作台 `orders`。已纳入订单禁止旧入口收款／交款／分成写入。旧账单已绑定、已有付款或成本的订单拒绝自动迁移，避免重计；未绑定客户不自动冒认C01演示用户。

正式接口至少提供财务待办、按对象授权的订单账、资金申报／确认、制单／修订／复核／审批／退回、执行登记／结果查询／核销、交接／点收／差异、报表查询／授权导出。金额整数最小单位；USD/KHR精度分开。所有写动作须服务端身份、同人职责冲突、对象版本、幂等、跨公司范围和事务余额检查，不能信任前端actor参数。

生产审计需独立访问控制、留存、备份及篡改检测；本地数组和sessionStorage不具备这些能力。银行端授权与现金内部制度配套；系统不能阻止网银持有人绕开系统转账。AI和代码审查均不能替代人类业务批准。
