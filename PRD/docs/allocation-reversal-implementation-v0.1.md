# 财务纠错第一步：撤销核销 · v0.1草案

2026-10-25。基于已批准的预付、独立复核审批、保留原始记录和保险独立规则，不改正式PRD/RULE/AT。范围是未派单订单的整笔核销撤销：申请→独立复核→独立审批→入账→恢复费用未结及资金未分配余额→重新核销。原银行到账事实保持不变。

新增007迁移：allocation_reversal和reversal_event，只追加、企业/客户RLS、复合外键、唯一撤销入账、审核顺序和人员校验。服务端锁订单、校验原件版本、冻结来源快照；订单读取和付款准入改为统计未撤销的有效核销。申请待审时不改金额，但暂停付款准入并显示有争议；拒绝解除该申请的暂停。

[5个接口及页面接线](../../contracts/allocation-reversals-api.md)为大旺开发依据。未改共享app.mjs/app.css/fee-settings；现有订单页根据服务端collectionState显示状态，完整财务表单仍由独立页面接入。现有8费用接口和保险分成计算不改。仅本机开发身份，不接真实支付。

本轮收口于“核销纠错”，没有把银行到账撤销和业务改价合并成一个按钮。下一步按依赖推进：

1. 已确认订单变更申请：保留原订单/报价，将拟改内容、原因和客户授权作为独立申请；暂不修改生效订单。
2. 重新评估区域、时窗、装载与费用，产生新报价版本；付款方重新确认价差。需明确原收款如何映射、新旧应收及已核销如何迁移、取消/退款义务如何记录。
3. 经独立复核审批后执行变更，原承诺/费用/审核链保留；在这一套闭环实现前继续保持006确认订单锁。

银行误确认需独立冲正或更正凭证，不能删除银行唯一交易记录；真实退款需收付证据，不以核销撤销冒充。关账期间、跨单核销、已履约订单、月结/COD及完整会计总账仍未实现。

后续008已补上服务申请入口，见[服务申请实施说明](service-case-implementation-v0.1.md)：它不解除报价锁，也不替代本文件列出的重报价、价差和资金映射闭环。本机235个契约/48个已实现。测试与旧库迁移证据见 [验证](../../services/routefit/verification/allocation-reversal/README.md)；最终代码包和新目录恢复结果见本地handoff/latest.json及restore-result.json。仍需RF-QA-01独立人员验收。
