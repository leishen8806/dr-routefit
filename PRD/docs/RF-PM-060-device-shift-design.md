# RF-PM-060 设备注册与当班管理设计

状态：设计草稿，待负责人批准。本文只定义后续接口边界，不实现设备注册或当班写入。

## 1. 设备注册

设备注册属于 RF-PM-055 批次 5 的司机设备会话流程。司机完成系统浏览器登录后，App 生成本机设备标识并向服务端登记；服务端把设备绑定到当前司机主体并签发可撤销的设备会话。调度人员只能查看和撤销设备，不能替司机注册设备。

后续最小接口：

- `POST /api/driver/v1/devices`：当前司机登记本机设备，要求重新认证；
- `GET /api/driver/v1/devices`：当前司机查看自己的设备；
- `POST /api/driver/v1/devices/{deviceId}/actions/revoke`：司机或受权运营撤销设备。

设备记录不存访问令牌、推送令牌明文或硬件序列号。App 重装后的设备身份与离线序号衔接由 RF-PM-055 批次 5 决定。

## 2. 当班开始与结束

推荐首期采用“调度排班、司机确认上班”：调度创建计划班次，司机在已登记设备上确认开始；司机可主动结束，调度可在异常情况下强制结束并留下审计原因。这样既避免司机自行扩大授权时段，也允许现场换班。

后续最小接口：

- `POST /api/ops/v1/driver-shifts`：受权调度创建计划班次；
- `POST /api/driver/v1/shifts/{shiftId}/actions/start`：司机在绑定设备上确认开始；
- `POST /api/driver/v1/shifts/{shiftId}/actions/end`：司机结束当班；
- `POST /api/ops/v1/driver-shifts/{shiftId}/actions/end`：调度带原因强制结束；
- `GET /api/driver/v1/shifts/current`：司机读取当前当班与绑定设备。

写操作都需要幂等键、当前版本、审计主体和明确时间边界；一个司机同一时刻至多一个有效当班，一个设备不得同时代理多个司机。

## 3. 开发夹具边界

本机开发夹具为合成司机直接创建一台 `ACTIVE` 设备和覆盖当前时间的 `ACTIVE` 当班，仅用于真实 PostgreSQL 集成测试。它不进入试运营初始化脚本，不代表生产设备注册或考勤已经实现。

## 4. 待负责人决定

1. 调度排班是否为首期唯一的班次来源，还是允许司机临时发起班次申请；
2. 设备首次登记是否必须由调度审批；
3. 设备撤销后未补传事件的保留与人工处理规则；
4. App 重装时沿用设备身份还是创建新设备并由服务端下发离线序号起点；
5. 强制结束班次的角色、通知渠道和申诉流程；
6. 当班记录是否作为考勤事实，还是仅作为 RouteFit 操作授权窗口。
