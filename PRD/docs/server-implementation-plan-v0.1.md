## 1. 当前交付与候选技术

本轮已经开始编写 [services/routefit](../../services/routefit/README.md)，不是只生成接口目录。首个闭环为“建费用草稿 → 按费目设置 → 服务端试算 → 查询历史”，有 8 个 HTTP 操作、PostgreSQL 迁移及实际数据库测试。网页 Demo 尚未接线，其他业务接口继续为设计状态。

候选为 **Node.js 24 LTS + ESM JavaScript + PostgreSQL 16+**，沿用现有 JS 模型的表达方式，使用内置 HTTP、pg 与 Ajv2020，不在首切片引入框架、ORM、消息队列或微服务。Node 24 是当前 LTS；工作机默认 Node 25 不作为目标运行时，本轮测试另用 Node 24.22.1。[Node 发布表](https://nodejs.org/en/about/previous-releases)

`pg` 事务使用同一连接，SQL 值参数化；OpenAPI 3.1 的 JSON Schema 2020-12 用 Ajv2020 校验。[pg 事务](https://node-postgres.com/features/transactions)、[参数化查询](https://node-postgres.com/features/queries)、[Ajv schema 支持](https://ajv.js.org/json-schema.html)

这是可逆的开发候选：本轮只固化已有契约下的首个切片。后续若团队统一技术栈或框架 POC 给出更好的维护证据，通过 D24 ADR 确认并保留 HTTP 契约和数据迁移测试；不把本文件视为已批准技术栈。

## 2. 服务边界与代码依赖

RouteFit 首期为一个模块化服务进程、一个业务数据库；GeoCore G1 独立服务／数据库，通过契约调用。接口按运营 Web、司机 App、客户／Telegram、公开跟踪、外部集成分组，认证和限流分别处理；不是每组立即部署一个微服务。

```text
Web / Driver iOS+Android / Telegram Mini App+Bot / WMS
       ↓ 各自身份验证与对象范围
HTTP adapter → application 动作与事务 → domain 状态／计费规则
                         ↓
          PostgreSQL / evidence storage / external provider adapters
                         ↓
             outbox worker（后续）→ GeoCore / KESS / 通知渠道
```

当前 `application/http.mjs` 负责 8 个路由、鉴权、schema 校验与动作编排，`domain/pricing.mjs` 不访问数据库／浏览器／支付 SDK，`adapters/postgres.mjs` 执行参数化 SQL、行锁、版本、快照和幂等。新增第二个领域时按领域拆 application 文件，接口需求稳定后再抽 ports；不先创建没有实现的接口层。

现有 `prototype/*.mjs` 为原型参考和测试样例，不直接作为生产业务模块导入。费用目录由 `contracts/pricing-catalog.json` 提供，测试校验与旧 UI 目录一致；UI 金额转换、生产授权和持久化改造仍须完成。

## 4. 每个动作的实现约束

1. 从可信会话／服务身份获得企业、自然人、货主和仓库范围。拒绝前端自报角色、已付款、已批准或最终分成金额。
2. 校验明确 DTO，拒绝未知字段、负金额、浮点金额、错误币种；未知数据保留未知原因。
3. 开事务，设置租户作用域；先检查幂等重放，再按固定顺序锁聚合并检查版本、状态、余额、容量和授权。一次动作写业务变化、事件／审计及幂等结果。
4. 外部调用通过后续 outbox／worker，在数据库事务外执行。保留外部操作ID、来源事件ID、结果未知状态；超时先查询，不直接再次扣款／付款。
5. 成功后返回聚合版本与可执行下一步。并发失败不静默重试成另一次业务动作。已确认记录通过追加更正，不覆盖历史。

S0 已实现其中费用领域的事务、版本、快照与幂等，**尚未实现通用 outbox、领域事件、独立审计服务或付款审批**。当前价表版本记载经办人，不等于已有防管理员篡改的全平台审计系统。

## 5. 财务与渠道不能混写

- 客户运费、商业保险、COD 本金、司机保管现金、合作方应付分别建账；保险不参与配送费分成。客户付现金给司机与司机交公司不能重复增加收入。
- 财务敏感动作绑定同版金额、币种、受益人、账户和明细，由不同自然人经办、复核、审批；换账号不能绕过自然人分离。已审批不等于付款，付款截图不等于到账。
- 不同结算对象配置账期与到期任务，通知出账／催收只生成待办与投递记录；失败／重试不可重复账项。真实外发与银行付款不是 S0 范围。
- KESS 使用服务端支付适配器，浏览器／Telegram 回跳不入账，需验签、金额／币种／收款账户核对及查单。商户未开通，继续模拟和准备。
- 司机端 iOS／Android 使用同一动作契约；离线补传按事件逐条返回生效／重复／拒绝／人工裁定。接受派单必须在线。
- Telegram Mini App 与 Bot 共用订单草稿和业务操作ID；用户可提交申请，不能直接改派、改账、绕过付款或客户授权。
