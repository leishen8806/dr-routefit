# 快递配送与仓配计价体系 v0.1

2026-10-25 · 研究与开发设计草案，待运营批准具体价表。依据 V1.4 §3.7、§9、§14.4、§21.5，以及[平台优先基线](platform-first-execution-baseline.md)、[跨端财务](cross-end-finance-and-reports-v0.1.md)、[Telegram／司机 App 范围](telegram-and-driver-app-scope-v0.1.md)。不重编正式 PRD、RULE、AT。

配套：[公开资料核查](research/2026-10-25-delivery-pricing.md)、[开发与验收对照](pricing-development-map-v0.1.md)、[待填价表](pricing/ratecard-template.json)、[合成算例](pricing/calculation-examples.json)。本稿提出完整规则结构，不把参考价格、设计建议或算例变成正式费率。后续已按用户要求实现[后台分项费用设置与试算](fee-settings-v0.1.md)，仅本地原型，不改变既有订单计价与结算。

## 1. 目标与确定边界

一笔报价必须能回答：为什么收这些钱、包含哪些服务、什么情况下会追加、司机／承运商拿多少、哪部分是保费或代收货款、变更后差额如何处理。客户、Bot、Mini App、调度、司机和财务引用同一报价版本；不得各端各算。

已经确认，不能因新计价设计改变：

- 默认发货人付费；先付款并核验，或获批月结例外，再派单。收货人付费须明确授权，不是默认到付。
- 安全、合法装载、真实尺寸、时窗和已约定服务先满足，再优化成本。禁送、禁运、超载、无法按时交付不能靠加价变为可接。
- 配送费按订单配置平台／司机分成。商业保费单列，不参与配送费分成；基础货损保障包含于配送服务，不再收第二笔“基础保障费”。
- COD 是商户货款本金；COD 服务费如启用是另一项服务收费，两者绝不混记。报价、收款、核销、司机交款与合作方结算分别建模。
- 取货后拒收不自动退原配送费；客户原因返仓由发货人确认报价承担，平台／司机原因先由平台承担再核责。客户退款不自动扣司机收入。
- 不做钱包、自动划款或自动退款。KESS 未开通，仅做模拟和接入准备。

下文费目适用范围、计价公式、账务分类为建议设计；实际单价、免费额度、系数、封顶和比例须填入批准版本。未知不能当零；明确批准免费才填 0。

## 2. 产品分开，订单与账务共用

| 计价产品 | 适用业务 | 主要计价量 | 不自动叠加的收费 |
|---|---|---|---|
| PARCEL 包裹快递 | 同城或跨区小包、合作快递委托 | 起讫区域＋计费重量／件，或合格箱型固定价 | 不同时再收一套整车起步费；箱型价和首续重互斥 |
| VEHICLE 专车／独享配送 | 摩托／三轮／面包车／货车即时或预约任务 | 车型起步价＋超距＋获准附加服务 | 载重和容积主要是车型准入，不自动同时按公斤和立方米加一轮费 |
| SHARED 经济拼单／计划仓配 | 经批准的同仓批次、受控顺路、返程货源 | 区域／货位／m³／重量三者中明确选择的运价，或标准价减明确折扣 | 不把整趟多客户绕行公里重复收给每位客户，不默认所有路线可拼 |
| CONTRACT 人工核价／协议服务 | 非标大件、暂缺自动规则、指定合作方 | 批准合同或单次书面报价＋明确范围 | 导入的总配送价不再按“基础价”自动叠加超距；不伪称自动核价 |
| WAREHOUSE 仓储服务 | 入库、仓储、出库、包装、退回待检 | 每次／件／托／m³·日等获批单位 | 不与运费中已含的装卸、仓配包价重复收费 |

时效 S1及时／S2当日／S3预约／S4经济，与“独享车辆”“本人交接／授权代收”“上楼搬运”是不同维度；及时送不自动等于独享或包含上楼。履约方式 OWN_VEHICLE／PARTNER_VEHICLE／PARCEL_CARRIER 不决定客户必须支付哪一价表；换承运方不自动涨客户价。

首期先落 VEHICLE 和受控 PARCEL 两种模板、CONTRACT 兜底及已有保险／分成规则；SHARED 仍按 R3 准入，完整仓储计费依赖可靠 WMS。首期不引入自动供需涨价、竞价、会员营销或跨境税关计算。

## 3. 可配送判定和价表选择

### 3.1 先准入再报价

检查取送地址和入口、当前区域版本、禁送区／车型通行、营业时段与截单、货类、包装、实测尺寸重量、工作时间和服务能力。道路距离未知返回待核价；不使用直线距离、示意地图或司机最终里程替代报价路程。取送点变更或测量数据改变需重新计算。已持货的安全处置独立于新订单准入，不因欠费让货物保管责任消失。

区域用于两件事：能不能送、按哪个区域收费。禁送区优先；收费区域重叠时必须配置明确优先级，不能把所有命中区域的基础费相加。区间边界、最大服务距离包含关系与服务区边界规则要在版本中固定。地址无法定位或有多个同优先级匹配时转人工。

### 3.2 唯一匹配与发布

匹配条件：运营企业、客户合同、起讫区域／仓库、计价产品、车型／箱型、时效与交付能力、币种、有效期、渠道适用性。先具体客户合同，再客户组，再通用价表；同层级仍多命中则阻断，不依数据库返回顺序取第一条。不因 Bot 与 Mini App 入口不同收两种价格；渠道活动若以后启用必须显式披露和版本化。

价表生命周期建议：DRAFT → REVIEWED → APPROVED → SCHEDULED／ACTIVE → RETIRED。制表与批准人员分开；发布前检查空值、重叠／缺档、负数、单位、币种、测例和费用叠加。生效时间以带时区时间保存，运营查看为金边时间。已批准版本不可改写，改价生成新版本。暂停／下线影响新报价；已确认的报价继续按原约定，安全条件失效则人工处置，不静默改价。

必配项：价表 ID／版本、适用条件、有效期、计费量及取整、起步价与含量、续费规则、封顶／最低费适用范围、税费模式、附加项白名单、折扣与分成范围、报价 TTL、审批依据。报价有效期与司机提案 TTL 分开；不直接采用别家五分钟有效期。

## 4. 主运费计算

### 4.1 包裹重量与体积

逐件保存包装后 L/W/H、实重、数量、测量来源及时间；同规格数量 q 必须展开等价逐件计算，不把单件重量当订单总重。计费和装载使用同一可靠测量事实，但计费通过不等于装得下车。

单件体积重 kg = L_cm × W_cm × H_cm ÷ D，其中 D 是**该承运商／产品／线路版本**的体积系数，不能全平台写死 5000。DHL 的 5000 仅为来源产品参考，不是柬埔寨国内统一标准。没有获批系数时不自动出可支付包裹价。

候选计算口径必须显式选择其一：

- PER_PIECE：计费重 = Σ[ceil(max(单件实重, 单件体积重) ÷ 计费步长) × 计费步长 × 数量]。
- PER_SHIPMENT：计费重 = ceil(Σ[max(单件实重, 单件体积重) × 数量] ÷ 步长) × 步长。
- 承运商若使用 max(总实重, 总体积重)，须单独配置 TOTAL_MAX；不能当成上式的等价简写。多件混装会出现不同结果。

首续重价格 = 首重费 + ceil(max(0,计费重−首重包含量) ÷ 续重单位) × 续重单价。首重计费量与重量取整是两件事，规则说明必须一起展示。阶梯重量如启用，必须区分“各段累进单价”和“达到档位后整票单价”，避免重量增加反而意外降价。超件数、超长、超围、不可堆叠先检查承接能力；允许承接时才按已批准规则追加。

箱型固定价只在包装尺寸、重量、货类、寄送区域和服务满足箱型条件时使用。超限要重新选产品／车型和确认，不能擅自拆箱收费。称重复核差异保留原值和证据；复测结果改变费用须重报差额，不自动扣款。

### 4.2 车型与距离

报价道路距离为批准取送站序的可行道路里程快照，保存路网／距离依据、车型和路线版本。单取单送从取件入口到交付入口；司机到取件点的调车距离属于成本，只有获批且提前披露的调车收费项才能额外向客户收费。

超距米数 x = max(0,道路米数−基础包含米数)。

- ACTUAL_METERS：超距费最小货币单位 = round(x × 每公里单价最小货币单位 ÷ 1000)。
- CEIL_UNIT：先 ceil(x ÷ 计费米数单位)，再乘该单位价格。仅超出部分进位，不能把含量内部分再收一遍。
- 分段累进：各段长度 = max(0,min(x,段上界)−段下界)，各段金额合计后按明确层级取整；不能在每个地图折线点或每条内部路段重复进位。

运输基础小计 = 车型起步费＋超距费；起步费包含的一次取件、一次投递、基础等待／装卸范围须明确。固定整车包价使用 CONTRACT 模式，不额外重复 VEHICLE 基础费。独享附加费只在基础产品尚未包含独享时收取；货车包车价若已含独享，则该费为不适用，而非再次默认叠加。

### 4.3 多点、拼单与返程

- 同一客户多点单：按约定站序的整条计费路线一次计算，另计超过基础包含数量的**实际服务站点**；新增站点的路程费与停靠服务费分别披露，不能重复起步价。多件同址同次交接通常是一个站点，特殊服务另列。
- 不同客户合单：每单按其已确认报价收费，内部整趟成本另分摊；客户不承担其他单造成的绕路费。份额依据须版本化且总和等于整趟成本，缺成本不能宣称精确节省。
- 折扣来源必须能解释为已配置的拼单产品价或批准优惠。未拼成按事先确认兜底处理：平台预算补贴独立配送、重新报价待同意或取消；不能静默多收或降低交付标准。
- 商业返程新货是新订单、新报价；拒收返仓是原订单的退回服务实例。事故分散转运关联原货物件级责任和实际救援应付，不给客户自动生成多笔全额基础运费。

## 5. 附加费与费用归属目录

费用必须绑定一个实际服务实例／站点／货物及批准规则，唯一业务键防止司机、仓库、承运商重复申报同一服务。下面“分成”是配置方向建议，正式发布前明确到费目；当前已确认配送分成规则保留，不能追溯更改已结算单。

| 费目 | 计算依据与收取条件 | 结算归属／控制 |
|---|---|---|
| BASE／DISTANCE | 主产品起步／超距 | 纳入已批准配送分成口径 |
| URGENT／EXCLUSIVE | 时效或独享产品未包含时，固定额或指定基数比例 | 白名单叠加；独享承接资格先通过 |
| EXTRA_STOP | 基础包含站数之外的服务站次 | 路程费另列，禁止多件同址按件伪造停靠 |
| REMOTE／ZONE | 获批可送区域的偏远／特殊入口 | 同一原因的区域附加与超距叠加须事先声明；禁送不能收钱放行 |
| WAITING | 起止证据、责任及免费时段；按单位计时，有封顶和升级规则 | 司机早到、平台延误不转嫁客户；司机申报后审核 |
| HANDLING／FLOOR | 重量档、件数、人手、水平搬运距离、楼层、电梯与货梯条件 | 搬运人员或司机归属单列；不与基础已含装卸重复 |
| EQUIPMENT／PACKAGING | 尾板、叉车、包装材料／人工的确认单位与用量 | 服务提供者及材料费分开，获批能力才收费 |
| TOLL／PARKING | 合规路线的实际票据及批准上限 | 实报实销，不默认参加配送提成，已含价内则不再收 |
| REDELIVERY／RETURN | 失败原因、责任、原服务范围、新服务实例 | 先报价授权；取消费不能替代持货后的返仓流程 |
| CANCELLATION | 所处阶段、已发生工作、预先披露规则及责任 | 原款保留，取消费用／退款作为单独决议，不直接删除收款 |
| INSURANCE_PREMIUM | 实际保险产品的申报价值、比例、最低保费／上限及承保约束 | 不参与配送分成；报价不等于承保；失败产生待处理保费退款／调整 |
| COD_SERVICE | 获批费率的固定额／本金比例、最低／最高费及触发时点 | 与 COD 本金独立；未收成是否收费按合同，不把百分比加到本金受益额 |
| WMS_IN／OUT／STORAGE | 实际收发、拣货行数、包装及权威占用量×时间 | 仓库提供证据，财务复核；不进入司机配送分成 |
| CHANNEL_COST | KESS／银行等实际渠道费用 | 首期作为平台直接成本；未经已披露合同和适用规则确认，不自动加收客户手续费 |
| TAX | 含税／未税、费目税务分类及批准税率版本 | 税款与净服务额分列；未核实税务口径时阻断正式发布，不默认免税或固定税率 |
| DISCOUNT／SUBSIDY | 获准费目的折扣分配、承担方与预算 | 不折减 COD／保费本金；平台出资不自动压低司机已承诺收入 |

等待时间建议从 max(有证据的到达时间,预约开始时间) 起算，扣除适用免费额度及不可归责客户的暂停区间；现场条件不明先待核实。结束事件、重叠区间、跨午夜、客户端时钟偏差均需校验。拒收、禁止进入和车辆故障不能一直累计“等待费”。

上楼需明确地面层为 0 次爬升还是当地楼层编号，并记录实际搬运层差，不能仅按“3F”猜价；电梯能否装入、可使用时段也影响能力。安装、冷链、危险品等未启用能力不因新增收费码而自动开放。

燃油、夜间、节假日等可预见加价按生效日和指定费目基数快照；先期用固定配置，不追踪实时供需涨价。重复倍率是同基数相加还是顺序相乘必须明确；本稿建议同基数各算一行，禁止默认层层乘到保险、税或 COD。

## 6. 统一计算顺序与金额规则

1. 校验身份／服务范围／货物／可用产品和有效价表；失败返回原因，不输出可支付报价。
2. 固定单位与输入快照，选唯一主运费模式；算主运费及该模式的最低收费。
3. 计算已明确获准的附加服务；百分比项只引用白名单基数，不读“含所有费用的总额”。
4. 分配折扣至允许费目，记录平台／商户／司机承担方；费目净额不得为负，不能用折扣触发另一笔暗藏最低费。低于成本门槛转授权预算审核，不能绕过安全准入。
5. 按已配置税务口径逐项计算净额／税额；保费等独立项按其自己的税务分类处理，不能一律套运费税率。
6. 汇总可支付服务费用，COD 本金另汇总展示；产生报价 ID、版本、有效期、服务范围、规则引用、四舍五入及客户确认依据。

每行同时保存计费原量、有理数费率／十进制定点数、计费量、取整模式和最终 amountMinor。金额使用整数最小货币单位：USD 分，KHR 瑞尔；不隐式换汇。后端避免二进制浮点直接累加金额；线性费率先精确计算再按 HALF_UP 到最小单位，本规则亦须随价表版本保存。取消／冲正以正数金额＋方向引用原行，不能对负数随意取整。

汇总等于各行已取整金额之和，不再对总数做隐藏的第二轮舍入。多单优惠／成本分摊如需配平，按最大余数法并用稳定行 ID 打破同余，分配和必须等于源额。现金如需按更大面额收款，单独记录现金取整差额、批准依据与承担者，不改原服务费或司机分成。示例只测 USD/KHR，未提供汇兑服务。

“客户本次应付服务费”包括配送、仓储及其他获准服务、保费和适用税费；“收货人 COD 待付货款”另列。KESS 当前契约只支付配送与保险未结项，不能因扩展价目目录就把仓储费、COD 服务费或本金自动塞入现有支付接口。

## 7. 客户价、司机／合作方价和成本分开

订单必须并列三份快照：CustomerQuote（客户收费）、ProviderSettlement（司机／承运商约定应付）、CostEstimate/Actual（经营估算／实发成本）。合作方涨价不自动改客户报价，客户折扣也不自动改合作采购价。

分成基数 B = 获批参与分成的配送净费用行合计，明确不含保费、COD 本金、税款、仓储和实报实销行。按订单平台比例 r：平台分成 = round(B×r/10000)，司机分成 = B−平台分成；尾差归司机余数，不分别舍入导致多付／少付。非分成补贴、搬运归属和已批准报销另加，分别列明。若订单协议包含特定附加项分成，则显式白名单；不得用任意名称“其他费”默认全部参与。

平台承担优惠时：保留司机已确认应付，优惠减少平台经济收益；商户承担时另有商户应收／补贴协议，不能凭空新增商户欠款。退款、拒收、事故后费用调整按责任和服务证据重新复核审批，已执行司机服务不自动归零。员工司机如果采用工资核算，不再对同一服务重复加入一份按单司机成本；工资系统仍不在首期建设范围。

经营贡献 = 按财务政策确认的净服务收入−已列明直接履约成本。外包采购、自营司机成本、能源、装卸、地图／通知、渠道、异常等注明范围与是否估算。按比例计算的“平台分成”不是净利润；客户已付也不是全部可用资金。计算成本不能同时重复扣合作采购价及已经包含在其中的司机工资／燃油。

包价比较同时看费用、交付方式、承诺时限、保险与 POD、COD 能力及异常条件。最低价不合格即排除；同口径成本未知时只列差异，不宣称最优。

成本底线按车型／区域和时间范围维护：自营计入可归属人时、接货空驶及执行里程能源、车辆使用成本、装卸与系统渠道成本；外包以协议采购价加未包含成本为准，不能再重复加已包含的司机和燃油。若内部采用目标贡献率 m，纯算术参考服务净收入目标为 C／(1−m)，其中 C 的范围、m 与估算误差均由财务批准；这不是已批准价格，也不是净利润保证。低于门槛须有预算承担者，不因业务量增加自动掩盖每单亏损。

## 8. 变更、复测、失败与退款矩阵

| 触发 | 报价／账务动作 | 业务限制 |
|---|---|---|
| 草稿改址、货物、时间／车型 | 新输入版本重新计算，旧报价标记被替代 | 不沿用原签字和旧金额付款 |
| 客户已确认、尚未派单 | 追加报价版本和差额说明；新的客户确认 | 多收转退款申请，少收补款或批准信用；不再收全额 |
| 派单后改址／加点 | 调度核能力及原承诺、付款方确认新费；司机确认新执行方案 | 收货人不能单独批准发货人承担的加价 |
| 称重／尺寸复核不符 | 保存两次测量与证据、确认新价或受控取消／退回 | 不因计费重更大而忽略车厢装载失败 |
| 平台绕路／改车／事故救援 | 保留客户原约；平台新增成本和责任审核 | 不把内部调度变化静默转嫁客户 |
| 未接单前取消 | 按已披露取消政策计算已发生费用；其余走退款 | 不默认没派车就退款已经到账 |
| 司机已到取件点取消 | 核验空驶／等待证据和责任，按批准政策申请 | 不叠收互斥的全额运费、取消费和同段空驶 |
| 已取货拒收／联系不上 | 原运输与返仓／暂存服务分别核定 | 保管安全优先；未确认新增费保持待裁定 |
| 二次配送 | 新履约尝试关联原订单，独立服务实例、费用和窗口 | 不新造 COD 本金，不重复计同一次失败收费 |
| 多件部分交付 | 件级完成／退回关联费用范围；按合同核定已完成服务 | 不能按件数比例自动退全价；不得整单重复计首重 |
| 付款金额不符／结果未知 | 待核验，先查原交易，匹配新旧报价差额 | 不标已支付、不重复发起全额扣款 |
| 保费已收但承保失败 | 独立异常、客户告知及退款／调整；如运输必须保险则停止新放行 | 不伪造保单、不拿运费冲平 |
| 到期月结未清 | 按未结余额出账／催收与信用规则；保留原到期日 | 账单确认不是收款，不默认利息或滞纳金 |

所有正式减免、退款、冲正、核销和付款沿用财务独立复核＋审批及版本绑定；业务报价确认不是财务付款批准。

## 9. 仓配计价与按客户合同

仓库起码区分入库卸货／验收、上架、存储、拣货、出库复核、包装、装车交接、退回验收。每项可按合同含在服务包内，不能所有节点都默认收费。仓储计费依赖库存事件和保管范围：货主、仓库、库位类型、占用体积／托位、起止事件、免费期及日切规则。库存数量不能代替占用面积，未知量不填零。

选择日结快照或精确占用时长一种策略，并固定切日、出入库当天是否计、跨月／时区、异常隔离库存是否收费；内部移库不能重新起算免费期。月最低消费／包量如采用，在期末显示服务已发生额和合同补足额，不重算每张历史订单。阶梯量价明确是只对超量部分优惠还是追溯全期；首期建议前者，避免月末改写所有已确认报价。

不同客户账期影响出账、到期和通知时间，不应暗中改变单位运价。后付信用、预付安排、可用额度、合同费率和账单周期分别保存。客户与供应商结算周期也分别配置，不用 COD 或待付司机款填补价格亏损。

## 10. 页面和消息应展示什么

| 页面 | 必须显示／操作 |
|---|---|
| Telegram Mini App 报价 | 运输产品、具体交付点、计费重／距离依据、基础含量、附加项、优惠、保费、总价、有效期、费用变化条件；确认后给订单号 |
| Bot 报价卡 | 摘要＋逐项费用＋有效期＋查看明细／修改／确认；旧卡版本失效明确提示，两入口重复确认不重复建单 |
| 客户订单／账单 | 已确认价、批准调整、已核验付款、未结；COD 本金／服务费／待返还分列，提供争议入口 |
| 调度 | 可承接与否、报价版本、客户确认、付款／月结准入、合格运力价格比较；补费／减免走申请 |
| 司机 App | 自己的任务、应收代收分项、预计应付与计算依据、报销及异常申报；不能编辑客户报价或保险费 |
| 仓库 | 测量、件数、包装／搬运／存储服务依据与差异，提交费用依据，不直接改已确认账 |
| 财务 | 客户费项、应收与应付、折扣承担方、保险／COD、核销、差额审批、账期及渠道费，按来源追溯 |
| 运营计价中心 | 产品与适用范围／基础价表／附加费／客户合同／分成与采购／模拟核价／版本发布；按 TAB 拆分 |

报价页不能只写“合计 $X”；也不要要求客户看内部成本和利润才能下单。未知费用必须写明待核实范围及处理方式，不输出看似最终可支付的精确总数。提前可知的费用在确认前披露；现场不确定费用先申报、取证和授权。

## 11. 交付顺序与上线准入

1. 先实现统一 Quote 及逐行 FeeItem 扩展、价表版本、两类主运费和金额取整；CONTRACT 只接受有凭据的授权核价。
2. 接上区域／重量／尺寸测量、客户确认、预付／月结派单守卫；各端同读报价，修复旧展示页和工作台孤立计算。
3. 接上分项分成、合作应付、等待／搬运／返仓证据、补退差额与财务审核。
4. 合成边界算例和服务端并发／幂等验收后，使用脱敏实际成本影子核价；不要求先做市场验证，也不以缺实际资料阻止领域实现。
5. 运营填写并批准正式费率、财务确认税务／分成与成本口径、合作方／保险合同核对后，才允许生产报价。没有这些资料不能从本文示例一键上线。

首轮暂不做实时竞价／动态涨价、国际关税、自动理赔或复杂会员；这些不是保证基础计价正确的前置条件。首期上线目标是“同输入同版本同金额，客户收费可解释，司机应付可核对，异常差额有路径”。

| 仓储 | 假设1.5 m³存5计费日、免费2日、0.40 USD/m³·日：1.80 USD；真实日切及占用来源仍须合同确定 |
