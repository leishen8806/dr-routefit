## 1. 调度优先级的可执行含义

必须先过滤硬约束，再对可行方案进行业务排序；禁止用单一加权总分让低价、短路程或高优先级抵消安全、装载与承诺违约。

| 层级 | 规则 | 系统行为 |
|---|---|---|
| P0 安全与合法装载 | 核定载重、有效容积、货物运输限制和装卸安全 | 不满足直接排除；人工批准不得突破安全 |
| P1 及时送 | 所有已接受承诺受保护；未承诺订单中及时送优先 | 先验证取送时间窗与服务能力，再在可行候选中优先安排及时送 |
| P2 车辆适配 | 车型、内部有效尺寸、门洞、剩余载荷、货物属性、司机/车辆时间窗口 | 同样是准入硬约束，不是派单后补做的低优先级检查 |
| P3 顺路拼单 | 新增取送点不破坏**任何**已承诺订单的时效及装载约束 | 可行且完成规定确认后才允许提交；不能只保护高等级订单 |
| P4 配送成本 | 在上述条件满足后减少里程、空驶和成本 | 在可行方案中优化，不用拼单率替代整体履约质量 |

因此 P0–P4 是业务说明层级，不是“先抢最快车辆、再检查装载”的执行顺序。执行顺序为：数据有效性 → 安全/资格/装载/时间窗联合可行性 → 及时送业务优先 → 可行顺路方案 → 成本优化。沿用 RULE-004 的同级排序：最晚可派发、承诺截止、需求时间、稳定 ID。

及时送不等于只选最快车辆，也不等于付费独享闪送。足够缓冲满足既定门槛后，可比较可行方案的成本；不能无限加价追求多几分钟缓冲。道路时间估计不是履约保证，沿用 RULE-003 的来源、校准和人工承诺边界。

无可行方案返回既有 `NO_FEASIBLE_CAPACITY`，界面提示“当前无满足已确认时效与装载条件的可行运力”。提示调度寻找额外合规运力或与客户协商新承诺；不得自动放宽约束、覆盖原承诺或自动派发。用户原文的“无可保证时效的运力”不解释为系统能给其他方案作绝对准时保证。

## 2. 必需数据与单位

### 车辆与司机

- 车型、核定载重、经核验的有效可用载重、内部可用长宽高及有效容积；不得以外部尺寸或车型宣传容积代替实测。
- 门洞有效尺寸、开门方式、尾板及其他设备、固定/通道占用、运输货类限制。
- 当前与计划载荷按路线区段计算；已承诺的任务也计入资源校验，避免只减已装车货物。核定载重、固定占用与货物占用分别记录，禁止重复扣减。
- 司机资格、工作时段、车辆可用窗口、位置来源及时间、车型/装载档案版本。
- 内部尺寸与门洞等参数须做一致性检查；未知值不得填 0 当作有效容量。

### 订单与货物

- 按包装后的实际货件/规格组登记长、宽、高、单件重量和数量，并保留实测/已验证模板来源、版本及有效范围；不是商品裸尺寸。
- 允许摆放方向、能否平放/旋转/堆叠、不可倒置、易碎、温控及其他运输限制。
- 取送地点、入口及各自时间窗；上楼、搬运、特殊设备和预估停靠/装卸时间。
- 服务等级独立于履约方式及计费选项。及时送对应既有 S1，预约送对应 S3；“普通送”尚不足以自动等同 S2 当日送，必须保留具体承诺窗口并在服务目录中明确映射。不删除既有 S2/S4 规划。
- 关键数据缺失或未经验证时，不得自动确认适配；进入补资料或授权人工复核。人工复核需有效依据，不可勾选后绕过安全硬约束。

### 体积计算

`单件体积 m³ = L(cm) × W(cm) × H(cm) / 1,000,000`

`货物总体积 = Σ（包装后单件体积 × 对应件数）`

用户示例中的 1.728 m³ / 假设车辆容积 6 m³ = 28.8%，该占比计算成立。但示例未提供具体长宽高及件数，不能反推或验证 1.728 m³ 的来源。3/6/12 m³ 均仅为讨论假设，不生成实际车型默认参数或可装载承诺。

容积占比只用于初筛。例如不允许外露、且合法摆放方向无法通过门洞并容纳于车厢的 3 米板材，不可因体积仅 0.3 m³ 就安排至内部长度 2 米的车厢。是否允许旋转须使用实际许可方向及几何验证，不能擅自假设可斜放。

## 3. 两层装载验证

1. **快速筛选**：有效数据、总重、总容积、车型/货类、单件允许方向、内部三轴尺寸、门洞、设备和司机时段。明确不可行直接拒绝。
2. **组合装载验证**：家具、板材、门窗、大型包装等必要场景使用经验证的装载模式或独立 3D 装箱能力，检查物体重叠、许可朝向、堆叠/支撑、固定与装卸空间、门洞可进入性及卸货顺序。仅放得进静态箱体不代表能从门洞装入或安全卸出。

装箱返回不可行则拒绝；超时、缺失约束或无法证明时保持 UNKNOWN/`MANUAL_LOAD_REVIEW`，不得转换为可自动派单。人工安全放行仍保留实际凭证与责任人。求解器通过只证明其已建模约束，不替代实际运输安全检查。

这次确认提升需求约束的明确性，**不要求正在开发的人工 R1 路径立即接入通用 3D 引擎**。R1 使用核验模板/模式与人工放行；复杂通用求解仍按既有 R4 及 D24 的评估和放行安排推进。禁止以尚未接入的装箱结果宣称“已验证”。

## 4. 时效与顺路协同

订单进入池 → 识别等级/取送窗口 → 过滤不合格候选 → 校验取件行驶、等待、装卸、运输和交付时间 → 在保护所有原承诺的条件下优先及时送 → 评估插入取送点 → 重算全部受影响订单时间及各区段载荷/装载 → 生成带数据/路线版本的候选 → 规定的调度及司机确认 → 原子复验 → 执行与独立签收。

示例：已有订单承诺 14:00 前交付，插单方案预计 14:10 才交付，必须拒绝；不能以新增收入、空间足够或新单等级更高为理由放行。

取件点必须先于送件点；不能只检查出发时或最终剩余容积。确认时重验路线版本、预留、资格、时窗和逐段容量；旧方案失效必须重算。拒绝新插单不损害原任务，也不改原承诺。

阶段不变：R2 先推荐，R3-A 发车前同仓合单，R3-B 途中插单，R3-C 受控返程独立放行。此次需求确认不自动开启这些能力。
