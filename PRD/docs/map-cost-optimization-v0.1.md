# 地图路线与导航成本优化方案

v0.1，2026-10-24 官方资料核查后的建议，不是 D24 选型批准。目标先跑通配送和合理派单，再依据实际调用账单决定自建范围；不以地图调用费更低为由牺牲车辆安全和承诺。

## 1 建议架构

| 能力 | 初期建议 | 成本控制 |
|---|---|---|
| 调度底图 | 使用授权的商业地图，按需加载并复用页面内实例 | 切 TAB 不反复重建地图；更新车辆图层而非重载底图 |
| 订单地址 | 客户填写/落点并核对入口，确有需要时搜索/地理编码 | 输入防抖、明确选择才查详情；地址/引用保存按来源授权，不反复解析同一业务地址 |
| 车辆位置 | 设备授权定位传给自己的后台 | 位置上传不等于调用路线 API；不逐点逆地理编码或吸附道路；后台定位仍需设备/电量/隐私验证 |
| 调度路线 | 先用自有业务数据筛掉无资格/已占用/超载/不服务该区域车辆，再查候选道路时间 | 只对受影响候选/区段计算；同仓共同取货点去重；批量不改变矩阵元素计费数量 |
| 司机导航 | 逐站打开 Google Maps 等已安装应用，先不内嵌收费 Navigation SDK | 路线任务和站点顺序由 RouteFit 管理，外部导航只导航到当前站 |
| 客户跟踪 | 优先显示本单时间线及当前位置摘要，地图按需打开 | 不为每个页面刷新重新求路线；不显示其他客户站点或全车队 |

Google Maps URLs 不需要 API key，可打开地图应用/网页并请求导航。它不是 Navigation SDK；调用外部应用不提供平台完整路线执行回调，也不能保证强制遵循 RouteFit 给定的具体道路。原生地图不存在时应提供网页/地址复制兜底。不能将“外部导航打开了”当作取货、到达或签收成功。[官方 Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)

## 2 真正影响费用的调用

地图展示、地址搜索/编码、道路路线、距离矩阵、轨迹匹配、内嵌导航分别计费。以 Google 为例，Compute Routes 按请求，矩阵按起点×终点的元素；交通感知、站点优化及某些车辆能力会触发更高 SKU。不能为追求低 SKU 删除货车通行条件。[Routes 计费说明](https://developers.google.com/maps/documentation/routes/usage-and-billing)

核查时全球公开价：Compute Routes/Matrix Essentials 各有每月10,000免费计费单位，随后首档每千单位$5、100,001–500,000档每千$4；Navigation Request 免费1,000单位后首档每千$25。不同SKU、账户共享用量、合同、税费及后续价格变化都影响最终账单。[官方价格表](https://developers.google.com/maps/billing-and-pricing/pricing)

**假设算例，不是本项目预算：**每月10,000单，每单比较20辆车到一个取货点，只计算这一段矩阵就有200,000元素；按上述 Essentials 阶梯，约$850。若业务过滤后平均只需3辆且不必扩大搜索，则30,000元素约$100。两者都不含送货路线、地图、地理编码、重算及导航；实际使用交通/车辆特性时不能沿用 Essentials 价格。这里减少的是待计算候选数量，不是将20辆拼成一个HTTP请求就省钱。

### 2.1 Google Maps Platform 最小开通与计费清单

以下是准备接入用的最小清单，不是采购承诺，也不是把所有能力一次开通。价格采用 2026-10-26 官方全球公开价的首个付费阶梯，均按每 1,000 个计费单位；最终账单以账户所在地区、合同、税费和当月 SKU 实际用量为准。[官方价格表](https://developers.google.com/maps/billing-and-pricing/pricing)

| RouteFit 用途 | Google 能力 | 何时调用 | 公开价口径 | 首期是否开通 |
|---|---|---|---|---|
| 用户在地图上选点、调度看车辆与订单 | Maps JavaScript API（Web）／Maps SDK（iOS、Android） | 页面按需展示；不因列表或 Tab 切换反复加载 | Dynamic Maps 每月 10,000 次免费，之后首档 $7；移动 SDK 当前公开价为免费 | 是，按端分别开受限凭据 |
| 地址文字 → 经纬度；经纬度 → 可读地址 | Geocoding API | 提交、明确选址、改地址或人工复核时；不随每次位置上报调用 | 每月 10,000 次免费，之后首档 $5 | 是，服务端调用 |
| 地址输入联想、选择可信地点 | Places API (New) Autocomplete／必要的 Place Details | 用户主动输入地址时节流；选定后再取最小必要字段 | Autocomplete 每月 10,000 次免费，之后首档 $2.83；详情另按所选 SKU 计费 | 试点后开通，不作为必填前置 |
| 一笔报价、改址后的距离、ETA 与路线 | Routes API Compute Routes Essentials | 报价、重新报价、已确认订单变更与异常复核 | 每月 10,000 次免费，之后首档 $5 | 是，服务端调用 |
| 调度候选车辆的道路时间比较 | Routes API Compute Route Matrix Essentials | 已经过区域、载重、容积、时窗等硬约束过滤后的候选集 | 每月 10,000 元素免费，之后首档 $5；元素数 = 起点数 × 终点数 | 是，服务端调用且限额 |
| 应用内语音导航、道路吸附、车队路径优化 | Navigation SDK、Roads、Route Optimization | 不进入首期 | 对应 Pro／Enterprise SKU，不能用 Essentials 预算替代 | 否 |

地址与坐标不是可以互相覆盖的同一个字段：保留用户输入的原始地址、入口/地标说明、已确认坐标、来源、精度和核验时间。逆地理编码只返回邻近的可读候选，可能无结果或与实际交接入口不一致，不能静默改写交付约定。[逆地理编码说明](https://developers.google.com/maps/documentation/geocoding/reverse-geocoding)

### 2.2 账号、密钥与费用归属

1. 建立独立的 Google Cloud 项目 `routefit-maps-prod`；开发、试点和生产不得共用账单项目或密钥。
2. 分开创建 Web、Android、iOS 和服务端四类凭据。Web 仅允许 RouteFit 域名；Android 绑定包名与签名；iOS 绑定 Bundle ID；服务端仅允许固定出口 IP 或使用支持的 OAuth。每把密钥再限制到所需 API，绝不提交到 GitHub、静态 Demo 或移动端服务端配置中。[Google Maps 密钥安全建议](https://developers.google.com/maps/api-security-best-practices)
3. GeoPort 对每一次收费调用追加记录：订单/调度场景、用途、供应商、SKU、计费单位或矩阵元素数、请求摘要哈希、缓存命中、重试、耗时、结果质量、估算金额和账单对账状态。完整地址、完整轨迹和密钥不进入公开日志。
4. 创建以 Maps SKU 为范围的月度预算提醒，建议在 50%、80%、100% 与预测超额时通知技术负责人和财务；仅告警预算不是硬性停用，仍由服务端日额度、QPM/EPM 配额和降级策略控制。[Cloud Billing 预算说明](https://docs.cloud.google.com/billing/docs/how-to/budgets)
5. 报价快照保存使用的坐标版本、路线引擎、SKU 类别、距离、ETA、计算时间与费用规则版本。重新报价才生成新快照；不能因后续地理编码或地图数据更新悄悄改变已确认价格。

## 3 控制策略

1. **候选分层但不误判无解。**资格、容量、时段等先过滤；距离近只能作为粗排序，不能用直线距离证明道路可行。可先算少量候选，无可行解时逐步扩大；预算耗尽时标“未完成搜索”，不能假报无运力或全局最优。
2. **按业务事件重算。**新增/变更订单、司机接受/拒绝、站点完成、明显偏航或时效风险触发；车辆每次上报坐标不自动触发全路线计算。阈值待试测，不把固定秒数写成既定策略。
3. **草稿编辑节流。**拖拽站点先本地预览，松手/确认后计算；并发相同输入合并进行中的请求。已在处理的请求复用不等于允许持久化第三方结果。
4. **地图不重复加载。**保持地图组件，批量更新标记/路线层；隐藏页面暂停非必要刷新，回来显示时效并按需更新，不能把旧数据伪装实时。
5. **导航逐站跳转。**传当前站业务坐标/授权位置引用；司机任务列表仍在本平台。使用普通 driving 导航不等于有货车限高限重保证，平台车型约束与调度复核仍保留。
6. **费用台账。**逐请求统计用途、供应商、SKU、元素数、是否重试、耗时、候选数与失败原因；不记录完整敏感地址到公开日志。按日、每单、每活跃车查看消耗，区分估算与供应商实际账单。
7. **配额和降级。**服务端控制候选数量、频率、重试和日额度；按优先级限制新批量优化，保留必要的在途异常处理预算。超限转人工复核，不能虚构路线或终止已确认货物保管链。

仅设置 alerts-only 预算不会自动封顶；如使用云平台 spend-cap 功能须确认本账户、目标服务和执行条件，不能只凭告警当作硬上限。仍需服务端调用控制与供应商 API 配额。[预算官方说明](https://docs.cloud.google.com/billing/docs/how-to/budgets)

## 4 不能采用的省钱方式

- Google Routes 的缓存受限制；place ID 的可保存例外不能外推到所有坐标、时间矩阵、路线几何。Google 路线若在地图展示须按其 Google Map 展示要求；不能默认画到免费的其他底图上。底图、路线、编码来源及储存许可要配套核对。[Routes 使用政策](https://developers.google.com/maps/documentation/routes/policies)
- OSM 数据开放不等于社区公共瓦片服务器可用作无限商业基础设施；公共服务器无 SLA，禁止批量下载和离线预取。生产需要有合适授权的瓦片服务或自行托管，不用代理抓取绕过限制。[OSMF 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)
- 自建 OSRM 可提供 route/table 能力，但仍有服务器、地图数据更新、配置、故障处置和地址质量成本；其道路时间不自动等于实时交通或全车型装载/限行保证。[OSRM 项目文档](https://github.com/Project-OSRM/osrm-backend/blob/master/docs/http.md)

## 5 选择判断

**已知事实：**当前仅合成路线 Demo，无实际日订单、API用量或地图账单；Google 官方覆盖表包含柬埔寨驾车路线和地理编码，但不证明具体入口、货车适用性和现场误差。[覆盖表](https://developers.google.com/maps/coverage)

**假设：**初期允许司机跳转外部导航，尚不要求应用内全程语音/偏航回调；商业服务可在可控配额内试用。**推断：**优先减少多余调用，比在无用量证据时自建全套地图更符合“先跑通”。**未知：**当地地址/货车路线质量、账号最终SKU、订单量、候选数与重算频率。

反对这一建议的三个主要理由：外部导航打断任务体验且不能强制道路路径；柬埔寨实际入口/道路适配仍未知；高频矩阵或高阶SKU可能使商业成本快速增加。

支持的三个主要理由：无需先建设内嵌导航；业务资格筛选能减少无价值调用；GeoPort 保持供应商适配边界，可在真实账单出现后验证替代方案。

### Verdict

先采用“商业地图/路线按需调用 + 外部导航 + 服务端过滤/计量/配额”的可回退切片，不立即自建全套地图，不冻结具体供应商。增长后只迁移经验证成本高且可替代的能力。

### Confidence

80%，为当前执行建议的主观置信度，不是节省比例或当地地图准确率。

### Why

当前缺实际用量，全面自建的运维成本不能证明更低；减少无效矩阵与重复加载具备直接可计量的效果。

### Key Variables

每单候选/重算元素数；实际车型与交通功能所需SKU；外部导航和当地地图的任务完成质量。

### Largest Unknown

真实车辆条件下每单可用路线的地图成本与错误率。

### Reversal Condition

若现场任务必须应用内导航、授权道路能力不满足车型，或经验证商业总成本持续高于可维护的自建/其他服务总成本，则调整方案；不凭免费额度大小直接换供应商。

## 6 最小技术验证

建议用2个工作日、20组获授权或合成坐标（含仓库入口、城市道路、郊区、绕河路线）比较路由质量和API计数；不把它当生产上线验收。

- 假设：先过滤候选与事件触发计算能减少调用，不破坏原可行订单分配。
- 测试：同一输入比较全候选基线与渐进候选方案；记录矩阵元素、实际SKU、候选覆盖、最终时窗与车型约束；手机测试打开导航、返回任务及站点不自动签收。
- 成功条件：这组样例没有新增安全/承诺违规，已知可行样例不被误报无解；调用量低于全量基线且每笔费用可解释。
- 失败条件：任何危险道路/车型违规、丢单、重复计费、假报无解或API消耗失控，先修复再扩展；地图质量差时换数据源测试。
- 测试后：按真实调用分布填写小/中/高订单量的费用模型，再决定是否需要OSRM或其他服务的独立评估。未执行前状态为 NOT_RUN，不购买订阅或启用付费API。
