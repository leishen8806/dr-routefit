## 官方接口依据

来源于 [KESS WebPay 官方文档](https://devwebpayment.kesspay.io/docs) 的 Generate Payment Link、Query Order、Signature、transaction/order_info；核对日期 2026-10-24。旧 [WebPay 文档](https://www.kesspay.io/api/index.html) 的 Basic 认证与本版 OAuth 不能混用。

- 沙箱：`https://devwebpayment.kesspay.io`。OAuth `/oauth/token`；V2 `/api/mch/v2/gateway`，Bearer 认证。
- 创建服务按官方 V2 请求示例用 `webpay.acquire.createorder`，查单用 `webpay.acquire.queryOrder`。创建字段表另写 `createOrder`，大小写冲突已记录，必须由实际沙箱结果和 KESS 确认。
- 请求签名使用官方 HMAC-SHA256 示例规则，排序标量字段、排除 sign／空值／嵌套数据、附加密钥。不杜撰 RSA2 或回调验签协议。
- 校验 `out_trade_no`、`seller.code`、`total_amount`、`currency`、状态与成功交易标识。返回支付链接必须属于沙箱 HTTPS `/pay/`。
- 不把顶层响应签名当成嵌套交易数据已独立验签的证明。当前可信读取仅为服务器主动向固定 HTTPS 网关查单；没有开放接收回调的入口。

## 业务数据与状态

支付意向绑定公司、付款主体、订单及版本、费用明细快照、币种、最小单位总额、唯一商户支付号。金额由服务端应收明细产生，不接受用户提交“已支付”或修改总价。配送与保险可合付，后续分项核销；分成基数不含保险及 COD。USD 两位、KHR 整数；不做隐式换汇。

创建不等于收款；返回页、截图、通知文案不构成资金确认。`WAITING` 为待支付；超时记 `UNKNOWN` 并保持原支付号，先查询原单；`SUCCESS` 仅代表渠道确认收款；失败／关闭必须有渠道查询事实，不能按浏览器超时推断。退款类渠道状态交人工处理，适配器返回原状态，不自动冲销历史收款。

成功形成唯一收款来源，重复查询不再入账。其保管方为 **KESS，待渠道结算**，不增加公司银行保管余额或可对外付款额度。经办仍需选择应收账项 → 独立复核 → 独立审批 → 核销，满足预付派单门槛。渠道成功不修改履约、签收或司机收入。

款已收但订单费用变更或其他款已核销时，不重写来源；核销按实时未结检查，超额保留待分配并进入退款／人工处理。后续渠道结算应独立保存毛额、手续费、净额、币种、批次与银行流水；不将到账净额减去保险、COD 或司机收入来凑平。

## 沙箱使用

服务端文件：[适配器](../../integrations/kess-pay.mjs)、[显式联调入口](../../integrations/kess-sandbox.mjs)、[支付意向 sandbox worker](../../services/routefit/scripts/kess-payment-worker.mjs)、[环境变量模板](../../integrations/.env.example)。支付意向先持久化，再由 worker 在事务外创建或查询原渠道订单；超时只进入未知状态，不能重新生成商户单号。密钥仅在本地受保护环境变量中设置，不放聊天、Git、日志或浏览器。

经授权的测试意向 JSON 示例：`{"tradeNo":"DR-SANDBOX-001","amountMinor":1200,"currency":"USD"}`。金额是测试来源快照；该 CLI 是操作者工具，不能作为公开接口收取任意浏览器金额。

```text
node integrations/kess-sandbox.mjs create <测试意向文件路径>
node integrations/kess-sandbox.mjs query <同一测试意向文件路径>
```

创建超时后只查询同一意向，不能换号重付。此工具无数据库，不提供跨进程幂等；因此只允许沙箱操作，不用于生产。正式后台必须在外部请求前持久化意向，并以事务保证公司／渠道／交易标识唯一，保存历史未知与补查结果。

## 接通所需资料与验收

KESS 测试商户 client ID、client secret、API 用户名／密码、签名密钥、seller code，及商户合同确认的 API 版本、支持币种、手续费和结算安排。正式回调还需确认完整签名、重放、重试及应答契约；生产地址与允许的收银台域名由 KESS 提供，禁止猜测。

已验证本地签名、请求字段、OAuth 复用、错误处理、不自动重试、错误对象／金额拒绝、渠道账与公司余额隔离及浏览器交互。真实 KESS 支付、渠道关闭后迟到成功、Webhook、退款／冲正、扣费净额结算、生产并发与长期补查尚未验收。正式启用前须以商户沙箱实证和服务端实现分别补齐，不能把单测响应替身称为 KESS 沙箱通过。
