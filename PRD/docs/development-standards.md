## 1. 基本原则

1. **契约先行。**接口、事件和数据结构先在 `contracts/` 中定义并评审，再写实现（PRD 13.2）。
2. **规则可追溯。**每段业务逻辑能追到 `ROUTEFIT-RULE-xxx`，每条规则至少有一个 `ROUTEFIT-AT-xx` 验收案例。
3. **未知是一等公民。**缺失、未知、超时都有明确表达，不默认为 0、true 或"成功"。
4. **安全底线不降级。**对象授权、幂等、审计、实物保管在任何降级模式下都不放宽（PRD 6.5）。
5. **证据说话。**"已完成"以固定 SHA、测试记录和运行证据为准；文档存在不等于功能完成，Mock 通过不等于真机通过。
6. **不自审。**实现者不能批准自己的代码；独立审查针对固定 SHA（PRD 附录 D.3）。

## 2. 仓库结构（建议，R0-B 按技术栈确定）

```text
dr-routefit/
├─ contracts/                   # 唯一机器契约（PRD 13.2、附录 D.2）
│  ├─ openapi.yaml
│  ├─ schemas/*.json
│  ├─ events/*.json
│  └─ examples/{valid,invalid}/*.json
├─ services/routefit/           # RouteFit 领域与 API
│  ├─ domain/                   # 实体、状态机、规则；不依赖任何外部 SDK
│  ├─ application/              # 用例、事务、幂等、审计
│  ├─ ports/                    # GeoPort、CarrierPort、NotificationPort 等接口定义
│  └─ adapters/                 # 端口的具体实现（含人工登记实现）
├─ modules/geocore-g1/          # Daen GeoCore 地图基座 G1；目录名 R0-B 确定
├─ integrations/ops-snapshot/   # RouteFitOpsSnapshot 只读投影（R1-V）
├─ apps/
│  ├─ dispatch-console/         # 调度台 Web
│  └─ driver-android/           # 司机端
├─ tests/
│  ├─ contract/                 # 契约正反样例
│  ├─ acceptance/               # 按 ROUTEFIT-AT-xx 命名
│  └─ e2e/
├─ docs/
│  ├─ adr/                      # 架构决策记录
│  └─ runbooks/                 # 降级、暂停、恢复操作手册
└─ brand/                       # 品牌资产（或引用外部资产库）
```

**依赖方向（CI 中用架构测试强制）：**

- `domain` 不依赖 `adapters`、数据库驱动、供应商 SDK 或 UI。
- `modules/geocore-g1` 不引用 RouteFit 业务代码；RouteFit 只通过 GeoPort 调用它（PRD 5.1）。
- `integrations/ops-snapshot` 只读，不存在任何写业务的调用路径（PRD 21.6）。
- 影子推荐代码不能调用 Assignment、RoutePlan、预留或通知的写接口（PRD 11.2、AT-43）。
- 不共享数据库：RouteFit、GeoCore G1、既有 `E:/Daen_GeoCore`、智序工场各自持有数据，只经接口交互。

## 3. 分支、提交与评审

### 3.1 开始前

- `fetch` 并核对 origin、目标分支、完整 SHA、工作区状态和依赖锁文件；记录基线 SHA。
- 不为"同步"强制回退 `main`，不共享 stash（PRD 附录 D.3）。

### 3.2 分支与提交

| 项目 | 规则 |
| --- | --- |
| 分支名 | `<类型>/<任务编号>-<简述>`，例：`feat/ROUTEFIT-R1-012-load-release` |
| 类型 | `feat`、`fix`、`contract`、`test`、`docs`、`refactor`、`chore` |
| 提交信息 | `ROUTEFIT-R1-012: 实现装载放行失效规则` ；正文写明关联 RULE／AT |
| 提交粒度 | 一个提交只做一件事；契约变更单独提交 |
| 禁止 | 提交凭据、真实客户／司机数据、真实轨迹、生产配置；对 `main` 强推 |

### 3.3 合并请求

每个合并请求必须包含：

- 任务卡编号与目标 Gate。
- 关联的 `ROUTEFIT-RULE-xxx` 与 `ROUTEFIT-AT-xx`。
- 契约版本；如有契约变更，附变更说明和兼容性判断。
- 测试结果清单：PASS／FAIL／**NOT_RUN（必须列出并说明原因）**。
- 界面改动附截图，覆盖设计标准第 5 章的状态集。
- 新增依赖的名称、版本和许可证。

### 3.4 审查与合并

- 独立审查者审查固定 SHA 和限定差异，不审自己的实现。
- 人类集成负责人批准候选的依赖与差异；选择性转移代码导致 SHA 变化时，适用内容须复验。
- 合并 `main` 与部署是两次独立授权。
- 完成后推送独立分支并核对远端 SHA；没有推送不算异机交付。

## 4. 契约规范

### 4.1 格式

- 接口用 OpenAPI 3.1，数据结构用 JSON Schema 2020-12；OpenAPI 引用同一份 Schema，不在多处手写不同定义。
- 进程内接口（如 GeoPort 在同一进程时）用类型定义 + Schema + 契约测试；只有真实 HTTP 边界才写 OpenAPI 路径（PRD 5.2）。
- 每个 Schema 至少有一个合法样例和覆盖主要拒绝原因的非法样例（PRD 13.2：缺字段、显式零、重复 ID、公司不符、未知枚举、非有限数值、无时区时间、路线冲突、过期提案、重复支付、定位过期）。

### 4.2 版本

- 每个契约有 `schemaVersion`（语义化版本）。
- 破坏性变更：新主版本 + ADR + 迁移说明；旧版本的退役时间由人类集成负责人批准。
- 生成代码或校验器时记录契约版本和文件哈希。

### 4.3 字段约定

| 类别 | 规则 |
| --- | --- |
| 命名 | 字段 `camelCase`；枚举值 `UPPER_SNAKE_CASE` 或 PRD 已定的小写状态名，同一枚举内保持一致 |
| ID | 不透明字符串（建议 ULID 或 UUID），不承载业务含义，不可从客户端推测 |
| 时间 | RFC 3339，带时区偏移；服务端以 UTC 存储；展示时区 `Asia/Phnom_Penh` |
| 观测与接收 | 设备上报的数据同时带 `observedAt`（设备时间）和 `receivedAt`（服务端时间） |
| 时长 | 整数并在字段名中写单位，如 `serviceSeconds`、`ttlSeconds` |
| 物理量 | 字段名带单位：`weightKg`、`lengthCm`、`volumeM3` |
| 金额 | `{ "amountMinor": <整数>, "currency": "USD" | "KHR" }`；按币种最小单位存整数，禁止浮点；KHR 的小数位在 R0-B 契约中确认 |
| 未知 | 用 `null` 加 `unknownReason`，或显式 `UNKNOWN` 枚举；**禁止用 0 表示未知** |
| 企业作用域 | `companyId`／`operatingCompanyId` 由服务端从认证主体推导，请求体中的值只做一致性校验，不作授权依据 |
| 合作方 | `carrierPartnerId` 与 `operatingCompanyId` 是不同字段，不合并（PRD 21.3） |

### 4.4 数据可信字段

外部来源或可能过期的数据统一携带：

| 字段 | 含义 |
| --- | --- |
| `source` | 数据来源（如 `WAREHOUSE_MEASURED`、`DRIVER_GPS`、`CARRIER_REPORTED`） |
| `computedAt`／`observedAt` | 计算或观测时间 |
| `dataVersion` | 数据或适配器版本；供应商不提供时写 `UNAVAILABLE`，不伪造 |
| `quality` | `fresh`／`stale`／`partial`／`unavailable` |
| `mode` | `live`／`demo`／`shadow`／`unavailable` |

### 4.5 错误模型

所有接口返回统一结构：

```json
{
  "error": {
    "code": "PLAN_VERSION_CONFLICT",
    "messageKey": "error.plan_version_conflict",
    "retryable": false,
    "details": { "expectedVersion": 7, "currentVersion": 8 },
    "requestId": "01J..."
  }
}
```

- `code` 为稳定英文编码；界面文案通过 `messageKey` 本地化。
- PRD 已定义的编码必须原样使用，例如：`OFFER_EXPIRED`、`PLAN_VERSION_CONFLICT`、`OUT_OF_PILOT_SCOPE`、`PILOT_NOT_APPROVED`、`ETA_UNCALIBRATED`、`UNAVAILABLE`、`TIMEOUT`、`OUT_OF_COVERAGE`、`LOW_CONFIDENCE`、`FORBIDDEN`。
- 新增编码先加入契约，再使用。

## 5. 领域实现规范

### 5.1 状态机

- 每个状态机（Order、Assignment、RoutePlan、ReturnTask、Collection、Remittance、CarrierBooking 等，PRD 6.1、21.3.1）的转换表集中定义在一处。
- 状态只能通过转换操作改变，禁止直接更新状态字段。
- 每次转换检查：执行角色、当前状态、对象版本、幂等键、对象授权；成功后同一事务内写领域事件和审计事件。
- Order 是总览；Assignment 和 CarrierBooking 的结果按规则投影到 Order，不能双方任意改写（PRD 21.3.1）。
- 同一订单的有效 Assignment 与有效 CarrierBooking 互斥，人工登记同样校验。

### 5.2 幂等

- 所有写接口要求 `Idempotency-Key` 请求头。
- 服务端保存"幂等键 + 请求摘要 + 首次结果"；同键同内容重放返回首次结果；同键不同内容返回冲突错误。
- 司机端离线队列的每个事件自带幂等键，恢复后按原事件时间上传（PRD 6.2、6.5）。
- 对外部系统（快递 API 等）的请求，同一业务请求的幂等键和外部请求 ID 固定；超时后先查询，不换新键重试（PRD 21.3.2）。

### 5.3 并发与预留

- 对象带 `version`，写请求用 `If-Match` 或请求体中的版本做乐观并发控制。
- 提案使用带 TTL 的软预留，不持有跨司机确认的数据库长锁（PRD 7.1）。
- 司机接受时在一个短事务中复验提案有效期、路线版本、容量和时间窗；承诺级预留在同一事务中转换为执行占用；改派时原子转移，失败整体回滚（PRD 3.8）。
- 同一车辆的容量校验在数据库层面保证原子性，覆盖"两条不同路线同时预订同一车辆"（AT-72）。

### 5.4 外部调用

- 所有外部调用（GeoPort 供应商、CarrierPort、通知渠道）有超时、结构化失败原因和熔断；不在请求线程内无限重试。
- 有副作用的外部操作用 outbox（可靠事件表）记录并异步执行，不宣称本地事务能回滚外部已发生的操作。
- 结果未知时进入"待确认"状态和人工跟进队列，不重复下单、不推定成功或失败。
- 外部事件保存 `providerEventId`（或稳定去重依据）、`occurredAt`、`receivedAt`、`rawStatus`、`mappedStatus`、`mappingVersion`；未知状态不映射为成功。

### 5.5 时间

- 服务端时钟为准；服务器启用时间同步。
- S1 承诺时钟从 `promiseAcceptedAt` 起算，改派、重新派车都不能重置（PRD 3.1、AT-35）。
- 延迟上传的位置点保留原观测时间，不成为"当前位置"（AT-12）。

### 5.6 演示与影子隔离

- demo 数据使用独立数据集或明确 `mode` 字段；生产汇总查询必须过滤 `mode = live`，并有测试覆盖（AT-15）。
- 影子推荐只写 `RecommendationLog`，不写业务对象、不发通知、不做预留（AT-43）。
- 读取失败时不得静默回退到 demo 数据（PRD 21.6）。

### 5.7 功能开关

- PILOT-0（PRD 附录 C）中的每项能力都有独立开关，默认关闭；未批准参数不得作为生产默认值。
- 试点暂停（PRD 15.1）通过按能力的开关执行，开关变更需要授权并写审计。
- 开关读取失败时按"关闭"处理。

## 6. 安全与隐私

### 6.1 认证与授权

- 默认拒绝；每个读写接口都做对象级授权，不只校验登录。
- 企业作用域只从认证主体推导，客户端传入的 `companyId` 不能扩大权限（AT-14）。
- 合作司机只能访问被指派给自己的任务（PRD 11.1.1）；快递承运方不能访问企业的订单、司机、客户或地图私有数据。
- 中控台跳转只携带非敏感 ID 或服务器签发的短期引用，RouteFit 重新校验身份和权限（PRD 21.6）。
- CI 用第二个合成公司做跨企业拒绝测试。

### 6.2 凭据

- 凭据只放在密钥管理服务或部署环境变量中，不进仓库、不进前端、不进日志。
- CI 运行密钥扫描；发现泄露立即轮换，而不只是删除提交。
- 测试环境不得复制生产配置或凭据（PRD 17）。

### 6.3 个人信息

- 只收集业务必需的数据；日志、错误信息、URL、分析埋点中不出现电话、地址、证件、签收照片、银行账号或令牌。
- 照片、轨迹、客户查询链接和导出文件都受对象级授权，并有到期或撤销机制（PRD 17.1）。
- 位置只在授权班次和任务期间采集；保留期限按 PRD D11 执行，不设无限期默认留存。
- 对外分享的照片去除 EXIF 中的位置信息；取证所需的位置另行受控保存。

### 6.4 依赖与许可证

- 依赖锁定版本；CI 做漏洞扫描和许可证扫描。
- 引入新依赖须在合并请求中写明许可证。AGPL-3.0 组件（如 Fleetbase，PRD 附录 G.2）被修改并通过网络提供服务时需按许可证提供源代码，采用前由人类集成负责人评估。
- 不复制 VirtualAiOffice 或既有 `E:/Daen_GeoCore` 的代码进本仓库；复用须先评估并记录 ADR（PRD 5.1、17.2）。

### 6.5 审计

- 审计事件只追加：主体、动作、对象、前后版本、幂等键、时间、来源 IP 或设备标识；不记录凭据。
- 财务更正用冲正记录，不删除或覆盖原记录（PRD 9.3）。

## 7. 测试规范

### 7.1 测试层级

| 层级 | 内容 | 运行时机 |
| --- | --- | --- |
| 单元 | 领域规则、状态转换守卫、装载与时间计算 | 每次提交 |
| 契约 | `contracts/examples` 的正例通过、反例拒绝 | 每次提交 |
| 架构 | 第 2 章的依赖方向约束 | 每次提交 |
| 验收 | 按 `ROUTEFIT-AT-xx` 命名，覆盖 PRD 附录 B | 合并前（按 Gate 分组） |
| 并发 | 同车容量竞争、重复提交、迟到事件、重复支付 | 合并前 |
| 端到端 | 受控环境 + 合成数据的完整链路 | 候选发布前 |
| 真机 | 司机端定位、离线、强光、高棉文显示（PRD 8、14.4） | R0-B 与每次司机端发布 |

### 7.2 结果与证据

- 每个案例的结果只能是 PASS／FAIL／NOT_RUN；NOT_RUN 必须列出原因，不能被绿色流水线掩盖。
- 执行记录包含输入、预期、实际、环境、代码 SHA、契约版本、策略版本和运行标识（PRD 附录 B）。
- 试点未启用的功能，对应条件案例记 NOT_RUN 并注明"本试点未启用"，不得标为 PASS（PRD 附录 B.1）。
- 真机后台定位、实际地图覆盖、银行核验没有做，就不能用 Mock 通过替代。

### 7.3 测试数据

- 所有人物、地址、电话、账户和交易都是合成数据。
- 合成数据集至少包含两个公司，用于跨作用域测试。
- 业务采样须明确授权、最小必要、限定访问，脱敏方式在 R0 冻结（PRD 附录 D.5）。

### 7.4 测试框架本身

- 新的测试框架或门禁脚本先经审查：不复制配置、不访问未授权网络、退出码真实。
- 清理只删除本次运行明确创建的目录，不使用前缀通配删除。

## 8. 可观测性与运维

- 日志使用结构化格式，带 `requestId`／关联 ID、主体（脱敏）、对象 ID、结果编码。
- 指标覆盖 PRD 14.2 的业务指标，以及外部依赖的延迟、错误率和数据新鲜度。
- 告警：外部数据过期（stale）、对账差额、阻断异常超时、预留泄漏（应释放未释放）。
- 每种降级和暂停都有 runbook（`docs/runbooks/`），与 PRD 6.5、15.1 一一对应，并在演练中验证（PRD 2.1）。
- 发布前验证备份恢复、权限撤销、密钥轮换和回滚路径（PRD 17.1）。
- 服务重启或前端关闭不能中断已确认业务。

## 9. 国际化实现

- 文案全部使用多语言键，消息格式支持复数和变量（如 ICU MessageFormat）；禁止字符串拼接句子。
- 语言代码：`km`（高棉语）、`en`、`zh-Hans`；默认语言按试点范围表确定（PRD 1.4、D15）。
- 地址、地标、备注原文存储，不自动翻译。
- 高棉文的字形组合和行高在真机上测试；字体随应用打包。
- 金额、日期格式化只在展示层进行，不改变存储值。

## 10. 前端与移动端补充

### 10.1 调度台

- 写操作提交时携带对象版本；收到版本冲突时提示刷新，不自动覆盖。
- 列表默认按最晚安全派发时刻排序，S1 置顶（PRD 11.1）。
- 实现设计标准第 7 章的模式、质量和来源标注，不允许把 `null` 渲染为 0。

### 10.2 司机端

- 后台定位按目标 Android 版本的要求使用前台服务和相应权限；用户可随时停止，权限被拒或撤销时降级并提示（PRD 8、AT-58）。
- 离线队列持久化，事件带幂等键和原始时间；恢复后按顺序上传。
- 离线状态禁止接受新派单，禁止把未核验收款标为到账（PRD 6.2）。
- 照片在设备端压缩；上传失败不丢失。
- 最低系统版本和机型在现场调查后确定（PRD D05）。
