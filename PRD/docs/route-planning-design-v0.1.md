# 配送路线规划与调度界面设计

v0.1 草案，2026-10-24。依据[平台执行基线](platform-first-execution-baseline.md)、[调度与装载基线](confirmed-dispatch-loading-baseline.md)及 V1.4 §7、§15。目标是价格可核对、派单合理、减少无效行驶。本文为功能和交互设计，不代表真实路网、推荐引擎或定位已经接通，不改变原 RULE/AT 和阶段。

## 1 先定义路线是什么

成本专项见[地图路线与导航成本优化方案](map-cost-optimization-v0.1.md)：调度路由计算与司机导航分开，优先减少无效矩阵和重复地图加载；外部导航不回写签收，缓存/底图与路线混用遵循数据来源政策。该方案不等于供应商选型批准。

一条路线属于一个执行车辆和当班司机，包含起点、按顺序排列的站点、每站任务、进出站载荷、服务时段、预计到达/离开和结束位置。车辆当前坐标不等于仓库位置；接货空驶不能遗漏。路线结束可以是末站、原仓或批准的其他地点，比较方案时必须采用相同终点口径。

订单、路线和站点分别管理。一个站点可处理多个订单，但每笔交接/签收独立留证。同一地址不自动合并为同一收件人；楼层、入口、服务时间和货物限制可能不同。司机导航轨迹不直接改变订单状态。

## 2 输入与准入

| 对象 | 需要的数据 | 缺失时处理 |
|---|---|---|
| 订单 | 企业、仓库/取货点、送达点、入口、服务区域、包装尺寸重量件数、货类限制、取送时间窗、装卸/等待时间、服务等级及独享标志 | 地址待确认/尺寸未知不自动推荐；展示缺失原因 |
| 账务 | 有效报价版本、发货人付款核验或获批月结资格 | 未付款且无有效月结资格不进入可派队列；报价变更重核 |
| 车辆/司机 | 资格、实际可用载重与内部尺寸/门洞、设备、货类、工作窗口、当前位置时间与精度、已接任务/计划载荷 | 资格无效直接排除；定位过期不展示实时接货 ETA |
| 路网 | 点间道路距离/时间矩阵、车辆通行条件、来源及计算时间 | 不用直线距离假装道路距离；无结果转人工复核 |
| 成本 | 同币种的车辆/承运成本口径、适用版本、可计入的公里/时间/固定费用 | 成本未知仍可人工处理，但不能排序为最便宜或计算节省率 |

服务等级与独享不同：及时送按承诺安排优先；付费独享禁止普通拼单。月结是信用结算资格，不是收款成功状态。

## 3 路线生成与排序

1. 从已确认且具备付款/信用资格的订单中形成待派池，按原承诺和最晚可派时间突出风险；不能让新及时送挤掉已承诺任务。
2. 过滤无资格、区域不符、车型/装载不符、司机班次不符及已有独占任务冲突的车辆。
3. 为候选车计算当前位置到取货点的接货段，再计算送货段、必要返程段与停靠作业；保留不可行原因，不用低分掩盖硬约束失败。
4. 验证每一站的到达、等待、服务完成、逐段载荷和全体订单承诺。时间窗到底约束“到达”还是“完成服务”必须按站点契约明确；默认送达承诺按完成交付判断，不能到门口即算签收。
5. 在满足既定时效缓冲的可行方案中，按统一成本口径比较；同成本可比较空驶、总里程与稳定车辆标识。不得用加权总分补偿超载、超时或未知装载。
6. 调度查看差异并确认，司机接受；提交时复验报价/付款资格、车辆/司机资格、任务与路线版本、资源预留。期间状态变化则拒绝旧方案并重新计算。

首轮不要求求出数学全局最优。先输出能够解释、能复验、人工可选择的可行方案；“推荐”不等于自动派发。

## 4 时间和容量核算

每站到达 = 上站离开 + 有来源的道路时间；服务开始 = 到达与窗口起点中的较晚值；离开 = 服务开始 + 找入口/等待/装卸/签收等对应服务时长。缓冲按批准策略计入，不能在道路时间与每站服务中重复添加。

每段载荷 = 前段载荷 + 本站已计划装入 − 本站已计划卸下。重量、容积、实际装载尺寸和组合约束分别检查；同车所有订单都参与，不只检查新增单。取货必须先于本单送货；不可倒置、不可堆叠、卸货可达性及特殊设备按货物约束处理，未知不能标为通过。

实际到达/签收事件与计划分开保存；已经完成的站点和实际保管记录不可被重新规划改写。延期需建立风险或客户确认的新承诺版本，不允许悄悄移动原截止时间。

## 5 顺路合单与成本

先做同仓发车前合单：取货点确定、待装货物可复核，比较不同送达顺序；所有承诺可行后再比较成本。途中插单需要新取点先于新送点，尝试插入未完成路线的合法位置，重算所有剩余站及区段载荷。司机正在驶向的下一站如何冻结须形成明确策略；未确认新方案期间仍执行旧方案。

返程商业订单使用独立订单、报价、承诺和结算；事故返仓与拒收退回不是返程商业订单。R3-C 单独评审，若改变正在执行路线还要满足 R3-B。

成本应按承运模式选用互不重复的项目：自营使用批准的固定/里程/时间/通行/额外作业成本；合作车可采用约定承运价与未含的必要附加成本。若公里成本已含油耗，不再次加油费；司机应付已包含在承运价时不再叠加。已发生的固定成本与新增成本分别列示。

降本对比 = 同一批订单、同一约束与终点口径的独立配送基线成本 − 候选方案总成本。新增订单插入的增量成本用于方案比较，但不能以增量成本代替整条线路总成本。合单不得自动改变已确认客户报价或司机报酬，折扣和补偿另经批准。

合成例仅说明比较方法：独立配送 A 和 B 合计40km、成本$30；某合单方案28km、成本$24，且全部约束满足，可记录预计少12km、成本少$6（20%）。若该合单导致任一承诺超时，即使更便宜也排除。数字是假设，不是当前系统实测节省。

## 6 调度工作台设计

保留“概览 / 地图调度 / 订单队列 / 异常”主导航；地图调度内使用以下布局，不新增长瀑布流：

```text
日期/班次  仓库  服务区域  时效风险  运力状态          数据更新时间
┌ 待派订单 ─────────┬ 地图与路线 ─────────────┬ 所选方案 ──────────┐
│ 已具备派单条件    │ 车辆位置、仓库、取送点   │ 车型/司机/班次     │
│ 待付款单另分组    │ 原路线与候选路线可切换   │ 到站顺序/ETA       │
│ 服务等级/截止时间 │ 告警车辆与失效点明确标识 │ 装载/时窗通过情况 │
│ 多选同仓可合订单  │ 选择车辆或站点打开详情   │ 总成本/增量成本   │
└──────────────────┴─────────────────────────┴───────────────────┘
方案TAB：推荐方案 | 站点时间表 | 逐段装载 | 成本对比 | 排除原因
操作：重新计算 / 保存草案 / 确认派单（复验后）
```

- 推荐卡显示“为什么可行、为什么选它”，包括接货空驶、各单承诺、预计完成、剩余容量、成本来源/更新时间；候选数量不硬凑，只有一辆就显示一辆，无可行运力时明确显示无解。
- 地图拖动站点只是编辑方案草稿，必须重新计算与确认；不直接改变司机已接受路线。
- 确认弹窗对照旧/新路线、受影响订单、最晚完成、承诺风险、新增里程和司机报酬变化；不允许隐式加价。
- 未付款、定位过期、无路线、超载、服务时间不足分别给出原因和处理入口。地图加载失败仍可用订单列表和人工派单路径，不能伪装实时地图。
- 司机端只显示已确认的当前路线、下一站、取送事项、时间窗、导航和安全停车后的关键动作；新提案单独接受/拒绝，拒绝不损害旧任务。用户只见本单进度，不见其他客户路线和地址。

## 7 核心对象和接口职责

RoutePlan 记录车辆/司机、版本、状态、站点、来源订单版本及费用版本；RouteStop 记录取/送/仓库/返仓及对应订单任务；RouteLeg 记录距离/时间来源、载荷和成本；Candidate 保存候选可行性与原因、时间/装载/成本依据。名称为逻辑职责，落库先复用既有实体，不能另建第二个订单真值。

候选生成请求只计算不派单；派单确认请求才做权限/版本/预留复验。外部地图返回估计，调度领域决定业务可行性。候选失败保留原方案；中控只读取已确认结果和质量状态。幂等、并发与持久化契约沿用[接口设计](api-design.md)、[数据库设计](database-architecture.md)。

## 8 实现切片及验证

| 切片 | 页面/能力 | 必须证明 |
|---|---|---|
| 当前先跑通 | 一单一车，地址/付款/时窗/装载核验，人工确认派单，司机执行核账 | 未付款不得派，月结有效，预付不重复收款，无效运力不可选 |
| 合成路线比较 | 固定矩阵下比较同一订单集的独立与同仓方案，展示排除原因 | 算法/布局可重放，订单数量守恒、时间/容量正确，成本不重复计算；明确非真实推荐上线 |
| R2-A/R2-B | 有来源路网与位置、影子推荐、经人确认建议 | 时间估计质量与业务回放，真实数据缺失降级；沿用原阶段放行要求 |
| R3-A | 同仓发车前合单 | 全站时窗、逐段装载、费用和司机确认一致 |
| R3-B/R3-C | 途中插单/受控返程分别启用 | 已完成站锁定、定位有效、旧方案保护、原子复验与异常恢复 |

最小场景：最近车已满、远车更便宜但超时、独享单被请求拼单、两个同仓订单合单可行、取送顺序颠倒、某段载荷超限、门洞不适配、司机拒单、位置过期、候选确认时被其他任务占用、报价过期/付款失效、矩阵缺失、零基线成本不计算节省率。

每例记录计划和实际来源，比较基线、输入版本、候选、排除原因及结果。验收状态初始 NOT_RUN；不新增正式 AT 编号。本次仅设计，未更换地图供应商、冻结技术栈或接入真实算法。
