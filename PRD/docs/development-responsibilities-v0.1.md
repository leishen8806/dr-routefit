Codex辅助各自实现、检查和整理证据，不替代人类承担业务责任或独立审查。若另一方不能评审关键技术风险，明确记录未完成并补充独立技术审查；不能把“另一个Codex说通过”当作已经满足全部发布要求。产品分工不自动授予网银、财务审批或生产发布权限。

## 2. 共同工作方式

一个闭环的顺序：大旺整理功能与交互 → 你核对技术可行性并维护接口 → 双方分别实现 → 联调 → 交叉验收。设计和接口有问题时在同一任务卡记录，不在两份聊天中各自改变规则。

大旺的产品开发包至少包括页面入口／返回、字段含义及校验、按钮前置条件／成功／失败结果、加载／空白／权限／异常状态、设计稿或运行页面、验收步骤。你的接口交付至少包括请求响应、身份与作用域、金额单位、版本、幂等、错误、启动方式和可用合成数据。

功能完成应同时具备：可运行代码、实际接口调用、失败路径、相关测试、文档与验证证据。页面能点击、接口返回200、AI生成代码，均不是单独的完成标准。

## 3. 文件与接口协作边界

| 范围 | 默认维护人 | 协作规则 |
|---|---|---|
| `services/routefit/`、数据库迁移、`integrations/` | 你 | 大旺报告缺口；确需跨界改动先在任务卡列明，避免同时编辑 |
| `contracts/openapi.json`、接口说明与校验样例 | 你 | 大旺提出字段需求；目录／字段由脚本生成，不手改生成文件 |
| `prototype/`前端、设计资产与前端测试 | 大旺 | 你维护本轮约定的本地服务接入文件；共享入口文件排队修改 |
| PRD产品／UX文档 | 大旺 | 你确认技术及业务约束；正式PRD／RULE／AT变更单独处理 |
| 任务卡、验收记录 | 双方 | 每张卡有一名主负责人；写明基线、依赖、结果与待办 |

不同任务使用独立分支／worktree，不在同一工作目录同时运行两个写代码的Codex。共享文件如 `prototype/app.mjs`、`prototype/server.mjs`、全局CSS和机器契约，先登记本卡修改范围，按顺序整合；不要靠互相覆盖解决冲突。
