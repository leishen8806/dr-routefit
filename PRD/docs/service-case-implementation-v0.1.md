# 确认订单变更申请实施说明

v0.1 草案 · 2026-10-25。基于 V1.4 及既有财务纠错边界，不修改正式 PRD、RULE 或 AT 编号。

本轮实现的是闭环的第一道门：客户提交变更/异常申请，运营由不同自然人独立受理，系统保留原订单、已确认报价、收款与核销事实。地址、时间申请仅在未执行的 `quoted` 订单上受理；创建或受理都不直接变更路线、承诺、金额、签收责任或资金状态。

实现包含008迁移的只追加案件与决定记录、企业/客户RLS、版本与幂等、跨租户404、独立受理触发器和五个本机接口。009迁移将候选重报价与已受理案件、原报价建立不可改引用；010迁移在候选报价确认时冻结原收款、有效核销、未分配额与待补款/待处理贷项。复用报价接口的 `serviceCaseId`，重新核验候选地址/时间并返回价差，但不替换订单当前报价。真实PostgreSQL测试覆盖申请重放、跨租户读取拒绝、同人受理拒绝、独立决定、候选报价重复阻断、非零价差及原收款位置快照，以及订单版本/状态和原付款准入保持不变。

011迁移新增原确认报价费用项的只读应收台账，`allocatedMinor` 与 `outstandingMinor` 依据仍有效的POSTED核销读取时重算；整笔核销撤销后相应未结额恢复。它让财务可核对原收款已覆盖哪一费用项，但不创建候选价差账项，也不改变候选报价冻结的位置。

012迁移已先建立候选价差调整单、审核事件和候选账项的持久化边界：企业＋订单＋报价复合外键、RLS、不可改历史及提交／复核／审批的三人顺序由数据库保证。候选报价未确认时不能入账；此基础尚未对外开放 `FinanceDocument` 路由，也不产生应收／贷项或切换订单。

下一批的范围仍是：客户确认候选报价后，由独立财务动作创建价差应收/贷项，并把原已核验收款及有效核销映射到新旧应收。只有该映射、独立审批和客户同意都完成后，才允许切换订单当前报价和承诺。任何退款、银行更正、自动改价或已执行订单变更继续阻断，直到有单独的事实、审批和验收链。
