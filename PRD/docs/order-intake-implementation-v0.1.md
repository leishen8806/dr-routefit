# 订单受理输入切片

v0.1 草案，2026-10-25。与正式 PRD 冲突时以 PRD 为准；不改正文、RULE、AT。依据 PRD V1.4 的 draft→validating、地址确认、尺寸来源及区域准入要求。

## 本轮交付

订单草稿 → 人工登记取送入口与货物尺寸来源 → 当前区域检查 → 提交核验 → 有原因退回 → 重新登记并提交。保留版本、来源、登记身份、当时区域与退回原因；失败不写状态。validating 表示核验中，不是报价已接受或可以派单。

新增 8 个实际操作，其中 4 个复用既有设计接口、4 个补足登记／只读检查／退回／区域停用；完整契约 219 操作，25 本机实现，194 仅设计。技术栈仍为开发切片，D24 不因代码存在而自动批准。

## 数据与一致性

- 004 增量创建 coverage.area 当前投影、coverage.publication 只追加发布历史、orders.intake_evidence 只追加人工依据、orders.intake_return 只追加退回原因。
- orders.draft 增加来源依据、来源订单版本和区域 revision 外键；数据库检查 validating 必须有对应快照引用，draft 不携带旧受理引用。原订单 revision 继续只追加。
- 客户授权、企业 RLS 和幂等响应权限检查沿用原实现；区域发布与提交使用同一企业锁，订单变更使用行锁和 If-Match。
- 整数金额、保险排除、独立价格审核未改；受理不产生任何资金事实。
