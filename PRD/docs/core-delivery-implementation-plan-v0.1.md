## 1 本轮最终可演示结果

同一笔订单从录单/导入开始，费用只计算一次并保存确认版本；发货人付款经财务核验或使用有效月结资格后，调度选择合规运力，司机接单、取货、打开下一站导航、签收，最后财务与司机应付可核对。用户端、司机端、工作台和中控读取同一订单事件及状态，不再以另造一笔演示订单完成跨端跳转。

本轮普通自营配送先通过；付费独享沿用既有规则。先用合成数据及人工核验，不购买地图/支付服务，不借此冻结后端技术栈。R2/R3真实推荐和合单仍按原阶段，不能为了展示降本先解除独占任务约束。

## 2 先解决旧 Demo 的不一致

- 旧展示页默认为到达收现金，新要求是预付或获批月结。必须改入口和派单检查，不能只换文案。
- 旧展示与工作台数据隔离。先统一订单访问和动作处理，再补导航按钮；中控及财务不另存一份状态。
- 旧 B 全退全免只保留为注明政策假设的历史测试场景，不作为新订单默认政策。新主线异常转人工裁定，已收款不能被减免按钮直接删除。
- 历史会话读入时标记结算模式待核实；不能自动将“现金待收”迁移为“已预付”或“已批准月结”。提供保留旧场景查看和明确确认的新场景入口，避免静默清空。

## 3 任务顺序与通过条件

### P01 统一订单和报价快照

2026-10-25进度：订单录入子集已本地实现，见[接口说明](../../contracts/orders-api.md)。同源会话和真实PG支持客户授权、草稿及编辑历史；独立`orders.html`已完成录入／编辑／冲突／重试的浏览器验证，见[全项目交付记录](project-delivery-depth-v0.1.md)。固定费策略审核发布子集已实现；订单受理校验、正式报价生成／确认及共享工作台和其他端接线未完成，P01整体仍未验收。

依赖：无；先于所有其他卡。

- 涉及入口：录单、外部订单校对、报价确认、订单详情、展示页、费用设置。
- 同一报价包含币种、基础费、超距计费米数/单价/取整规则、独享费、保费、总应收、配送分成口径、规则版本与有效期；基础保障不另加一项收费。
- 前端预览与确认使用同一计价逻辑；导入已有配送价格时明确是总配送报价还是基础费，不能默认再加一次超距费。来源不清时留待核价。
- 修改地址、仓库、货物或服务类型触发重核价，确认报价不直接覆盖；明确未付、已付需补差/退款待处理，不自动重复扣全额。
- 完成：工作台、客户、司机与展示页金额一致，来源单到内部单可追溯；重复导入不生成重复应收；价格边界和分成尾差测试通过。

### P02 付款与月结派单守卫

依赖：P01。

- 涉及入口：客户付款状态、财务核验队列、月结客户资料、调度待派列表、司机提案。
- 分离付款方、结算方式和收款状态。预付必须有与有效报价匹配的已核验资金；付款截图仅待核验。报价/付款/信用资格在提案提交和接受时按适用规则复验。
- 月结检查企业/客户关联、批准状态、有效期及已配置的额度规则；没有额度设置不发明默认信用额度。派单后形成月结应收，不能显示已到账。
- 提案发出后付款被更正或资格失效，不得继续凭旧页面接新任务；已实际持货时转调度异常处理，不能直接删除任务或消失保管责任。
- 完成：未付、少付、币种不符、未核验、资格无效与过期报价不能派单；合格预付/月结可走通；重复核验不重复到账。

### P03 合格车辆与路线成本比较

依赖：P01/P02。

- 涉及入口：调度地图、待派列表、车辆详情、候选方案与确认弹窗。
- 先过滤资格、区域、班次、独占任务、车型、装载及时间窗；每个排除项可读。当前车距、ETA和成本明确标来源与时效。
- 比较同一任务的接货空驶、送达路线、必要返程、作业耗时与承运成本；未知成本不按0排序。选择费用低但不满足时窗的车必须被拒绝。
- 首轮候选采用可重放合成矩阵或人工核验，不称真实智能最优；保持调度确认和司机接受。地图服务后续接入时按授权及配额规则替换数据源。
- 完成：最近但已满、最便宜但超时、门洞不符、位置失效、候选被其他任务占用、司机拒绝等均有正确出口；提交旧版本方案不覆盖新任务。

### P04 司机执行与逐站导航

依赖：P03。

- 涉及入口：司机任务、订单列表、到仓点收、下一站导航、签收。
- 当前站显示取/送事项、准确入口、联系人及确认过的时间窗；打开外部地图只传当前授权目的地。未提供可靠坐标时不造演示坐标导航到现实地点，给地址核对/复制入口。
- 仓库放行、点收、出发、实收签收均由明确动作推进；导航打开、回到APP、进入地理围栏不自动完成签收。
- 预付与月结订单明确显示无需现场收取本次已覆盖配送费，不再要求输入同一笔全额现金。若存在经确认的额外应收，单独展示，不在本轮自动生成。
- 完成：安全滑动/替代确认、取消不生效、重复操作不多记、刷新保留、导航返回保留任务状态；离线接单禁用、离线凭证补传冲突可解释。

### P05 财务与司机应付收口

局部交付更新：按主体账期及提醒已以独立工作台切片接入共享原型数据，见[结算验证](../../prototype/records/2026-10-24-settlement/README.md)。该交付不表示 P01–P04 已完成，也不将客户预付/月结准入、P05 全部资金核验或 P06 生产发布标为通过。

依赖：P01/P02/P04。

结算补充见[合作单位／个人结算与资金管理](partner-settlement-and-funds-v0.1.md)。本卡先记录收款主体、应付、协议版本、到期日和人工支付核验；批量账单及资金日历在 F03/F05 复用。个人周结／企业月结仍为建议，不自动启用。月结客户未回款不抹除合作方到期应付；资金余额不等于平台可支配利润。

新增已确认要求：各客户／合作单位／个人可单独配置账期，分开截账、出账、收付到期及提醒时间。P05 记录有效规则和到期信息，F03/F05/F08 完成待出账、收款／催收和付款任务闭环；内部自动提醒、对外财务确认发送。账期设置不授予月结资格，已核销不再催收，规则修改不覆盖历史到期日；详见专项 §3.1–3.2。

- 涉及入口：财务订单账、收款核验、月结应收、司机收入、中控财务摘要。
- 客户应收、已核收、待核、月结未收、保费、司机应付和成本分别显示。银行预付不产生司机现金交款；实际由司机保管的现金才进入交款核对。
- 原订单分成约定保留；保险不参与。月结履约完成与客户到账分离，司机收入何时可提使用明确策略，未配置时保持待确认，不擅自判定可提现。
- 客户退款与司机收入独立裁定；本轮提供待处理入口和账项引用，不扩展自动退款、自动扣司机款或自动银行付款。
- 完成：每笔已核收只核销一次，配送分成与保费相加可核对，签收不等于收款完成，未结事项清晰可见且可追溯。

## 4 固定的基础验算场景

下面仅作为合成回归输入，不是正式费率。USD基础费$10，含10km，实际12.5km，每额外公里$2，实际超距计费；独享附加$3，可选保费$2，演示平台比例20%。

| 检查 | 应有结果 |
|---|---|
| 超距费 | 2.5 × $2 = $5 |
| 配送报价 | $10 + $5 + $3 = $18 |
| 总应收 | $18 + $2 = $20 |
| 演示分成 | 平台$3.60，司机应计$14.40；保费$2独立 |
| 预付$20已核验 | 可进入派单；送达不再收$20，不生成司机交款义务 |
| 仅付$18或付款截图未核验 | 不可按预付合格派单 |
| 获批月结且资格有效 | 可派单；履约结束保留$20应收，不显示已收$20 |
| 已独享配送 | 不参与普通拼单，不因地图候选更便宜改变服务类型 |
| 同一确认请求重放 | 金额、订单、指派、核验各不重复 |

另测基础里程10km以内、10km整、10.001km、最远服务边界、向上取整模式、空费率、超大金额、过期报价及地址改动；不得以一个正常金额算例代表全部计价正确。

## 5 依赖与暂缓项

原型阶段可用合成费率、人工距离、模拟到账和批准月结记录继续推进，不需逐项追问运营细节。真实运行前才必须取得：有效计价/分成规则、财务核验责任与付款渠道、月结批准记录、真实车型/仓库/区域及地图服务授权。没有这些不承诺真实上线。

本轮不做动态调价、自动理赔、自动银行划转、完整WMS替代、途中自动插单或通用3D装箱。它们保留在[F01–F09后续规划](future-closure-plan-v0.1.md)，不能阻塞基础主线，也不能因暂缓而删除已确认需求。
