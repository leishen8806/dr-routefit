## 2. 运行方式：VPS，只通过 SSH 访问

2026-10-28 项目负责人决定：试运营放在一台 VPS 上，只能通过 SSH 登录操作。VPS 的地址只记在负责人那里，不写进本仓库。

服务端目前只监听 `127.0.0.1`，数据库也必须在本机，身份是开发会话；代码注明部署前要换成经批准的身份服务。生产身份要做到能对公网开放，7 天内做不完，所以网页端口不对外开放。员工通过 SSH 隧道访问：

- VPS 上运行 PostgreSQL 和 RouteFit 服务，都只监听 `127.0.0.1`。防火墙只放行 SSH（22 端口），SSH 只允许密钥登录，禁止 root 登录和密码登录。
- **管理员**（项目负责人）用自己的 SSH 密钥登录，可以操作服务器。
- **员工**每人一个受限的 SSH 账号和一把密钥：
  - 不能进入命令行；
  - 只能转发到 `127.0.0.1:4180`；
  - 连接时自动显示本人的一次性登录链接。
- 员工在自己的电脑上运行一条命令建立隧道（Windows 10 及以上自带 SSH，可以做成桌面快捷方式），再在本机浏览器打开链接，访问 `http://127.0.0.1:4180`。服务端看到的请求来自本机，现有的本机限制、来源校验都照常生效。
- 身份每天续期一次（RF-PM-038 `trial:renew`），由管理员在开工时执行。
- 每天开工、收工各备份一次。备份先存在 VPS 上，管理员每天再拉一份到 VPS 以外的加密存储。

这意味着：持有员工 SSH 密钥的人就能使用系统。员工离职或丢失电脑时，管理员当天删除他的密钥。服务器准备与加固见 [RF-OPS-01](../codex/tasks/RF-OPS-01-vps-trial-server.md)。

## 4. 人工环节操作要点

以系统订单号作为线下所有记录的唯一关联键。

- **收款：** 客户确认报价后，财务按系统里的总应收收款（保费单列），在线下台账记录订单号、金额、到账时间、凭证号。到账核实前不派单。
- **派单与执行：** 调度在线下派单，台账记录订单号、司机、派单时间、签收时间。签收凭证按现有方式留存。
- **改址、改时：** 先在系统里申请改单。客户确认候选报价后再通知司机；差额的收退款走线下，台账注明候选报价号。
- **取消：** 在系统里取消订单，线下台账同步标注。
- **每日对账（收工前）：** 系统当天已确认的报价逐笔对线下收款台账：金额不一致或缺记录的，第二天开工前处理完。

## 5. 每日例行

1. **开工（管理员）：** 通过 SSH 登录 VPS：
   1. 运行 `trial:renew` 续期身份，重启服务；
   2. 运行 `trial:start` 检查：数据库、会话剩余时间、开工备份、服务状态；
   3. 把前一天的收工备份拉到站外存储。
2. **开工（员工）：** 双击桌面的隧道快捷方式。窗口里会显示本人的一次性链接，60 秒内在本机浏览器里打开；工作期间不要关闭这个窗口。
3. **工作中：** 发现问题时，只记录订单号和现象。截图前遮挡客户资料，截图不上传仓库。
4. **收工：** 完成每日对账，员工关闭隧道窗口，管理员运行 `trial:backup`。

## 6. 系统故障时回退

服务无法启动、数据库无法连接或页面报错时，当天改为全线下处理，用纸质或表格记录。恢复后**不补录**故障期间的报价，线下单据为准，并在台账中标注“系统故障期间”。不能确定数据是否完好时，从最近一次备份恢复到新库核对，不覆盖原库。

## 9. 试运营不能做的

- 不接超出固定费范围的订单（无超距费）。
- 不提供及时送（S1）。
- 客户不能自己登录系统查看或确认报价。
- 系统不处理收款、派单、司机、地图、KESS 支付。
- 不对公网开放网页：没有域名、没有 HTTPS 网址，只能经 SSH 隧道访问。
