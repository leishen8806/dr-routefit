## 2. 运行方式：单机

服务端目前只接受本机（`127.0.0.1`）请求，身份是开发会话，代码注明部署前必须替换为经批准的身份服务。生产身份与服务器部署属高风险项，7 天内做不完，所以试运营用单机方式：

- 一台专用电脑运行 PostgreSQL 16 和 RouteFit 服务，只在本机访问，不对外开放端口；
- 每位员工在这台电脑上用自己的浏览器配置文件（Chrome 用户），各自取一次性链接登录；
- 身份每天续期一次（RF-PM-038 `trial:renew`），换班时取新链接；
- 每天开工和收工各备份一次，备份放在仓库目录以外的加密磁盘。

这意味着：能碰到这台电脑的人，就能使用系统。试运营期间物理保管这台电脑就是访问控制，所以第 3 节要指定保管人。

## 4. 人工环节操作要点

以系统订单号作为线下所有记录的唯一关联键。

- **收款：** 客户确认报价后，财务按系统里的总应收收款（保费单列），在线下台账记录订单号、金额、到账时间、凭证号。到账核实前不派单。
- **派单与执行：** 调度在线下派单，台账记录订单号、司机、派单时间、签收时间。签收凭证按现有方式留存。
- **改址、改时：** 先在系统里申请改单。客户确认候选报价后再通知司机；差额的收退款走线下，台账注明候选报价号。
- **取消：** 在系统里取消订单，线下台账同步标注。
- **每日对账（收工前）：** 系统当天已确认的报价逐笔对线下收款台账：金额不一致或缺记录的，第二天开工前处理完。

## 5. 每日例行

1. **开工：**
   1. 运行 `npm run trial:start`：检查数据库、检查会话剩余时间、做开工备份、启动服务；
   2. 会话不足 2 小时时先运行 `trial:renew`，再重启服务；
   3. 每人用 `npm run session:link <序号>` 取一次性链接，在自己的浏览器配置文件里打开。
2. **工作中：** 发现问题时，只记录订单号和现象。截图前遮挡客户资料，截图不上传仓库。
3. **收工：** 完成每日对账，运行 `trial:backup`，然后锁屏。

## 6. 系统故障时回退

服务无法启动、数据库无法连接或页面报错时，当天改为全线下处理，用纸质或表格记录。恢复后**不补录**故障期间的报价，线下单据为准，并在台账中标注“系统故障期间”。不能确定数据是否完好时，从最近一次备份恢复到新库核对，不覆盖原库。

## 9. 试运营不能做的

- 不接超出固定费范围的订单（无超距费）。
- 不提供及时送（S1）。
- 客户不能自己登录系统查看或确认报价。
- 系统不处理收款、派单、司机、地图、KESS 支付。
- 不能在试运营电脑以外访问系统。
