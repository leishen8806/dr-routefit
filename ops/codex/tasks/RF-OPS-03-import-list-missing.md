## 背景

2026-11-07 v0.3.1 部署后核对时，已审查的逐员授权核对脚本在前置检查阶段失败：11-03 正式客户导入时保存在 root 专用目录中的客户名单文件**不存在**，权限核对也 FAIL。那一项改用只读等价查询完成（不匹配 0），部署不受影响。

需要查清名单是被清理了、被移走了，还是从未按约定保存。这关系到：

- 以后核对"正式客户"时还能不能用名单作参照；
- 正式客户资料是否在服务器上残留在别的位置（隐私与最小留存）；
- 恢复演练是否依赖这份名单。

## 要做（全部只读）

1. 只读确认：名单原定目录是否存在、目录的属主属组权限；目录内文件数（只输出数量）。
2. 只读查找：root 专用配置目录和备份相关目录下，是否有同名或相似名称的客户名单文件（只输出数量和修改时间，不输出路径和内容）。
3. 对照 11-03 当天的操作记录和 RF-OPS-01 的清理步骤，确认有没有任何已执行的步骤会删除或移走该文件。
4. 结论三选一：已按流程清理 / 被移到其他位置 / 原因不明。

## 不做

- 不恢复、不复制、不删除任何文件，不改权限；
- 不在任何输出、证据或聊天里出现客户名称、文件内容或真实路径。

## 后续（按结论另行决定）

- 如果名单已按流程清理：把逐员授权核对改为不依赖名单的只读等价查询（11-07 已验证），并入 RF-PM-052；
- 如果在其他位置找到：由负责人决定是否收回到 root-only 600，或按最小留存原则删除；
- 如果原因不明：补充文件留存的约定，写进 RF-OPS-01。
