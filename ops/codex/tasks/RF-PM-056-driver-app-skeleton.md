## 背景

PRD 要求司机使用 iOS/Android 原生 App，网页或 PWA 不算交付。后端已有 `/api/driver/v1` 契约与 19 个操作，但正式登录仍处于 RF-PM-055 设计阶段。先固定可审查的技术方向和最小骨架，避免在认证、签名、后台定位尚未批准时扩大实现。

## 要做

1. 比较 React Native（Expo）、Flutter、Kotlin + Swift 原生，覆盖后台定位、离线队列、证据、推送、导航、签名分发、TypeScript 复用和两人维护成本。
2. 在 `apps/driver/` 建推荐方案的最小工程：
   - 本机开发会话占位，API 固定为 loopback，认证封装可替换；
   - 读取并显示 `GET /api/driver/v1/assignments`；
   - 离线事件队列：连续序号、`eventId` 去重、断网重放单测；
   - Android/iOS 模拟器运行说明，未运行的平台明确 NOT_RUN。
3. CI 的 `driver-app` 任务执行 lint、类型检查、单元测试与 Android export 构建检查，六项 CI 全绿。

## 不做

- 不实现 RF-PM-055 正式登录、刷新令牌、设备绑定或生产服务地址；
- 不连接 `/sync/events` 真实上报，不实现持久化队列；
- 不实现后台定位、相机、证据上传、推送、内嵌导航；
- 不申请应用商店账号，不生成证书、签名密钥或分发包；
- 不改后端、迁移、`openapi.json`，不连接试运营服务器，不部署。

## 验收

- 选型文档完整比较三种方案，明确推荐、反对理由、反转条件与最小真机实验；
- App 只能连接本机开发服务，任务列表使用真实司机接口；
- 离线队列四项单测通过（含嵌套对象字段顺序稳定去重），测试不调用服务器；
- `driver-app` 的 lint、类型检查、单测与 Android export 构建检查通过，CI 六项全绿；
- Android API 30 模拟器连接本机开发服务、使用合成司机身份运行通过，任务列表显示正常空状态；脱敏截图位于仓库外 `E:\RouteFit-QA\evidence\RF-PM-056\android-empty-list.png`；
- 草稿 PR 描述按“选型文档 / 骨架 / 测试 / CI”写 PASS／FAIL／NOT_RUN；
- Android/iOS 真机、签名、商店、后台权限均不得用静态或模拟证据冒充通过。
