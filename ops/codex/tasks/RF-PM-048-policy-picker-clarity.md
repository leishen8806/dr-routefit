## 背景

2026-11-03 部署核对发现：

- 生成报价时，员工在订单页从"已发布策略"下拉框选一条，系统按所选策略 ID 报价，**不会自动选最新**，也不会让旧策略失效（`services/routefit/adapters/policy.mjs`）；
- 下拉框每项的文字只有 `v{版本} · 有效期 · 策略 ID 前 8 位`（`prototype/orders-ui-rules.mjs` 的 `policyOptionLabel`），其中版本号写死为 3，不提供任何信息；列表接口也没有返回提交依据（`reason`）；
- 当前试运营服务器上唯一生效的策略是合成测试策略（有效期至 2026-11-10 23:59，UTC+7），真实策略发布后，如果有效期重叠，员工无法在页面上分辨哪一条是正式的。

目前靠"真实策略晚于合成策略到期再生效"来规避，这是隐性约定，不应长期依赖。

## 要做

1. **接口：** `GET /api/ops/v1/pricing/policy-versions` 的每一项增加只读字段，让页面能区分策略：
   - `tariffName`（费率草稿名称）和 `reason`（提交依据，取前 80 个字符，不含个人信息）；
   - 发布人、复核人、编制人只返回各自的角色名称和时间，不返回身份标识；
   - `contracts/openapi.json` 和策略相关契约文档同步。
2. **页面：**
   - 下拉框每项显示：费率名称、提交依据摘要、有效期（UTC+7 显示）、策略 ID 前 8 位；去掉写死的 `v3`；
   - 选中后，在"生成报价"按钮旁边只读显示该策略的完整有效期、提交依据、发布时间；
   - 列表中同时存在多条当前有效策略时，在下拉框上方给出一行提示："当前有 n 条有效策略，请核对后选择"；
   - 手填 ID 路径保持可用，但选中后同样显示上述信息；
   - 订单页长时间不刷新时，下拉选项可能在 `validUntil` 过后仍显示（11-03 只读核对：生成报价前页面和服务端都会再次拒绝过期策略，所以不会成功报价）。本卡要求在最早一条选项的 `validUntil` 到达后自动重新读取列表，或至少在选项过期后将其标灰并注明"已过期"。
3. **测试：**
   - 集成测试：列表项包含新增字段；字段值不含身份标识；两条重叠有效期的策略在列表里可被区分；
   - 单元测试：标签生成、重叠提示；
   - 浏览器验收脚本：两条重叠策略并存时，页面上能分辨，选错能被发现；连跑 3 次，输出 JSON 放进 `services/routefit/verification/rf048/`；不接入现有 CI。
4. **文档：** `ops/trial/员工使用说明.md` 写明：生成报价前核对策略名称、有效期和提交依据；有疑问不要生成。

## 不做

- 不新增策略撤销或替代机制（RF-PM-049）；
- 不改变报价计算和策略有效期规则；
- 不新增距离计价（RF-PM-032）。

## 验收

- 合并后由项目负责人的 Codex 在试运营环境只读复验下拉框显示。
