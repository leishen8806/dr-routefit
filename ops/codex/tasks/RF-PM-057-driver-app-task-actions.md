## 背景

RF-PM-056 的骨架只能用本机开发会话读取任务列表。正式登录（RF-PM-055）的批次 0 要等负责人定下身份提供方和司机登录方式，在那之前，司机 App 可以先把不依赖正式登录的任务流程做出来，接口层保留替换位置。

本卡是 RF-PM-056 选型文档里的批次 B：任务查看与接单／拒单。出发、定位、离线补传、拍照取证、交付记录、推送和导航返回涉及敏感权限或真机验证，放在之后的高风险批次。

## 要做

1. **任务详情：** 从任务列表进入详情，调用 `GET /api/driver/v1/assignments/{assignmentId}`，显示状态、到期时间、路线版本；只读。
2. **必要订单资料：** 详情页调用 `GET /api/driver/v1/orders/{orderId}`，只显示契约返回的字段（取送地址、联系人、件数等），不在本地另存。404 统一显示“任务不存在或已不属于你”，不区分原因。
3. **接单／拒单：** 调用 `POST .../actions/accept` 与 `POST .../actions/reject`：
   - 每次操作生成新的 `Idempotency-Key`，网络重试复用同一个键；
   - `If-Match` 使用详情返回的版本；412／409 时提示“任务已变化”，自动重新读取详情，不自动重试写操作；
   - 拒单需要二次确认；接单成功后刷新列表和详情；
   - 按钮在请求进行中禁用，防止连点。
4. **开发会话写操作占位：** 本机开发认证要求写操作带精确 Origin 和 `X-CSRF-Token`。在 `src/development-auth.ts` 中扩展占位：启动时同时输入开发会话令牌和 CSRF 令牌（都只存进程内存），写请求附带 `Origin: http://127.0.0.1:4180` 与 `X-CSRF-Token`。
   - 只在本机开发占位中这样做，代码和 README 都标明“RF-PM-055 批次 5 正式会话上线后删除”；
   - 不修改后端认证代码。
5. **外部导航跳转：** 详情页“导航”按钮用系统地图链接打开目的地（Android 用 `geo:` 或 Google Maps 链接，iOS 用 Apple Maps 链接）；从地图返回 App 后**不得**自动改变任何任务状态。
6. **语言：** 请求带契约中的 `Language` 参数；界面文案集中在一个文件里，先提供中文和英文，高棉语留占位（文案待负责人提供），不硬编码在组件里。
7. **测试：**
   - 单元测试：幂等键生成与复用、`If-Match` 取值、412／409 处理、404 文案统一、拒单二次确认；
   - Android 模拟器实际跑通：本机开发服务＋合成司机身份＋合成派单，完成“列表 → 详情 → 接单”和“列表 → 详情 → 拒单”各一次，并确认重复点击只产生一次接受。结果写进 PR，截图不得含令牌；
   - iOS 可写 NOT_RUN（Windows 无模拟器）。

## 不做

- 不做出发、位置上报、离线事件补传、证据上传、交付记录、收入与提现；
- 不申请定位、相机、通知权限；
- 不做正式登录、刷新令牌或设备注册（属于 RF-PM-055 批次 5）；
- 不改后端代码、迁移、`openapi.json`；
- 不申请应用商店账号、签名证书，不做分发。

## 验收

- CI 六项全绿（`driver-app` 含 lint、类型检查、单元测试、Android 构建检查）；
- Android 模拟器两条路径实测 PASS，或写明 NOT_RUN 原因；
- 写操作在 412／409／404 下的表现与上面第 3 条一致；
- 代码中没有令牌、CSRF、真实地址或真实客户资料；开发占位的删除条件写在代码注释和 README；
- PR 描述按“要做”逐项写 PASS／FAIL／NOT_RUN，范围外发现写进“发现但未处理”。
