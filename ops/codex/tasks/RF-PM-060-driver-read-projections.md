## 背景

RF-PM-058 实现时发现，司机 App 无法安全完成交接签认和出发，原因在后端：

1. 司机端没有读取“待我签认的交接”的接口。`driverConfirmTransfer` 需要交接 ID 和版本，但司机拿不到；
2. 司机端看不到“全部件是否已由我保管、装载复核是否放行”。出发按钮只能盲按，再靠服务端拒绝；
3. 本机开发夹具里没有受控设备和有效当班，`/sync/events` 和 `/locations` 在本机无法验证。另外，仓库里目前没有任何创建设备或开始当班的接口。

## 要做

1. **待签交接列表（只读）：** 新增 `GET /api/driver/v1/assignments/{assignmentId}/custody-transfers`：
   - 只返回当前司机本人、该指派订单下、状态为待司机签认的交接；
   - 每条包含交接 ID、版本（ETag 语义与现有接口一致）、状态、逐件 `itemId`／`packageIds`、发起时间；
   - 非本人或不存在统一返回 404；不返回运营内部字段和其他司机的数据。
2. **出发就绪（只读）：** 新增 `GET /api/driver/v1/assignments/{assignmentId}/departure-readiness`：
   - 返回 `ready`（布尔值）和未满足条件的原因代码列表，至少包括“装载复核未放行”“有件尚未由本人保管”“指派状态不允许”；
   - 判断逻辑必须复用 `driverDepart` 现有的校验，不能另写一套。PR 里要说明复用方式，并用测试证明两者结论一致。
3. **契约与文档：** 更新 `openapi.json`、`contracts/driver-api.md`、`contracts/endpoint-catalog.md`；新接口的权限沿用 `driver:tasks:read`。
4. **开发夹具：** 在本机开发夹具中，为合成司机增加一台 `ACTIVE` 设备和一个覆盖当前时间的有效当班，只用于本机开发和测试，不进入试运营初始化脚本。
5. **当班管理缺口（只写设计，不实现）：** 在 `PRD/docs/` 新增一页短设计，说明设备由谁注册（与 RF-PM-055 批次 5 的设备会话怎么衔接）、当班由谁开始和结束（司机上班打卡，还是调度排班）、需要哪些接口，列出待负责人决定的事项。
6. **测试：** 真实 PostgreSQL 集成测试覆盖：本人可读、他人 404、跨企业 404；就绪判断和 `driverDepart` 的结论在“未放行／未全部保管／全部满足”三种情况下一致；夹具设备和当班能让一次合成 `/sync/events` 补传返回 `APPLIED`。

## 不做

- 不改任何写接口的校验规则；
- 不新增设备注册或当班开始／结束的写接口（只做第 5 条的设计）；
- 不改试运营初始化脚本，不碰试运营服务器；
- 不改司机 App（RF-PM-058 返工另行处理）。
