## 背景

2026-11-07 v0.3.1 部署后的开工检查，使用的是负责人本机 QA 目录中的一份私有脚本（不在仓库内）。部署中暴露三个问题：

1. **最新备份写死。** 脚本把"最新备份"的文件名和哈希写成 11-03 的固定值。11-07 部署后它报 `LATEST_BACKUP=PASS`，实际核对的是 11-03 的旧备份，部署后新备份只能另行核对。
2. **隐式依赖 `SSH_CONNECTION`。** 隧道账号限制检查读取 `SSH_CONNECTION`，脚本启用了 `set -u`；通过 `sudo -n bash -s` 执行时 sudo 会清空该变量，脚本在第 18 项之后以退出码 1 中止，报错只有"缺少必要变量"。最终用 `sudo -n --preserve-env=SSH_CONNECTION bash -s` 才通过。
3. **期望数量写死。** 正式客户数、区域数、历史测试订单数等期望值都是脚本里的常量，数据正常变化就会误报 FAIL。

## 要做

1. 在仓库新增只读开工检查脚本，建议放在 `ops/trial/`，名称由执行人提出。仓库内不得出现真实地址、端口、账号、口令、哈希或真实客户数据。
2. **最新备份：** 自动选取备份目录中最新的 `.dump`，要求同名 `.sha256` 存在、`sha256sum -c` 通过、文件非空、距今小于 24 小时、属主属组权限符合 RF-OPS-01。输出所选文件的时间（UTC+7）和 PASS/FAIL，不输出哈希。
3. **SSH 连接依赖：** 脚本开头检查 `SSH_CONNECTION`，缺失时立即以明确的信息退出（例如 `SSH_CONNECTION_REQUIRED=FAIL：请以 sudo -n --preserve-env=SSH_CONNECTION bash -s 执行`），不要在中途因 `set -u` 中止。
4. **期望值参数化：** 正式客户数、活动区域数等期望值从 root-only 的参数文件或命令行参数读取，不写死在脚本里；参数缺失时直接 FAIL，不使用默认值。
5. 每一项输出 `名称=PASS/FAIL`，最后一行 `FINAL_OPEN_CHECK=PASS/FAIL`；任何一项失败都以非零码退出，并输出失败项名称。
6. 文档：在 [RF-OPS-01](RF-OPS-01-vps-trial-server.md) 和 `ops/trial/manual-ops-guide.md` 写明标准调用方式（PowerShell 示例，见 RF-PM-054）。

## 不做

- 不改服务代码、不改数据库、不改 sudoers 或 sshd 配置；
- 不把负责人本机的私有脚本原样提交（其中有真实路径和哈希）。

## 验收

- 单元测试或脚本测试至少覆盖：缺少 `SSH_CONNECTION` 时明确失败；最新备份选择正确（多份备份中选最新的一份）；`.sha256` 缺失或校验失败时 FAIL；期望值参数缺失时 FAIL；
- 在一次性合成环境中跑通全量 PASS，并演示一条 FAIL 路径；
- CI 五项全绿；PR 描述逐项写 PASS / FAIL / NOT_RUN；
- 真实试运营服务器上的首次运行由负责人另行执行，不在本卡内执行。
