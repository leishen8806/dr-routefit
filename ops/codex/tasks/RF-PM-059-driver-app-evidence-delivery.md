## 背景

送达时司机要拍照留证，再按件提交交付结果：全部送达，或部分送达、其余待退回。后端接口已有：`driverUpload`、`driverCompleteUpload`、`driverDelivery`（见 `contracts/driver-api.md`、`contracts/evidence-api.md`）。交付记录是只追加的事实，提交后不能改，所以 App 必须在提交前让司机逐件确认。

## 要做

1. **相机权限：** 只在司机点“拍照”时申请相机权限；拒绝授权时给出说明和去系统设置的入口，不反复弹窗。不申请相册、定位等其他权限。
2. **拍照与上传：**
   - 拍照后在本地压缩到契约允许的大小和格式（以 `evidence-api.md` 的 MIME、大小限制为准），计算 SHA-256；
   - 按“创建上传 → 上传文件 → 完成上传”三步走，用途为 `DELIVERY`；
   - 上传失败可重试，同一张照片重试不重复创建证据；
   - 照片只存 App 私有目录，上传完成后删除本地副本；不写入系统相册。
3. **交付记录：**
   - 按件列出订单全部件，司机逐件选择“已交付”或“待退回”，不能只填数量；
   - 提交前显示汇总并二次确认；提交调用 `POST /api/driver/v1/orders/{orderId}/delivery-records`，带幂等键；
   - 全部交付显示“已送达”，有剩余件显示“部分送达，剩余待退回”，不显示成整单完成；
   - 服务端拒绝时（收货授权失效、证据不符合用途、件不完整等）按错误代码显示原因。
4. **离线：** 本卡的上传和交付记录要求在线；离线时按钮禁用并提示“需要联网”，不进离线队列（契约要求的独立证据流程留给后续）。
5. **RF-PM-058／063 遗留（一并做）：**
   - 开发版专用调试入口“写合成到达事件”：只在开发构建（`__DEV__`）显示，写入一条合成观测点的 `ARRIVED` 事件进离线队列；正式构建不得出现；
   - 按钮禁用时在按钮旁说明缺什么（例如“请先填写说明和证据”“需要联网”），交接、出发、交付都要有；
   - 所有接口请求加超时（`AbortController`，15 秒）；补传超时按临时错误退避，在线写操作超时提示“网络超时，请重试”，不自动重试写操作；
   - 接单页显示派单剩余时间（来自 `expiresAt`）；过期后“接单”按钮禁用，提示“派单已过期，请等待调度重新派单”；
   - 交接和出发目前手填证据文件 ID：若契约允许司机上传对应用途的证据，改为拍照上传；不允许就保留手填，写进“发现但未处理”。
6. **演示数据：** 在 `scripts/driver-scenario.mjs` 增加 `--stage delivery-ready`（已出发、并已由运营创建收货授权），仍只走业务接口；同步更新集成测试和 README。
7. **测试：**
   - 单元测试：压缩后大小与格式校验、SHA-256、上传重试不重复、件级选择完整性、二次确认、请求超时；
   - Android 模拟器实测（模拟器相机可用，数据用 `npm run scenario:driver`）：`delivery-ready` 拍照 → 上传 → 全部交付；另造一单部分交付；拒绝相机权限后的提示；
   - 回归（补 RF-PM-062 批次 2）：`offered` 列表 → 详情 → 接单（先打开 App 停在列表，再造数据，2 分钟内完成）；`custody-pending` 交接签认 → 出发；
   - 离线链路（补 RF-PM-058）：调试入口写合成到达事件 → 杀进程 → 重开仍在 → 补传 APPLIED；
   - 真机相机、iOS 可写 NOT_RUN 并说明原因。

## 不做

- 收货人验证码或签名采集流程的新设计（以现有契约为准，缺什么写进“发现但未处理”）；
- 现金／COD 申报、退回入库；
- 位置上报、后台定位、推送；
- 修改后端业务代码、迁移、`openapi.json`（第 6 条演示脚本除外）；正式登录、商店账号、签名。

## 验收

- CI 八项全绿；
- 模拟器实测路径全部 PASS，或逐项写明 NOT_RUN 原因；
- 本地不残留已上传照片，照片不进系统相册；
- 正式构建中不出现调试入口；
- 合并后看板把 RF-PM-058 标为 DONE（离线链路由本卡补齐）；
- PR 描述按“要做”逐项写 PASS／FAIL／NOT_RUN，范围外发现写进“发现但未处理”。
