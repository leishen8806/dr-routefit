## 背景

司机接单后，要先在仓库逐件签认交接，再出发；路上网络不稳定，到达、交接等事件要能离线记录、联网后按顺序补传。后端接口已有：`driverConfirmTransfer`、`driverDepart`、`driverSync`（见 `contracts/driver-api.md`、`contracts/custody-transfers-api.md`）。RF-PM-056 的离线队列目前只在内存里，App 一关就丢。

本卡对应 RF-PM-056 选型文档“批次 C”的前半部分；拍照取证与签收交付在 RF-PM-059，后台定位与推送在后续批次 D。

## 要做

1. **交接签认（阻塞，转 RF-PM-060：司机端只读投影与夹具）：** 详情页显示待签认的交接（件级 `itemId`／`packageIds`），司机核对后调用 `POST /api/driver/v1/custody-transfers/{id}/actions/confirm`；按件展示，不能只显示数量。差异由运营端报告，App 只提示“如有差异请联系仓库”，不提供凑数操作。
2. **出发（阻塞，转 RF-PM-060：司机端只读投影与夹具）：** 全部件已由本人保管后才显示“出发”按钮，调用 `POST .../actions/depart`；服务端拒绝时（装载复核未放行、件未全部签认等）按错误代码显示原因，不在本地猜测。
3. **离线事件队列持久化：** 把 RF-PM-056 的内存队列改为本地持久化（推荐 `expo-sqlite`，在 PR 里说明选择理由）：
   - 进程被杀、重启后队列和 `nextSequence` 完整恢复；
   - 本地数据只存补传所需字段，不存令牌、不存完整客户资料；
   - 写入采用事务，崩溃时不会出现半条事件。
4. **补传 `/sync/events`：**
   - 联网后按 `sequence` 顺序补传；`eventId` 永久不变，重传不改内容；
   - 按服务端逐项结果区分“已接收／重复／永久拒收”：已接收和重复出队；永久拒收的事件**移入隔离区**，不再阻塞后续事件，并在界面提示司机“有 N 条记录未被接受，请联系调度”；
   - 临时错误（网络、5xx、429）保留在队首，按退避重试，不丢弃；
   - 本卡只接入契约允许离线记录的事件类型中“到达”这一种，其余类型留给后续卡，接口层留好扩展位置。
   - 后台定位能力上线前隐藏“记录到达”入口；保留离线队列代码，并只用合成观测点做单元测试，不得把订单地址当作司机观测点。
5. **设备与当班（阻塞，转 RF-PM-060：司机端只读投影与夹具）：** 补传要求受控设备和有效当班。若本机开发环境缺少设备或当班的合成数据，先查现有开发夹具（`services/routefit/db/local-fixture.mjs` 等）能否提供；不能提供就在 PR 写 NOT_RUN 和原因，**不得修改后端或夹具**。
6. **测试：**
   - 单元测试：持久化恢复、事务写入、三类服务端结果的处理、隔离区不阻塞、退避重试、`eventId` 重传内容不变；
   - Android 模拟器实测：接单 → 交接签认 → 出发；飞行模式下记录一次“到达”→ 杀掉 App 进程 → 重新打开确认事件仍在 → 关闭飞行模式后补传成功；同一事件重复补传只生效一次；定位能力上线前，“记录到达”链路标记 NOT_RUN；
   - iOS、真机可写 NOT_RUN 并说明原因。

## 不做

- 拍照取证、证据上传、交付记录（RF-PM-059）；
- 位置上报、后台定位、推送（后续批次 D）；
- 离线接单（契约不允许）；
- 修改后端代码、迁移、`openapi.json`、开发夹具；
- 正式登录、商店账号、签名。

## 发现但未处理

- App 重装后本地 `sequence` 会从 1 开始，而服务端保留原设备的 `last_sequence`，补传会持续返回 `SYNC_SEQUENCE_INVALID`。由 RF-PM-055 批次 5 的设备注册处理：分配新设备 ID，或由服务端下发起始序号。

## 验收

- CI 六项全绿；
- 模拟器实测路径全部 PASS，或逐项写明 NOT_RUN 原因；
- 本地数据库中没有令牌和完整客户资料（PR 里说明检查方法）；
- PR 描述按“要做”逐项写 PASS／FAIL／NOT_RUN，范围外发现写进“发现但未处理”。
