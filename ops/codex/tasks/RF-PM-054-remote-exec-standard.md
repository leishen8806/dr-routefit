## 背景

2026-11-06 部署前备份和 11-07 v0.3.1 部署中，有 8 次失败都出在命令的写法或执行方式上，与代码和数据无关：

| 现象 | 原因 |
| --- | --- |
| 命令解析失败 | 文档里的命令带着未替换的 `<NODE24_PATH>` 等占位符，bash 把 `<...>` 当成重定向 |
| 远端退出码 127 | 非交互 SSH 不加载 shell 初始化文件，直接写 `node` 找不到 |
| git 拒绝执行 | 不是以版本库属主身份执行 git，被 git 的属主安全检查拦下 |
| Node 退出码 9 | 以服务账号执行，读不到 root 专用的运行环境文件 |
| 管理角色核验解析失败 | 带单引号的 SQL 经过 PowerShell、ssh、bash 三层引号嵌套后被拆坏 |
| 开工检查缺少变量 | `sudo` 清空了 `SSH_CONNECTION` |
| 开工检查退出码 127 | Windows PowerShell 5.1 向外部程序传参时吞掉内层双引号，含空格的变量值被拆开 |
| 只读断言竞态 | 服务启动后立即检查监听，端口尚未就绪 |

## 要做

在 `ops/trial/manual-ops-guide.md` 新增"远端执行标准写法"一节（RF-OPS-01 命令表里加链接），内容至少包括：

1. **占位符：** 文档里的 `<...>` 必须替换后才能执行；在执行前用一条只读检查确认命令里没有残留的 `<`、`>` 占位符。
2. **Node：** 一律使用 systemd 单元 `ExecStart` 里的绝对路径，以及如何只读查到这个路径。
3. **身份：** git 以版本库属主身份执行；涉及运行环境或数据库的探针以 root 身份执行；禁止用修改 `safe.directory` 来绕过检查。
4. **送脚本的标准方式：** PowerShell 里把脚本放进 here-string，先去掉 `\r`，再用管道送给 `ssh ... 'sudo -n bash -s'`；SQL 放在远端 heredoc（`<<'SQL'`）里。给出一个完整的、只用占位符的示例。
5. **需要保留环境变量时：** 用 `sudo -n --preserve-env=变量名 bash -s`，不在 PowerShell 一侧拼带引号的 `env VAR="..."`；说明 Windows PowerShell 5.1 与 PowerShell 7.3+ 在传参上的差异。
6. **服务刚启动后的断言：** 允许等待不超过 30 秒后只读复核一次，并在证据中注明；不得用重启服务来"修复"断言。
7. **证据规则：** 回复只写 PASS / FAIL、数量、时间、退出码；示例里不得出现真实地址、端口、账号、路径或哈希。

## 不做

- 不改脚本或服务代码；
- 不提交负责人本机的私有部署手册。

## 验收

- 文档中所有示例只用占位符；提供一份可以直接复制的 PowerShell 示例（占位符替换后可执行）；
- 由负责人或大旺在本机 PowerShell 5.1 中用合成环境实际跑通第 4、5 条示例，结果写进 PR（PASS / FAIL / NOT_RUN）；
- CI 五项全绿。
