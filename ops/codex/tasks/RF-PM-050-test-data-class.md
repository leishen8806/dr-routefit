## 背景

2026-11-03 部署核对时，服务器上仍有合成数据：2 个已停用客户、3 个订单、1 个案件、1 个已发布策略、3 个已退役区域。目前区分它们靠文本约定、创建身份和关联关系，没有结构化标记。风险是：报表、统计、报价选择可能混入测试数据，测试策略可能被正式报价误用。

## 要做

1. 设计文档：在客户、服务区域、订单、案件、费率草稿、策略等根记录上增加明确的数据类别（`TEST`／`PRODUCTION`），关联记录继承；
2. 约束：测试策略不得用于生成正式客户的报价，反之亦然；创建订单时校验客户与区域的类别一致；
3. 展示：运营页默认隐藏测试数据，增加"显示测试数据"开关；
4. 迁移：存量数据按已有的约定回填，回填脚本只输出数量，不输出内容；
5. 审计和备份不过滤测试数据，只在业务页面、统计和正式运营报表中排除；
6. 备选方案及不选的理由（例如仅用 `[TEST]` 文本前缀）。

## 不做

不删除任何历史测试数据；不改已有的审计记录。

## 验收

设计文档经负责人侧 Claude 审查并由负责人批准，之后另立实现卡。
