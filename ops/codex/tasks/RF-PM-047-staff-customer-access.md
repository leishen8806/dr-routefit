## 背景

2026-11-03 正式部署中发现：客户访问授权（`customer_access`）只在 `trial:import` 里写入，且只授权给**导入那一刻已存在的启用员工**（`services/routefit/scripts/trial-import.mjs`）。`trial:staff` 不写任何授权。结果：

- 导入之后新增的员工看不到任何客户，下不了单；
- 部署时只能用手工 SQL 补授权，没有文档化、没有断言、没有复核；
- 清理过期员工时也曾遗漏一条对停用客户的授权，开工检查没有覆盖，靠只读核对才发现；
- 导入没有去重，重跑会产生重复客户，所以试运营期间新增客户没有安全路径。

试运营还要接入 4 个真人员工，上面的缺口会再出现。

## 要做

1. **新增员工授权：** 给 `trial:staff`（或同级的独立命令，二选一，在 PR 里说明理由）增加"把当前所有启用客户授权给该员工"的明确步骤。
   - 必须是显式动作，不是静默副作用：命令输出写明授权了多少客户；
   - 只授权启用客户，不授权已停用客户；
   - 对角色没有读取订单权限的员工（如纯策略编制角色）不授权，并说明理由；
   - 重复执行幂等，不产生重复授权。
2. **增量客户导入：** `trial:import` 支持在已有客户基础上追加。
   - 去重键由负责人在评审时确认（建议：企业内客户名称精确匹配；匹配到的客户跳过，不重复创建，输出"跳过 n 条"）；
   - 新增客户授权给**当前所有启用的需要客户范围的员工**；
   - 追加运行不得重复发布服务区域；
   - 不读取、不打印客户内容，输出只写数量。
3. **停用路径：** 提供停用员工和停用客户的命令，停用时同步清理该员工的客户授权和会话，输出只写数量。
4. **开工检查：** 在 `ops/` 的开工检查模板里写入两项断言：
   - 活动员工对停用客户的授权数必须为 0；
   - 每个需要客户范围的活动员工可访问的启用客户数等于启用客户总数。
5. **测试：** 真实 PostgreSQL 集成测试：新增员工后授权数正确；重跑幂等；追加导入去重；停用后授权清零；停用客户不被授权；纯策略角色不被授权；脚本失败时事务回滚。
6. **文档：** `ops/codex/tasks/RF-OPS-01-vps-trial-server.md` 部署清单与 `ops/trial/员工使用说明.md` 同步，写明新员工的开通顺序和核对命令。

## 不做

- 不做客户自助登录（阶段 B）；
- 不改 RLS 策略本身；
- 不读取或展示客户资料内容，不新增导入列（电话、地址仍不导入，另立卡）。

## 验收

- PR 描述按 PASS／FAIL／NOT_RUN 逐项写明，并写明新增命令的权限和审计输出；
