## 背景

PR #35（RF-PM-022）、#36（RF-PM-024）、#37（RF-PM-023）未经审查即合并。Claude 事后对照任务卡审查，结论均为 CHANGES_REQUESTED，逐条记录在三张卡的“审查记录”中。本卡把这些缺口合成一次修复，不重开原卡。

## 要做

### 订单受理（`orders.mjs`，对应 RF-PM-022）

1. 422 INTAKE_BLOCKED 与受理检查阻断项按 `error.fields`／阻断项字段定位：对应输入框加 `aria-invalid` 与字段旁说明，并能从阻断列表跳到字段。
2. 服务等级下拉不再提供及时送 S1（会议 M03：PILOT-0 不启用）。已有 S1 草稿打开时只读显示，并提示改选。
3. 修正坐标沿用：地址或地标改动而经纬度未改时，不得把旧坐标随新地址提交。恢复“地址变化清空坐标”，或在提交前明确要求重新确认经纬度，二选一并写进 PR 描述。

### 报价（`orders.mjs`，对应 RF-PM-023）

4. 报价明细改为可读表格，不再输出 JSON：基础费、超距计费米数／单价／取整方式、独享费、保费（单列，并注明不计入配送分成，会议 M05）、总应收、币种、规则版本与策略版本、创建与到期时间、来源订单快照摘要。金额按币种格式化（USD 两位小数），不显示“最小货币单位”。
5. 生成报价与记录确认的响应带 `Idempotency-Replayed` 时，必须重新 `GET /quotes/{id}` 再展示和判断能否确认（契约要求）。
6. 确认时间必填，不再静默取当前时间。

### 费率策略（`fee-api-ui.mjs`，对应 RF-PM-024）

7. 复核、发布说明改为页面内必填文本框，去掉 `window.prompt` 和写死的 `Synthetic independent policy decision` 默认值。

## 不做

不改服务端接口、迁移与计价规则；不新增策略列表接口（契约没有，维持按 ID 读取）；不做改单重核价（RF-PM-025）、付款与派单。

## 验收

- 单元测试（`node --test prototype/*.test.mjs` 能跑到）：
  - 受理：依据登记请求体、阻断项到字段映射、412 与 422 处理、退回原因必填、S1 不在可选项、地址改动后坐标处理。
  - 报价：明细渲染（含保费单列）、issued／expired／superseded 与 unusableReasons、错误码映射、确认请求体、重放后重新 GET。
  - 策略：412 与 INDEPENDENT_REVIEW_REQUIRED 的提示、说明为空时不发请求。
- 用实施计划 §4 固定场景核对页面金额：基础 $10、超距 $5、独享 $3、配送报价 $18、保费 $2、总应收 $20；页面显示值与服务端报价逐项一致。
- 浏览器脚本（合成数据，真实 Chromium），全部经页面操作而不是直接 fetch 判定结果：
  - 区域外订单受理被阻断，能看到原因并定位到字段；
  - 过期报价与被替代报价都不能确认；
  - 同一人复核被拒、复核人发布被拒，各自截图。
- CI 三项通过。
