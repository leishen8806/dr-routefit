## 背景

2026-10-28 项目负责人把 7 天目标定为**受控试运营**：P01 订单受理、报价与客户确认上系统，收款、派单、司机执行走人工流程（见 [P01 受控试运营方案](../../trial/p01-controlled-trial-plan.md)）。

试运营前订单页还有三处问题：

- 两处是 #41 的同步合并 `6d8b02b` 覆盖了 #45（提交 `a2b7128`）造成的回归，RF-PM-033 卡没有列入；
- 一处来自 #52 的审查。

另外，策略列表接口（RF-PM-034，#55）合并后，报价页可以改为从列表选择策略，不再要求运营人员粘贴策略 ID。这是 v0.3.0 发布说明已知限制第 4 项。

## 要做

### A 修复 #41 合并造成的回归

1. **订单页不再提供及时送（S1）。** `selectableServiceLevels`（`prototype/orders-ui-rules.mjs`）已有单元测试，但订单页没有调用，S1 又回到了服务等级下拉框，违反 M03。
   - 下拉框只用 `selectableServiceLevels` 的结果。
   - 已存为 S1 的历史草稿打开时，显示只读提示“PILOT-0 不启用及时送，请改为 S2 或 S3”，不能静默改值。
   - 受理浏览器脚本加一项检查：新建订单的服务等级下拉框里没有 S1。RF-QA-02 第 5 步“页面无及时送选项”按这一项核对。
2. **报价命令重放后重新读取报价。** #45 在“生成报价”“记录客户确认”两处处理了 `Idempotency-Replayed` 响应头：重放时重新 `GET /api/ops/v1/quotes/{id}`，按服务端当前状态渲染。现在 `prototype/orders.mjs` 里这段逻辑已不存在，重放时页面会显示重放响应里的旧状态。按 #45 的行为恢复，并补测试：
   - 抽成纯函数做单元测试；或
   - 在报价浏览器脚本里用 `page.route` 模拟重放响应。

### B 报价策略

3. **策略预检查不阻断没有 `pricing:read` 的会话**（来自 #52 审查）。#52 在生成报价前先读 `GET /api/ops/v1/pricing/policy-versions/{id}`。这个接口要求 `pricing:read`，而生成报价只要求 `quotes:create`。
   - 会话没有 `pricing:read` 时跳过预检查。
   - 预检查返回 403 或 404 时不显示阻断原因，照常提交，由服务端判定。
   - 补单元测试。
4. **报价页从已发布策略列表选择。** 调用 `GET /api/ops/v1/pricing/policy-versions`，参数：
   - `serviceLevel`：当前订单的服务等级；
   - `effectiveAt`：省略，由服务端取当前时间。

   每个选项显示费率版本、策略有效期和短 ID（前 8 位），完整 ID 作为 `value`。另外：
   - 有下一页（`nextAfter`）时提供“更多策略”；
   - 列表为空时显示“暂无可用的已发布策略”，并禁用“生成报价”；
   - 保留手填策略 ID 的输入框作为备用，列表读取失败时提示改用手填。

   报价浏览器脚本改为从列表选择策略。完成后在 [v0.3.0 发布说明](../releases/v0.3.0.md)已知限制第 4 项注明已解除。
