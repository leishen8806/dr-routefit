v0.1 原型增补，2026-10-24。依据 PRD V1.4 §3 报价、§5 地址及既有仓配原型。保持 PRD 正文、规则/验收编号和四份标准不变。下表区分本轮落地、已有功能与未实现事项，不能把清单当作完成证据。

## 本轮已落地：按配送地址核价

入口：调度 → 新建/编辑草稿 → 配送计价方式选“基础运费＋超距费用”。

1. 保存目的地址、装卸入口、出库仓以及人工核验的道路里程；依据字段记录路程和费率批准参考。地图尚未接入，不用示意路网、直线距离或司机临时绕路当计费距离。
2. 每单明确填写基础运费包含里程、超出每公里价格、最远服务距离、区域核验结果、报价有效期。费率无正式默认值。
3. 取整方式必须主动选择：按实际里程（最多三位公里小数，按米计算，费用四舍五入到分），或超出部分不足 1 km 按 1 km。两种均为待运营选择的可配置能力，不擅自指定商业规则。
4. 超距费 = 超出基础里程后的计费公里数 × 每公里加价。总运费 = 基础运费 + 超距费用 + 闪送附加费。短于或等于基础里程不收超距费；未填距离不能当作 0。
5. 草稿允许编辑地址和重新计价；确认服务承诺时展示费用分解，必须另外确认客户同意里程、加价和总额。待核验、不服务区、超过最远距离或报价过期均阻断承诺。
6. 承诺后沿用已有禁止直接编辑规则，保存报价与客户确认时间快照。司机查看、财务应收及订单分成都使用同一总额；不因后续司机行驶里程增加而静默多收。
7. 已有人工总价订单保持可操作，明确标示“未启用里程计费”，不是免费或已通过范围核验。正式上线前需确定哪些订单必须用距离规则，不能仅靠前端切换限制。

这是逐单规则快照，尚无运营统一费率模板、车型/区域定价版本发布或自动路由测距。报价过期发生在客户承诺前；确认后的原价不随时间过期自动重算。尚未开发承诺后的改地址差额审批，不能用草稿编辑或司机实收绕过。

## 全链路细节缺口

| 环节 | 必须明确的处理 | 当前状态 / 后续优先级 |
| --- | --- | --- |
| 地址 | 原始文字、地图点、确认入口分别保存；地标、联系人、电话、门禁、入口照片、车型通行限制；坐标精度不足人工核验 | 本轮入口/文字/依据；真实坐标、联系及地址库待补 P0 |
| 服务范围 | 区域边界、禁行区、距离上限、营业时段、车型/货类资格；付费不能突破禁服务条件 | 本轮人工区域/距离上限；真实围栏与时段待补 P0 |
| 基础运费 | 按仓库、区域、车型、载重/体积、服务类型选择获批价表，记录版本与生效时间 | 当前逐单人工基础价；统一模板发布待补 P0 |
| 超距 | 路程来源、计费起终点、基础里程、每公里价格、取整、有效期、客户同意 | 本轮已实现逐单原型；地图取路/模板待补 P0 |
| 预约与闪送 | 可用时段、截单时间、独享运力、超时处置、客户收费确认 | 闪送与人工承诺已有；时段容量与截单待补 P0 |
| 装卸 | 上楼层数、电梯、货梯、搬运距离、件数/重量、人力、安装服务、包装及拍照凭证 | 货物尺寸/包装放行已有；搬运/上楼计价待补 P0 |
| 等待/停车/路桥 | 免费等待时长、起止证据、计费单位、封顶、票据；客户与运营同意后计入差额 | 未实现 P0，不能司机任意加收 |
| 中途改址/加点 | 保存原址和原价，重新核验时限、容量和增量费用，客户确认、司机接受、调度批准 | 未实现 P0；当前承诺后禁止直接编辑 |
| 支付主体 | 发件方付、收件方付、企业月结；运费与 COD 代收货款分账；欠款不能冒充收入 | 运费现金/转账已有；付款主体、COD、月结待补 P0 |
| 取消/无人收货 | 接单前、到仓后、取货后分别处理；联系次数、保管责任、取消费/空驶费及退款 | 取消/拒收退回履约已有；收费、退款审批待补 P0 |
| 退回/二次配送 | 退回原因、返仓地址、客户确认、返程费、重新预约及新服务实例；库存待检 | 退回、待检库存已有；返程费用和二配待补 P0 |
| 丢损/少货/争议 | 件级证据、责任人、冻结争议费用、赔付审批，不改写原收款或司机历史收入 | 件数差异与事故转运已有；赔付账务待补 P0 |
| 分成 | 哪些费用参与提成、哪些实报实销归司机、补偿/罚扣及调整审批 | 当前全部确认运费按订单比例；费用分类分成待补 P0 |
| 提现 | 最低额、手续费、额度/频次、到账时效、银行拒付/失败后重试、冲正、防重复付款 | 申请/审核/驳回/人工付款已有；失败冲正和额度规则待补 P0 |
| 仓库 | 入库质量、预留/出库、退回待检；库位、批次/效期、盘点差异、仓间调拨、波次拣货 | 前四项已有；后续 WMS 能力待补 P1 |
| 客户通知 | 报价确认链接、接单、到达、改期、加价、异常、签收回执；语言与发送失败重试 | 尚未接真实通知 P1 |
| 运营权限 | 谁发布费率、谁批准差额/减免、谁退款；操作人、原因、前后值审计 | 只有原型角色和事件；生产授权/审批待补 P0 |
| 财务单据 | 费用项、应收/实收/退款、司机应付/已付、发票税费、对账批次 | 当前 USD 单运费切片；正式单据与税费待补 P1 |

## 下一步顺序

先补“统一费率与配送条件模板 → 附加费申请/审批/客户确认 → 改址/取消/退回/退款差额账 → 分成与提现失败冲正”，每一步沿用同一订单和不可改写费用记录，不能只添加按钮。再扩展复杂 WMS、客户通知和经营报表。

运营仍需决定实际费率、等待免费时长、上楼/搬运单位、取消/返程收费、费用项分成范围和提现政策。这些属于待批准业务参数，本轮没有替用户填定值。无需市场验证；下一轮验证聚焦完整业务流程与异常处理。

## 测试例与证据

合成例：基础 USD 10 含 10 km，道路距离 12.5 km，超距 USD 2/km 按实际里程，闪送 USD 3，总运费 USD 18。20% 示例平台比例得到平台 USD 3.60、司机 USD 14.40；它们不是正式政策。

58 项模型测试通过（含 6 项新增超距测试）。browser-distance-quote.js 覆盖区域阻断、草稿改址重算、客户确认阻断、司机费用展示、收款/分成一致性、390px 和刷新；browser-warehouse-platform.js 回归原仓配/提现。记录见 records/2026-10-24-distance-pricing/。
