# KESS 付款演示使用说明

2026-10-25 · 供客户、财务和产品评审使用。**KESS 商户尚未开通，真实付款未开放。** 页面所有支付结果都是模拟，没有扣款、真实二维码或真实收银台。

## 从哪里开始

打开 [订单与财务页面](finance.html)。首次演示由财务经办在“今日待办”选择“加载三笔合成订单”。再将演示身份切换为客户，进入“付款与退款”。身份选择仅用于评审，不是真实账号登录；只用合成资料。

若当前币种没有订单，“模拟 KESS 付款”不可用。先加载合成案例或切换到有订单的币种；不要为了试付款编造真实订单。

## 模拟一次付款

1. 选择“模拟 KESS 付款”，选择自己的配送订单。金额由订单带入，配送费和保险费分别显示，不能手填总额。
2. 确认后产生模拟支付单，此时没有收款。
3. 选择“模拟查询结果”，按评审场景选择待支付、结果未知、成功、关闭、失败或金额不匹配。
4. 模拟成功后显示模拟收款凭据，等待财务核销。它不表示真实到账、订单已交付或财务已结清。

| 页面结果 | 下一步 |
|---|---|
| 模拟待支付 | 继续查询该支付单；不重复建单 |
| 模拟结果未知 | 保留原单继续查询，不换单号重付 |
| 金额／商户不匹配 | 系统拒绝确认，保留原支付单供核查 |
| 模拟成功 | 财务选择对应账项制单、独立复核、独立审批，再完成核销 |
| 已确认关闭／失败 | 保留原记录；原型可重新创建不同意向，不把网络超时当失败 |

客户可选择模拟结果只是测试工具；正式产品不会让用户选择“支付成功”。原型离线时阻止资金确认与审批；恢复连接后继续原单，不自动重试付款。

## 金额怎样理解

- 配送费与保险费可以合付，但分别记账；保险不参与平台与司机的配送费分成。
- 本支付入口不收 COD 货款。
- “KESS 渠道待结算”不等于公司银行已到账，不增加公司可对外付款余额。
- 收款、核销、签收、司机交款和对外结算是不同状态，不能用一个“完成”代替。

## 财务怎样接着操作

模拟渠道成功会形成一笔渠道收款来源，不要再手工重复登记。经办在“收款与核销”选择对应账项制单；由不同自然人进行复核和审批，再由授权人员核销。管理者在“财务报表”查看渠道待结算与公司保管余额，二者分别显示。

退款、司机提现、商户返款和合作运费不通过此页自动划转。渠道未结算款也不能用于模拟公司退款。具体开发准备见 [KESS 接入说明](../PRD/docs/kess-payment-integration-v0.1.md)。

模拟记录只保存在当前浏览器标签页，不是多人共享后台。不要输入支付密码、真实银行卡或商户密钥。商户开通后仍需真实渠道联调、后端身份与账务持久化、银行对账等验收，本页面不能证明这些已完成。
