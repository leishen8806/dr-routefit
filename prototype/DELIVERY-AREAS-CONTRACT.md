# 配送区域 · v0.1 交互原型补充

2026-10-24。用户要求管理后台在地图上划定哪些区域配送、哪些不开配送。沿用现有 Logo、设计标准及运营/调度职责；不修改 PRD 正文、规则和验收编号，四份标准继续为 v0.1 草案。

## 入口与操作

- 运营中心 → 配送区域，或 `#areas`。分“地图与区域”“发布与影响”两页签。
- 选择可配送或禁送类型，地图逐点绘制多边形，也可输入经纬度添加顶点。支持撤销顶点、清空、编辑边界、改名、启停和删除草稿区域。首尾自动闭合。
- 保存区域先进入草稿；刷新保留已保存草稿。未保存的绘制在导航间保留，关闭/刷新页面触发浏览器离开提醒。未保存的边界不能直接发布。
- 发布需要勾选影响确认。发布版本与历史区域快照追加保存。修改或删除草稿不改变已发布规则，直到再次发布。
- 绘制模式显示草稿边界；地址检测模式显示并使用已发布边界，避免图面与检测结果不一致。
- 调度可以检测和绑定订单落点，不能修改或发布范围。订单“下一步操作”提供“核验配送区域”入口。

## 当前规则

| 条件 | 结果 |
| --- | --- |
| 区域未首次发布 | 保持原有人工区域/里程核验，明确提示尚未发布；不会把旧订单擅自判定可送 |
| 发布后命中启用禁送区，包括边界 | 禁止配送，优先于可送区 |
| 命中启用可配送区，未命中禁送区 | 地点准入通过；容量、时间、司机资格与财务等检查仍需满足 |
| 不在任何启用可送区 | 不配送，不能付超距费绕过 |
| 没有启用可送区并确认发布 | 全域关闭新的配送准入 |
| 坐标缺失或坐标对应的地址与订单当前地址不一致 | 待人工核验，不视为可送 |

可配送区边界算区内，禁送区边界算禁送；禁送优先。区域最多50个，每个3–100个顶点，拒绝无效坐标、重复顶点、交叉/相互接触边界、共线或近零面积。

普通仓库配送校验送货地址；有上门取件地址的订单同时校验取件和送货地址。经纬度顺序为 `[longitude, latitude]`，人工确认记录绑定地址原文及订单版本。仅草稿或待派单可以修改落点；有有效提案先撤回，在途不能直接修改地址。

承诺、车辆提案、合作车辆提案、人工快递委托建立/确认、司机接受提案，统一使用共享业务模型重新检查当前已发布范围；通过时记录区域版本。区域变化不会直接取消已有订单，不更改货物保管与资金状态；在途签收、退回和事故救援仍按既有流程处理，异常由调度处置。没有提供隐式加价、闪送或人工确认绕过区域准入的入口。

## 数据与一致性

`serviceAreas` 包含草稿、已发布区域、配置版本、发布版本及追加的发布历史；订单 `areaPoints` 保存取送地址的人工坐标证据，`areaValidation` 保存最近一次执行入口检查的版本。操作复用幂等键、权限和版本冲突检查。校验失败不写回业务状态。

UI 使用现有 sessionStorage 演示库。纯模型可供现有本地接口复用，但未增加正式区域管理 HTTP 接口，也没有将浏览器规则同步到独立4174联调进程。API、数据库迁移及真实地图基座接入需后续实现。

## 地图与生产边界

当前沿用**金边示意底图**，不是在线街道地图，不提供真实地址搜索、地理编码、测距或导航。画布覆盖演示经度104.82–105.02、纬度11.48–11.68；用户需人工确认落点。页面不请求第三方地图服务，不上传地址或坐标。

多边形算法用于小范围平面经纬度演示，不用于跨日期变更线、极区或全国级精密边界。地点准入通过不证明行驶路线不会穿越禁送区；路线绕行、道路封闭和车型限行是不同能力，不能从区域图推断已经支持。

本期区域为全平台统一范围，未增加按仓库、服务类型、时段、车型的独立区域规则。正式启用前需明确这些范围、接入实际地图与可信地址坐标、数据库事务/权限及操作审计，并复核历史待派订单。当前页面仍为中文，未声称三语全量完成。
