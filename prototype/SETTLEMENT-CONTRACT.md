# 按主体结算与财务提醒交互契约

v0.1，2026-10-24。依据 PRD/docs/partner-settlement-and-funds-v0.1.md §3；不更改正式 RULE/AT。用户已授权实现 Demo 和同步需求。

- 页面：财务导航“结算与提醒”，规则／待办／账单／催收记录 TAB；详情有返回。复用 app.mjs 表单、dialog、错误、toast、权限与 sessionStorage，品牌样式 app.css。中文评审，native select/date 沿用原契约。
- 数据：结算规则按客户、合作单位、个人主体及方向配置。旧订单缺独立客户 ID，Demo 按客户名称建立临时主体；不是生产身份合并规则。应收引用原订单金额/核验，合作应付引用 payables，司机收入引用 earnings/withdrawals，账单不新增第二笔钱。
- 演示数据通过显式按钮加载，添加带 SET-DEMO 标识的已履约月结合成订单、合作应付和示例规则，不覆盖已有订单。不授予真实客户月结资格，不连接银行或消息渠道。
- 账期：日/周/月/每 N 天/逐单，明确锚点、出账延迟、付款天数、提前提醒与逾期间隔。金边日期、日历日；短月选月末或跳到下个有效月份。工作日银行日历未接入，不能冒充已支持。新版本不覆盖已绑定账项，预览三个周期。
- 动作：检查到期 → 账单草稿和持久待办 → 财务确认 → 模拟发送（可注入失败并重试）；应收逾期生成催收草稿，确认发送前复核余款。转账到账人工核验可部分入账，回写原订单；现金、合作应付和提现沿用既有页面。已读不完成待办；争议/待核款从可催金额中扣除，更新后重新评估。
- 权限：规则/账单/应收/催收用 finance.verify，提醒读取用 finance.read；付款入口原权限不变。限定范围账号暂不开放跨主体账单，服务端安全未实现。所有写动作版本及幂等校验。
- 定时：页面加载与可见页面每分钟检查，重启补查不重复出账；模拟日期可向前推进并显示。关闭页面无后台调度、无真实推送；无自动付款。
- 验证：模型边界测试＋真实浏览器正常/异常/刷新/返回/窄屏/键盘与只读权限。不得将本原型作为生产财务或银行托管已上线证明。


## 2026-10-24 财务设计审查后的限制

本契约对应当前 Demo，不等于完整资金核销契约。源码显示：settlementCollect 将资金直接关联单一订单并将部分收款标 mismatch；合作 payablePay、提现 withdrawPaid 登记凭证即计已付。尚未分离付款执行、银行核对和核销，也未支持一款多单。目标及迁移要求见[财务闭环设计](../PRD/docs/financial-closure-design-v0.1.md)，本轮仅文档审查，运行行为未变。
