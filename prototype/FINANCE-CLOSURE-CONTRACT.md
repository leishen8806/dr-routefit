# 跨端财务闭环交互契约

v0.1 · 2026-10-24；用户已授权更新需求、Demo、设计图及各端订单与报表。依据 `PRD/docs/financial-closure-design-v0.1.md` 和本轮补充：COD 纳入首期；经办、复核、审批按不同 personId 三人分离，付款执行和资金核对分离。收入提现保留，不做充值钱包或真实自动划款。

实现入口 finance.html，与现有工作台使用同一 sessionStorage 数据库、原订单引用及 app.css 品牌 token。新财务模块接管的订单禁止旧收款／交款／入账入口改写；历史已有结清证据的订单不自动迁移。合成样例显式加载，不能覆盖旧订单。账务范围在页面持续标识；所有各端报表来自同一资金、核销和交接记录。

页面：财务今日待办、订单账、收款与核销、付款与审批、交款差异、报表；司机、用户、商户、仓库是同一数据的授权投影。订单可下钻费用、资金分配、现金保管、凭证和审批链。列表搜索、币种筛选、8条分页，详情返回保留列表状态。权限由模型和投影双重校验，但浏览器角色选择只是模拟身份，不是生产鉴权。

共享组件所有权：app.css 的按钮、field、panel、pill、tabs、table-wrap、dialog-head/form-body/dialog-footer；本页原生 dialog、select、date，接受操作系统弹层。表单 novalidate、行内错误、取消保护、焦点恢复、提交防重；搜索显式提交支持 IME，清空恢复，页面用 URL 保留席位／页签／查询／币种。中文评审，金边业务日期，高棉语／英文完整翻译仍待迁移。

核心流：申报 → 独立确认资金事实 → 核销制单 → 独立复核 → 独立审批 → 核销；付款制单 → 复核 → 审批 → 人工执行登记 → 独立资金核对 → 核销。未知结果保留占用，不能重复执行。审核后修改关键数据使审核失效；已入账通过反向分配／批准补差更正。

司机交款先申报，点收如实记录保管事实，生成审核批次；实交少于申报单列待查差异，不推定责任，不扣收入或 COD。COD 返还只能使用已确认且归属商户的代收，不因签收即视为已收款。费用、保费、货款、司机收入独立。

设计图：浏览器从当前实际页面导出桌面财务、订单追溯、司机、用户、商户、仓库及报表截图，保留可打开的设计图索引。不把静态图片当功能证明。

验证：FIN-AT-01～12 专项编号不替代正式 AT；模型覆盖越权、同人多账号、跳步骤、金额版本、幂等、超配、币种、现金差额、未知出款；浏览器覆盖跨端正常链、异常、刷新、返回、搜索、窄屏与键盘。外部银行、生产服务端、真实人员可用性、审计防篡改与后台通知不在本地原型完成声明内。


## KESS 接入与再次复核（2026-10-24）
