# R1-M 合作车辆与人工快递原型契约

v0.1 草案，2026-10-24。依据 V1.4 §21.3–21.5、RULE-041～046、049、052 与 AT-81～90、101～103；沿用四份标准及首期页面规划。冲突以 PRD 为准，V1.4 冻结后复核。原 R1 契约继续有效，本文件新增原型设计覆盖单元，不重编 PRD 编号。

## Persona

调度兼授权合作方管理演示席：登记准入档案、核验、暂停／退出、选择合作运力、人工委托、事件核验、异常退回与取消。仓库：逐件交接、差异记录、回仓点收。合作司机：固定演示身份 P01 / Dara，仅访问被指派任务，接受时确认实际可用窗口和持货。财务：应付核对、争议、部分付款、付款登记及冲正。本地 mock 不构成生产鉴权。

## User Flow

合作车：待核验档案 → 资格／协议／窗口核验 → 可用 → 订单确认承诺 → 合作车派单与费用确认 → 合作司机接受 → 复用装载／取货／送达 → 独立应付核对与付款。部分签收复用调度授权退回、司机返仓、仓库点收。暂停阻止新任务；既有持货任务仅在明确继续处置授权下可读写，退出可撤回该权限。

快递：待核验档案 → 服务范围／货类／尺寸限制及责任核验 → 可用 → 已承诺订单 → 保存委托草稿 → 人工联系与证据 → pending_confirmation → 外部接单确认 → awaiting_handover → 仓库与承运方逐件签认 → handed_over → 人工录入运输／报告送达事件 → delivery_reported → 凭证核验 → delivery_verified。付款与应收独立。

委托未知结果不能重新创建；cancel_requested 不释放实例，只有未持货且承运确认取消才 cancellation_confirmed，可另选车辆／委托。交接后异常必须保留承运保管责任，调度确认拦截／退回，仓库实际点收才结案。未知／重复／乱序事件留原文而不回退当前可信状态。

## Interaction Matrix

| ID | 动作 | 输出／恢复 |
| --- | --- | --- |
| MI01 | 登记档案 | 待核验，必填错误保留输入 |
| MI02 | 核验准入 | 证据、有效期、窗口、责任齐备才可用 |
| MI03 | 暂停／退出／重新审核 | 新任务禁用；明确是否授权已有任务继续；历史不删 |
| MI04 | 合作车派单 | 校验有效窗口、容量、互斥；记录约定应付 |
| MI05 | 合作司机接受／拒绝 | 本人任务，确认窗口及持货；拒绝释放提案 |
| MI06 | 合作车交接／签收／退回 | 复用 R1 状态守卫、事件与保管链 |
| MI07 | 保存快递委托草稿 | 不创建虚拟车辆；有效实例互斥 |
| MI08 | 登记人工联系 | 结果待确认；重试不创建重复委托 |
| MI09 | 确认承运接单／安排交接 | 外部单号和确认依据齐全仍不等于揽收 |
| MI10 | 快递实物交接 | 双方、地点、逐件件数与包装签认一致才转保管 |
| MI11 | 录承运事件 | 事件 ID 去重，保留原始状态及时间；未知／旧事件不改可信状态 |
| MI12 | 核验签收 | 批准凭证、数量、收货确认齐全才业务送达；不自动结账 |
| MI13 | 请求／确认取消 | 未确认不释放，已持货不可直接取消 |
| MI14 | 登记异常／确认退回 | 负责人、期限、原始证据与承运方确认，保持保管责任 |
| MI15 | 退回到仓及点收 | 不符不结案；实物准确点收才闭合 |
| MI16 | 应付核对／争议 | 与客户应收分账，争议不自动抵销 |
| MI17 | 部分付款／已付清／冲正 | 凭证去重、不可超付、追加历史，不触发真实付款 |
| MI18 | 队列筛选与角色切换 | 方式和状态显式展示，合作司机不能读其他实例 |

## State Matrix

新增业务状态覆盖：合作方 pending/available/paused/exited 及有效期失效判定；快递 draft/pending_confirmation/confirmed/awaiting_handover/handed_over/in_transit/delivery_reported/delivery_verified/cancel_requested/cancellation_confirmed/return_requested/returning/returned；应付 pending/verified/disputed/partially_paid/paid。至少 23 种显式状态（5+13+5），不包含既有 R1 状态。空队列、错误、无权限、必填校验、提交中复用原型公共表现。实际覆盖逐项记在 R1M-COVERAGE.md，不提前宣称通过。

## Component Map 与行为所有权

复用 AppShell、角色切换、表单字段、dialog、表格、badge、详情、timeline、toast、装载与退回逻辑。新增 PartnerWorkspace、BookingDetail、PayablePanel；仍由 app.css 维护 tokens。模型沿用 apply 的版本／幂等语义；承运事件及应付分别记录历史。真实认证、API、合同法律清单和付款服务不在本地原型内。

原型只演示金边普通包装货物、USD 客户运费／合作应付；COD、KHR、月结继续关闭。不把关闭项计入已实现范围。准入审核中的服务范围／货类须显式勾选匹配，未知拒绝。数量以逐件编号列表作为演示件级依据；凭证为合成编号，不伪造真实签名或照片。
