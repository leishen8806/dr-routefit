## 2. 待补领域对象（概念名，尚非机器契约）

| 对象 | 必要字段／约束 |
|---|---|
| PricingPolicyVersion | tenant、产品、客户合同／组、区域版本、车型／箱型、服务等级、币种、有效区间、优先级、状态、制表／审核／批准、来源凭据、规则摘要指纹；同优先级不得歧义命中 |
| PricingRule | feeCode、模式、单位、包含量／步长、累进或整票档、体积系数、计费重聚合口径、费率、上下限、基数白名单、叠加互斥组、取整／税费／折扣／分成分类 |
| PricingInputSnapshot | 订单版本、取送入口、路线距离和来源／时刻、区域／路线版本、逐件测量与数量、时段、服务要求、客户合同及来源；缺失与零分开 |
| QuoteLine | 稳定行 ID、规则版本、原量／单位、计费量、单价或比率、基数行 ID、折扣承担者、净额／税／最终额、方向、费用用途、承担方／受益方、服务实例与证据 |
| Quote 扩展 | 保留现有 ID／version／orderVersion／state／fees／total／expiresAt，补输入指纹、计算器版本、范围说明、排除项、报价来源、费用承诺／可变项、确认主体／证据 |
| ServiceChargeEvidence | 实际等待、搬运、上楼、仓储、返仓等事件；源单／站点／尝试／件／时段、申报与核验；同服务重复来源只入账一次 |
| PricingAdjustment | 原报价／行引用、新原因及服务证据、客户费用授权、复核审批版本、差额和退款／补款引用；追加而非覆盖 |
| ProviderSettlementSnapshot | 司机或承运商、协议／分成版本、基数白名单、平台出资优惠、应付及报销；与客户价分开 |

租户、客户身份和金额由可信服务端确定，不接受 Bot 或 App 自报“已批准”“已支付”、客户身份或分成结果。金额／比例采用整数或定点形式，单位必须可验证。未知产品／费目禁止落入宽松默认分支。

## 3. 接口增量清单

这是待转入 OpenAPI 的契约清单，不是可调用 URL；不得让前端临时猜路径。保持现有报价生成／确认／读取路由，字段扩展后需同步版本与兼容行为。

- 管理侧：价表列表／明细、创建草稿、编辑草稿（If-Match）、试算、提交审核、独立批准、预约生效／停用；发布前验证空值／歧义和算例。
- 核价侧：由订单快照选择服务器批准价表并返回明细、排除项或待人工原因；手动指定版本也须检验权限和适用条件。试算不生成应收，报价确认亦不直接派单。
- 客户侧：取得本订单有效报价、确认具体版本、改条件重报；Bot 和 Mini App 共用操作幂等键和草稿版本，过期消息不能重放。
- 作业侧：提交服务证据／测量复核，核价差额建议；不能提交最终客户应收或任意改价。
- 财务侧：批准费用调整、追加补差／退款／核销，不复用普通草稿编辑；付款确认金额匹配现有合法未结账项。
- 报表侧：客户报价版本、费目收入、司机／合作应付、优惠承担、异常成本、税费／保费／COD，USD/KHR 分开汇总。

错误码候选：PRICING_INPUT_REQUIRED、NO_APPLICABLE_TARIFF、AMBIGUOUS_TARIFF、SERVICE_INELIGIBLE、PRICE_EXPIRED、PRICE_INPUT_CHANGED、UNAPPROVED_SURCHARGE、DUPLICATE_SERVICE_CHARGE、DISCOUNT_EXCEEDS_BASIS、CURRENCY_MISMATCH。正式编码纳入机器契约时统一；不在未实现服务中伪称可返回。

## 4. 候选验收矩阵

以下 `PRICE-CASE` 是本专项设计编号，不替代正式 AT；除明确列出的算术自检外均 **NOT_RUN**。

| 编号 | 场景 | 必须结果 |
|---|---|---|
| 01 | 缺距离／重量／费率与明确0费率 | 缺失不能当免费；已批准0费率可计算 |
| 02 | 基础距离内、恰等于、超1米 | 仅超出部分收费，取整透明 |
| 03 | 距离分段边界与多点 | 累进／整票算法不混，整条路线不按内部碎片重复进位 |
| 04 | 实重／体积重较大、两者相等 | 按规则选择；D缺失阻断，不能默认为5000 |
| 05 | 多件／数量／逐件取整／整票取整 | 产生各自正确计费重，口径快照可追溯 |
| 06 | 重量和体积均合格但长板装不下 | 拒绝承接，不因已算出价而可派 |
| 07 | 箱型限重／尺寸边界及超限 | 合格才使用箱价；超限重报，不叠两套主运费 |
| 08 | 禁送区与收费区重叠 | 禁送优先，超距付费不能绕过 |
| 09 | 多价表命中／有效期交界／客户合同 | 唯一确定；歧义拒绝，批准版本不可改写 |
| 10 | 独享价已含独享／附加项互斥 | 不重复收费；及时与独享分别检查 |
| 11 | 等待早到、暂停、跨日、无结束证据 | 免费范围与责任正确，未核实不自动应收 |
| 12 | 仓库和司机重复申报同次搬运 | 只一项服务事实；第二笔提示重复或争议 |
| 13 | 优惠大于允许基数／最低费 | 不负金额，不暗中二次补最低费 |
| 14 | 平台承担优惠／不承担优惠 | 司机承诺不被偷偷扣减，补贴归属可查 |
| 15 | USD半分／KHR小数／大金额 | 确定性取整，金额边界拒绝，禁止隐式换汇 |
| 16 | 配送＋保险＋COD＋报销 | 仅白名单配送行参与分成；本金／保费独立 |
| 17 | 两入口同草稿并发、重复请求 | 一次报价确认／一次应收，旧版本409且不改状态 |
| 18 | 地址变更后点击旧报价／付款链接 | 重验输入和费用版本，不按新费用重复扣全额 |
| 19 | 已支付后加价／降价／取消 | 明确补款／退款待处理，不抹掉原收款 |
| 20 | 取货后拒收／部分签收／二配 | 原服务与新尝试分开，COD本金不复制 |
| 21 | 合作方涨价或救援多车 | 不自动涨客户价；应付独立核对 |
| 22 | 同币种费用拆分汇总 | 行之和＝总额，分成／分摊和＝源额 |
| 23 | 角色越权／伪造费率与确认状态 | 服务端拒绝，跨客户不泄露报价成本 |
| 24 | WMS晚到／更正／移库／跨月 | 不重复起算或静默改历史；出账追加调整 |
| 25 | 税务未配置／免税与未核实混淆 | 未核实阻断正式发布；免税必须明确配置 |
| 26 | 商业保险收款后承保失败 | 不显示已投保，独立异常及款项处理 |
| 27 | 模板未批准／演示价表 | 生产报价不可使用；演示环境与规则明确隔离 |
| 28 | 报价成功但付款／信用未满足 | 不能派单；价格校验不替代付款准入 |

## 5. 本轮产物与开发顺序

本轮完善的是规则、资料、模板、算例和现有差距；不把上述验收标成已通过。算例校验命令 `python scripts/check-pricing-examples.py` 仅检查合成公式与金额，不调用 Demo、后端、Telegram、地图、保险或支付。

并入 P01：费目／报价快照与模板试算 → P02：有效报价＋付款／信用守卫 → P05：分成、合作应付、调整与核账。每阶段同时覆盖正常与失败场景。迁移旧会话保留来源原价；没有费用来源的历史金额标待核实，不自行拆成虚构费项。

当前必须保留的实施缺口：统一计算器尚未接入各端、OpenAPI／SQL 还未覆盖新价表对象、正式费率／税务／保险资料尚未批准。正式实施时应一次性同步机器契约、样例、领域测试与页面，不能只加价格设置菜单。
