# 配送保险费分成口径核查 · 2026-10-24

用户确认：保险费单独记账，不参与配送费分成。

## 结论与证据

| 环节 | 当前本地原型实现 | 结果 |
| --- | --- | --- |
| 客户应收 | 配送费（基础＋超距＋闪送）加保险费 | 一致 |
| 平台分成 | 从应收扣除保险费，再乘订单平台比例，按整数分取整 | 一致 |
| 司机分成 | 配送费减平台所得，保险费不进入司机收入 | 一致 |
| 收款/交款核验 | 核对客户应收全额，不能只核对配送费 | 一致 |
| 入账记录 | deliveryMinor、insuranceMinor、platformMinor、driverMinor 分字段保存 | 一致 |
| 钱包/提现 | 钱包累计 driverMinor；提现上限为可用司机收入 | 一致 |
| HTTP 接口 | deliveryMinor / insuranceMinor / totalMinor 分开返回 | 一致 |
| 分成确认文案 | 原来把含保险的总额标作“运费” | 已修正为配送分成基数、独立保险费、客户应收三项 |

示例：配送费 USD20、保险费 USD2、客户应收 USD22；演示平台比例20%，平台USD4、司机USD16、保险独立USD2。司机代收22不代表司机收入22，可提现收入仍为16。

## 验证

`tests.txt`：23项定向测试通过（external-orders、integration-server、platform-model）。全流程覆盖收款22、核验22、交款22、保险2独立记录、分成4/16；补充钱包16断言、HTTP金额字段测试、两种分成确认表单文案测试。

本轮只修正文案并补充测试，不改变既有费用算法。不重复运行全部浏览器流程；金额链路为真实业务模型与本地HTTP测试，文案为渲染输出断言。

## 范围与未完成项

- 核查对象是当前本地未提交的原型改动。GitHub现有提交中的旧分成模型尚未包含保险费拆分，不能当作此口径已发布。
- “独立记账”当前指订单/分成记录的独立金额字段和界面列，不等于已经建立正式保险机构应付、退款、理赔或复式总账流程。
- 正式数据库/API设计草案尚未完整纳入这批保险扩展；未修改PRD正文、四份标准或规则/验收编号。
- 未进行真实银行、保险机构、生产数据库或生产结算验证。
