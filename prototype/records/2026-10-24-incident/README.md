# 事故应急多车转运 · 交付记录

2026-10-24，v0.1 原型。需求与范围以 [INCIDENT-CONTRACT.md](../../INCIDENT-CONTRACT.md) 为准。这是用户明确要求新增的异常处置能力，超出原 V1.4 单车首期边界；PRD、四份标准、数据库和 API 草案均未改动。

## 入口与流程

调度地图选择已取货／运输中／持货退回的车辆订单 → “车祸／事故应急转运” → 登记现场、负责人、事故及货物依据 → 原车停用、货物逐件待处置 → “分配事故货物”选择件号和接驳车，可多次分给不同车辆。

每车生成一个明确标示的接驳子任务，不是新增客户订单；原订单应收不复制，原承诺不重置。自营／合作司机分别接受任务，现场核对件数、包装、交出人、接收人、地点和双方凭证后才改变实物保管。合作接驳按独立服务实例生成待核对应付，原合作费用仍保留。

地图显示事故停用标记及醒目“处理转运”入口，可跳到右侧逐件清单。事故车展示现场尚未交接重量；接驳车在交接前展示预留装载，不声称已经持货。普通派单、合作派单和接驳分配均受事故停用及资源占用限制。

每车分别签收；原单仅在全部货物签收后 delivered。部分收货必须授权剩余返仓、到仓、仓库准确点收，所有件去向闭合后原单 closed_exception。无法确认／无法安全交接的货物保持未分配或待交接，不能用“已安排车辆”结案。

交接前允许拒绝或撤回，释放件号并保留历史；交接后只能通过签收／返仓闭合。事故车辆即使货物结案仍保持停用；没有实现修复解禁，更不以原型重置代替生产恢复审批。

## 使用说明

现有自营候选 V01、V02 与合作方 P01。要演示事故后两车同时接驳，先保证另一辆自营车空闲，并完成 P01 准入审核。不能从其他占用任务中强抢车辆；资源不足时保留未分配货物。原型角色切换演示的是授权操作链，不是生产司机身份认证。

原单放货条件继续生效：现金须先申报、转账须先核验。接驳子任务不重复收款；原单收款和交款继续由原账务链核对。本轮未扩展多司机分别代收的资金分摊。

## 实现边界与后续契约

这是浏览器本地 mock。生产数据库/API 尚未支持此次多车异常执行：需在正式需求评审后补充事故事件、件级接驳任务、占用及保管交接模型，并保持普通订单唯一有效执行约束，不能通过复制客户订单绕过约束。当前子任务为原型视图模型，不代表已批准的物理表设计。

不包含真实 GPS、现场安全判断、医疗/救援指挥、保险或责任判定、真实签名照片、生产权限、并发数据库事务、车辆修复解禁。单货类按演示件号分配；多品类拆包、接驳车再次事故与跨网络承运待专门设计。
