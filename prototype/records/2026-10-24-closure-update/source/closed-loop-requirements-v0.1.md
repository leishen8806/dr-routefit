## 2 已确认范围与不变量

| 范围 | 必须保留的业务要求 |
|---|---|
| 产品端 | 运营中心、调度中心、仓库作业、司机 APP、用户 APP、财务、只读中控；运营与调度采用不同工作入口，是否独立部署待选型，不复制订单数据 |
| 运力 | 自营、准入后的合作车、人工快递委托；同一订单不得同时存在互斥的有效执行 |
| 配送服务 | 服务等级与付费独享配送分离；超距收费须经报价确认；独享订单不参加普通拼单 |
| 仓配与接入 | 仓库接入、用户或其他平台订单导入与派单申请；复制文本仅形成待校对草稿，不能跳过地址、尺寸、报价和承诺核验 |
| 费用 | 配送费与保险费分别记录；保险不参与平台/司机分成；订单比例可配置，20% 仅为演示值 |
| 司机账务 | 司机可申请提现，财务人工审核；身份与银行卡资料需权限和审计；审核通过不等于已付款 |
| 安全和时效 | 安全、重量、实际装载与所有既有承诺先作为硬约束，再优化及时送、顺路与成本；无可行方案明确拒绝 |
| 事故 | 允许事故货物分散给多车，逐件追踪原车、接驳车、收件人或仓库；不能借此开放普通订单任意拆单 |
| 体验与权限 | 长页面分 TAB，二级页可返回；重要动作确认后执行；司机关键动作沿用安全滑动模式；中英高棉三语、服务区域、账号角色和数据范围贯穿各端 |
| 状态 | 签收、异常结案、收款核验、交款结清、应付及提现分别表达；已读通知不结案，离线证据上传不自动等于已生效 |

## 3 闭环功能与交付顺序

此处顺序是实施建议，不改 PRD 的 R1/R1-M/R1-V/R2/R3 阶段含义。每个闭环均应使用同一订单标识、货物项、费用版本和事件记录。

| 顺序 | 功能闭环与页面 | 关键异常与最终结果 | 当前与本轮边界 |
|---|---|---|---|
| 先补 | 配送异常：司机任务 → 调度异常 → 退回任务 → 仓库点收 → 财务裁定 | 联系不上可恢复配送；拒收经授权返仓，件数不符不结案；待检库存与可售分离 | 本轮接通展示页 B 全部退回与未收款费用减免；部分签收仍待同源接入 |
| 随后 | 用户下单：地址/服务区域 → 货物规格 → 费用明细 → 客户确认 → 派单 → 查询/售后 | 地址不确定、禁送、超距、报价过期、重复导入、取消；明确确认后的价格与承诺版本 | 原工作台已有导入/区域/费用原型；尚未统一到展示页同源订单 |
| 随后 | 仓配作业：预入库 → 实收 → 待检/可用 → 预留 → 拣货复核 → 出库交接 → 退回检验 | 短少、库存不足、并发占用、货损、退货；库存守恒，外部 WMS 与自建库存不能同时作为权威 | 已有轻量库存原型；批次、库位、盘点及权威切换需独立契约 |
| 随后 | 多运力：准入 → 可用窗口/报价 → 合作提案或快递委托 → 交接 → 签收核验 → 应付 | 拒单、委托取消未确认、撤销资格、承运回传重复/矛盾；保管与应付不丢失 | R1-M 独立原型保留；需与同单异常、费用调整统一 |
| 随后 | 事故转运：司机上报 → 停用事故车 → 逐件分配 → 接驳接单/交接 → 各自签收或退回 | 重复分配、接驳拒单、救援车容量不足；原承诺和父单费用保留，追加责任/成本 | 原工作台已有原型；不能将原车货物仅凭派单即视为已转移 |
| 随后 | 财务售后：收费/减免/退款申请 → 审核 → 执行凭证 → 核销/失败处理 → 分成冲正 | 部分退款、付款失败、重复回调、争议冻结；不可删除原收款替代退款 | 本轮仅未收款、未投保且人工批准全免；真实退款和理赔未实现 |
| 随后 | 收入提现：收入确认 → 冻结/可提 → 提现申请 → 财务审核 → 付款核验 | 驳回、撤销、到账未知、付款失败、换卡；冻结与可提余额守恒 | 原工作台有模拟提现；需接退款冲正与真实付款证据 |
| 持续 | R1-V：业务事件 → 同源快照 → 质量/时效标识 → 只读异常摘要 → 授权跳转 | 过期、断连、部分模块不可用、越权；快照不写运单，不泄露客户或司机完整资料 | 本轮展示签收与退回分开；真实接口待接入 |
| 后续 | R2 推荐 → R3-A 同仓合单 → R3-B 途中插单 → R3-C 返程 | 每段载荷、所有时间窗、司机确认、方案过期与原子提交；不通过保留原路线 | 本页固定矩阵与格位仅用于交互验证；正式优化与装箱独立验收 |

## 4 本轮同单异常需求

演示前置：原单 A 已交付并申报现金；B 尚未交付、未收款、没有真实保单。当前仅演示 B 全部拒收或联系不上，不推断适用所有保险产品、客户协议或订单。

| 动作 | 主体与输入 | 状态及约束 |
|---|---|---|
| 上报异常 | 司机选择原因并填写证据 | B 不改变为已签收，实物仍在司机；不得继续正常签收直到处理 |
| 恢复配送 | 调度记录客户可收货及时间/路线复核依据 | 恢复原 B 配送；不覆盖原承诺；本页人工模拟，不宣称真实 ETA 校验 |
| 授权退回 | 调度确认返仓安全、容量、时间和原仓目的地 | 形成退回任务，司机继续保管；通知确认不替代授权 |
| 报告返仓 | 司机填写到达凭证 | 仅到仓，尚未交接 |
| 退回点收 | 仓库填实际件数及凭证 | 件数必须与全部退回数一致；进入待检区，实物保管转仓库 |
| 费用裁定 | 财务登记客户同意和批准依据 | 限定演示允许全免未收配送费与未投保保费；保留原报价，追加负向调整；不产生虚构退款 |
| 最终核对 | 财务核验 A 收款 → 司机交款 → 财务核对 | B 显示未收款已减免；A 现金和分成按有效配送费计算；退回不能显示正常签收 |

默认样例：原报价 A 配送 $24；B 配送 $20、保险 $2。正常场景应收 $46，分成基数 $44。限定退回全免场景保留原报价与 B 调整 -$20/-$2，应收变为 $24，演示平台 $4.80、司机应计 $19.20。没有支付、保险或免赔政策承诺。

## 5 页面与接口约束

- 展示页新增“异常与退回”“功能规划”TAB，异常操作不得跳出到另一套 A/B 数据；旧工作台事故/部分签收入口明确为独立原型。
- 中控分别显示正常签收、退回与资金状态。路线图标注原派单示意，不能把原路线 ETA 当返仓 ETA。
- 新动作沿用动作命令、版本校验、必填证据及状态守卫；重复请求不能重复点收、减免或核销。前端席位切换不等同服务端鉴权。
- 正式 API 后续应补退回任务、费用裁定、调整账项、退款及事件投影契约；沿用现有认证、幂等键、对象版本和权限范围，不将 Demo 状态字符串直接作为数据库模型。
- 承诺、实际收款、原报价、调整、分成与保费分开存储。保险实际投保、退保及理赔需独立业务契约，保费报价不能展示成已投保。

## 6 验收条件与待定事项

本增补使用描述性检查项，不新增或重编正式 AT。演示验收要求：正常链不回退；异常与正常动作互斥；返仓点收差异阻断；原承诺/原报价保留；减免可追溯且不重复；保险不分成；刷新恢复；中控不能写；桌面和手机可操作；旧会话无需重置也可继续正常链。

后续必须确认的运营参数：取消/等待/返程/搬运收费，部分交付分摊，保险供应方与投退保规则，争议冻结和提现可用时间；不能由 Demo 自动决定正式政策。选型、并发、真实设备定位、服务端权限与资金对账仍需工程验收，不以市场验证作为本次前置。

本轮先证明“正常交付或全部退回最终都有明确保管和账务结果”，不把规划表全部标为完成。下一切片建议部分签收与已付款退款，同样先用合成订单验证守恒，再接真实服务。
