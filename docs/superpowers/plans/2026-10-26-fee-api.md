# RF-PM-011 Independent Fee Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Connect independent fees.html to the eight local pricing APIs without changing the demo.
**Architecture:** Decimal DTO model, session-scoped request controller and standalone DOM UI. One pending mutation at a time retains serialized request until a definitive result. Read sequences isolate selections.
**Tech Stack:** Node24 tests, native ES modules/HTML/CSS, existing local PostgreSQL16 service.
**Spec:** docs/design/RF-PM-011-fee-api-design.md (scheme A approved in chat).

## Global Constraints
- Only synthetic data; no production deployment, auth changes or payment.
- No app.mjs/app.css/server.mjs/contracts/services changes. Shared navigation is owned by project maintainer; direct /prototype/fees.html is this delivery.
- Amount max 9000000000000; USD2, KHR0, quantity3, percent2 digits; BigInt conversion.
- 412 retains input; unknown mutation retains same key/body/version; credentials only in controller memory.
- QA nine scenarios separately PASS/FAIL/NOT_RUN; no mock substitutes for DB/browser verification.

## Review Focus
- Identity change must not replay former principal mutation (Task2).
- Late read must not replace selected tariff (Task3).
- Unknown write and non-JSON response must not display success (Task2).
- Dirty switching and refresh must not silently erase inputs (Task3).
- Insurance belongs to separate subtotal, no double addition (Task3/4).
