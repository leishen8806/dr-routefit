# 仓库待退回点收队列 API

> 本机开发切片。该读取只投影已落库、尚未关闭的返仓任务；它不是库存、入库、拣货、承运商揽收或通用 WMS 队列。

## 读取队列

`GET /api/ops/v1/warehouse/queue`

需要 `warehouse:read`。支持 `limit`（1–100）、不可偏移的 `cursor`，以及可选的 `warehouseId`。游标签名绑定当前企业、主体、筛选条件和排序；不能跨会话或改筛选复用。

仅列出返仓任务处于 `authorized`、`received` 或 `inspected` 的订单摘要，按返仓任务最近更新时间倒序排列。`requested` 仍待独立授权，`closed` 不再占用仓库队列。每行沿用订单、履约与收款投影；未知库存、入库、拣货和外部揽收状态不会被填充为成功。

响应使用 [`OrderSummaryPage`](fields.md#ordersummarypage)。它只供队列展示和进入既有订单／返仓工作流，未额外泄露任务快照、证据或其他客户信息。

## 边界

- `warehouseId` 仅筛选已分配给返仓任务的目的仓库；没有把订单地址或车辆当前位置猜成仓库归属。
- 当前仓储库存、客户入／出库申请与库存预留仍是后续 C2 能力，不能由此接口推导为已实现。
- 本机开发会话可带 `warehouse:read`，生产身份、真实仓库岗位授权和设备／扫描联调尚未实现。
