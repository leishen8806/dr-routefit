# 内部角色与操作范围 · 本机开发切片

本组接口维护内部员工的角色及其仓库、对象范围记录。它是授权控制面，不是登录、密码或生产 IdP；服务端始终以可信会话的 `principalId` 和权限为准，绝不接收前端自报身份。

| 操作 | 路径 | 权限 | 行为 |
| --- | --- | --- | --- |
| 查询授权 | `GET /api/ops/v1/access-grants` | `access:read` | 返回本企业稳定游标分页的角色范围记录 |
| 授权角色 | `POST /api/ops/v1/access-grants` | `access:grant` | 向另一名有效内部员工创建带到期时间的角色范围 |
| 撤销角色 | `POST /api/ops/v1/access-grants/{grantId}/actions/revoke` | `access:revoke` | 以 `If-Match` 撤销原记录，不删除历史 |

## 强制规则

- 目标必须是同一企业、`ACTIVE` 的 `STAFF`；当前授权人不能给自己授权。
- 仓库范围必须属于同一企业；对象范围只能引用同企业的内部主体或货主。重复范围、过期授权、跨企业 ID 均拒绝。
- 授权记录与事件只追加：`active → revoked` 是唯一变更，撤销者、理由和版本均保存；过期并不改写历史。
- 角色范围记录不能替代财务自然人分离、对象资源授权、银行端权限或生产 IdP。各业务动作仍须再次校验自身版本、对象和职责冲突。

## 本机边界

本地开发会话使用启动时写入的受限合成权限。创建或撤销角色范围不会热修改既有浏览器会话；生产接入必须让 IdP/BFF 在签发与续期时读取已生效范围，并在每个受保护资源上执行范围校验。当前不提供公众账号注册、密码管理或生产登录。

完整字段、错误码和请求头以 [OpenAPI](openapi.json) 的 `AccessGrantDraft`、`AccessGrant`、`AccessGrantPage` 为准。
