# 应收台账查询 API · v0.1 本地开发

2026-10-25。新增两个只读、仅本机的财务查询接口，作为“已确认订单变更申请 → 候选重报价 → 原收款与原核销”的可核对基础。它们不发起收款、付款、退款或报价切换，也不把候选报价差额伪装成已到账。

| 方法及路径 | 权限 | 结果 |
|---|---|---|
| `GET /api/ops/v1/finance/ledger-items` | `finance:ledger:read` | `LedgerItemPage`，稳定 UUID 游标分页 |
| `GET /api/ops/v1/finance/ledger-items/{ledgerItemId}` | `finance:ledger-items:read` | 单项 `LedgerItem`；无范围权限时404 |

## 数据口径

初始确认报价按费用项生成不可修改的应收账项。当前只生成 `DELIVERY` 与 `INSURANCE`：保费独立列示，不参与配送分成。每项返回原额、有效已入账核销额和未结额；整笔核销撤销后，撤销的分配不再减少未结额。金额均为整数最小货币单位，币种不混算。

账项来自确认报价费用快照，而不是前端或余额编辑框。`sourceType=QUOTE_FEE`，`sourceId` 为原费用项；`subjectId` 为本单客户。`allocatedMinor` 是读取时依据有效 `POSTED` 核销事件重算，不能通过本接口修改。

## 查询与权限

- 可重复传 `orderId`，最多 20 个 UUID；不传则按该企业获授权范围分页读取。
- `limit` 为 1–100，默认 50；`cursor` 是绑定公司、主体、筛选条件和时效的签名游标，不支持 offset。
- 只有获得 `finance:ledger:read` 且对订单客户仍有授权的身份能看到项目；无授权返回空页或404，不暴露其他企业、客户或订单事实。
- GET 无副作用；不得缓存成可写余额，也不得用页面状态代替重新读取。

## 与确认订单变更的关系

候选重报价确认会冻结“原报价／候选报价／原确认收款／原有效核销／原未分配款／待补款或待处理贷项”位置；本接口展示原确认报价费用项及其有效核销。它们仍是两种不同的事实：

1. 候选价差快照说明需要后续财务处理多少；
2. 台账说明原费用项已核销多少、尚欠多少。

尚未实现候选差额应收、贷项、原收款跨新旧账项分配、真实退款或报价切换。未来这些动作必须由独立、可审批的财务接口创建追加事实，不能覆盖本接口的原始账项。

验证：真实 PostgreSQL HTTP 集成测试覆盖确认报价后按费用创建账项、部分/完整核销读取、保险独立列示、客户授权隔离、整笔核销撤销后余额恢复，以及候选重报价不改原订单财务准入。真实 KESS、银行与生产身份均未接入。

## 资金总览（本地开发）

| 方法及路径 | 权限 | 结果 |
|---|---|---|
| `GET /api/ops/v1/finance/reports/overview?currency=USD` | `finance:reports:read` | `MoneyOverview`，按单一币种返回可核对的资金与往来位置 |

查询必须且只能传入 `USD` 或 `KHR`；货币不混算。结果分别列示应收、应付、司机保管现金、公司已点收现金、已登记但尚未匹配的银行入账，以及已提交的司机提现申请。金额都由已确认的台账、交款或银行事实计算，不能编辑。

`quality=partial` 是当前唯一允许的质量标记：COD 待返还与 KESS 渠道保管额尚未有已接入、可核验的数据源，所以它们不是“零”，而是未知。页面和调用方不得据此声称全量对账或可支付余额；付款、退款、自动划款和 KESS 回调仍未实现。
